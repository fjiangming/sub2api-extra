# 会话滚动续期

本功能只调整用量排行的内存登录会话，不修改 Sub2API 源码、数据库、主站 Token 或其他子服务。

## 行为

- `USAGE_LEADERBOARD_SESSION_MINUTES` 从登录起的固定时长改为滚动空闲窗口，默认 30 分钟，可配置 5～120 分钟。
- 普通受保护请求仍最多复用 60 秒内的主站验证结果。到期需重新调用 `/api/v1/auth/me`，只有验证成功且身份一致，才将会话延长至当前时间加空闲窗口。复用验证结果的请求本身不会延长会话。
- JWT 中可解析的 `exp` 只用于收紧到期上限，不用于证明身份或授予权限。续期始终不超过这个固定上限。对没有可解析 `exp` 的 Token，以主站验证为准，不另承诺固定的最长登录时长。
- 续期同时更新 HttpOnly Cookie；HTTPS 下普通 Cookie 和 `SameSite=None; Secure; Partitioned` Cookie 保持相同的服务端到期上限。跨站 Cookie 被阻止时，已有 `Session` 令牌也能使用续期后的会话，不需要浏览器保存原始主站 Token。
- 页面可见、在线且未打开规则弹窗时，原有的每分钟榜单刷新即可触发续期。没有新增后台心跳。隐藏、离线和规则弹窗会暂停自动刷新；空闲超过窗口后，旧会话不会恢复。
- `/api/auth/me` 返回最新的 `expiresAt`。公开榜单结构、匿名标识及个人用量统计不变。

## 失败与并发

- 主站返回认证失败、账号停用或不同用户身份时，撤销本地会话，不设置续期 Cookie。
- 主站超时、网络故障、无效响应或验证并发达到上限时，请求仍返回错误，既不延长会话，也不提前删除尚未到期的会话。恢复必须发生在会话到期前。
- 同一会话的并发验证继续合并为一次主站请求，每个成功响应都可携带更新后的 Cookie。
- 在调用主站前后检查会话有效性和内存中的同一会话对象。验证期间发生到期、退出、重新登录替换会话或服务关闭，都不能被稍后返回的验证结果恢复。
- 退出继续删除会话并清除两类 Cookie；原 `Session` 令牌立即失效。服务重启后所有会话仍失效。

## 安全与兼容性

滚动续期会增加活跃会话以及对应主站 Token 在内存中的保留时间。持续打开的页面会自动刷新，因此它也算活跃；持有被盗会话令牌的人同样可能尝试保持会话。可解析的主站 Token 到期上限、主站验证、User-Agent 检查、会话数量上限和限流仍然生效，不能把这一改动称为零风险。

普通页面的账号停用和 Token 撤销仍在下一次主站重验证时发现，正常请求下最多复用 60 秒旧结果；管理员接口仍每次重新验证主站角色，写接口仍校验 Origin 和 CSRF Token。管理员页面与展示页共用此会话，因此有效的管理员请求也会续期，不改变后台授权条件。

不接收、存储或交换主站 Refresh Token，不向主站新增写请求。主站自身刷新了 Access Token，不会自动替换已打开 iframe 中的旧 Token。旧 Token 到期时需重新从主站菜单进入，才能取得主站传入的新 Token。

主站页面退出登录不等于旧 Access Token 已被主站服务端撤销。如果主站仍接受旧 Token，排行无法独立判断父页面已退出；这沿用现有身份验证的边界。主站会话绑定仍需按 README 正确配置可信代理和客户端 IP、User-Agent 转发。

升级不新增环境变量或数据库迁移。旧版本浏览器脚本兼容服务端续期，无需修改页面存储或增加接口。部署新的排行进程后，用户从主站重新打开即可。

## 验证

自动化测试使用可控时钟覆盖持续访问跨越初始到期时间、空闲失效、JWT 到期上限、Cookie 与 Session 两种访问、Secure 与 Partitioned Cookie、认证拒绝、主站暂时故障，以及验证期间退出、到期、替换和关闭的并发情况。HTTP 测试通过真实路由验证榜单刷新续期、个人数据和退出行为；所有主站响应均由本地测试替身提供，不使用真实用户凭据。
