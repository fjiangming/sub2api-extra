# 排行榜后台设置与实现规则

管理员设置页为独立路径 `/settings`，与展示页 `/` 共用服务和域名，但使用独立 HTML 与 JavaScript 入口。

展示页、个人详情与管理预览均只展示 Token 用量，并固定按 Token 排名；不再提供调用次数或指标切换控件。模型占比只按 Token 计算，零 Token 显示空态。后端保留请求数统计和旧指标 API，用于兼容现有调用与候选格式；更新页面不需要重新生成已发布榜单。

页面由服务端验证主站管理员角色后返回表单，数据生成、校验、草稿、发布、回退均通过正式接口完成。部署和操作见[模块 README](../README.md#管理员设置与真实用户优先)。

2026-10-16 开发验收覆盖自动测试与 JavaScript 语法检查，以及设置页生成、发布和移动端检查。覆盖真实用户下限优先及超上限保留、按当前指标超过榜尾入榜、迟到用量的一致性重试、本人榜内名次、模拟双区间交集、来源无关的并列顺序、草稿隔离、真实用量保留、恢复、回退及普通用户拒绝访问。镜像发布与线上升级状态以 GitHub Actions 和实际部署为准。

## 页面与入口

- 延续现有排行页面：跟随系统主题，不添加 Logo、主题切换、系统名称或页脚宣传文字。
- 页面名称为「排行设置」。桌面采用左侧参数、右侧 Top 10 预览；手机按参数、预览、操作栏顺序排列。
- 顶部展示当前真实/模拟模式、发布版本及更新时间。草稿状态与已发布状态始终分别展示。
- 正式地址为 `https://实际排行域名/settings`，复用当前站点、端口和 Nginx。
- 主站添加「排行设置」自定义菜单，可见角色选择「管理员」。普通用户的「用量排行」菜单保持原地址。
- 展示页不包含管理入口、后台表单或管理员脚本。设置页在服务端实时确认管理员权限后，才获取 CSRF Token 和管理表单；普通用户只能得到拒绝响应。

## 设置项

| 分区 | 控件 | 规则与默认值 |
| --- | --- | --- |
| 数据来源 | 真实用量 / 模拟榜单，分段选择 | 已发布默认真实；选择模拟只改草稿 |
| 榜单范围 | 优先 Token 下限、模拟上限 | 达到下限的真实用户优先纳入；真实用户超过当前指标榜尾也可入榜，上限仅约束模拟；配置允许 1M～1B，默认 1.37M～980.83M |
| 模拟范围 | 单人模拟 Token 下限、上限，数字输入 | 与榜单范围取交集生成；允许 1M～1B，默认 1.37M～980.83M |
| 数值分布 | 自然梯度 / 差距接近 / 头部集中 | 默认自然梯度；影响数值分布，不允许突破边界 |
| 名单 | 保留身份与历史，复选框 | 默认勾选；沿用同一时间线，保留历史并计入自然增长；收紧有效区间或修改分布须生成新名单 |
| 人数 | 固定 Top 10 | 十个示例候选补足真实用户，累计空间不足时自动换用新示例身份 |
| 更新 | 生成后发布 | 发布后每 5 分钟按时间复算增长，跨天自动续接；不按访问次数重新随机 |
| 预览 | 今日 / 本周 / 本月 / 累计 | 切换周期只切换视图，不重新生成名单或数值 |
| 排序 | 固定按 Token 用量 | 对同一份候选数据混排，真实用户没有位置优先权；同值并列并以固定种子决定相对位置 |

真实用户头像读取主站保存的图片，未设置或加载失败时显示默认用户图标；模拟用户统一使用默认图标。新模拟身份从 `qq.com`、`gmail.com`、`163.com` 中随机选择邮箱域名，生成 `12***@qq.com`、`ab***@gmail.com` 这样的脱敏形式，QQ 邮箱前缀使用数字；重名替换和自动更换身份使用同样规则。已保存的 `example.com` 身份继续兼容；取消「保留身份与历史」后重新生成并发布，可切换为新邮箱规则。真实模式仍使用脱敏的注册邮箱。

## Token 的边界与随机性

榜单范围按每位上榜用户在当前统计周期的 Token 汇总判断，下限用于优先纳入真实用户，上限仅约束模拟。真实用户超过上限或 1B 仍以完整实际用量参与排序；低于下限但 Token 用量超过榜尾也可以入榜。单人模拟范围只限制模拟用户，生成时与榜单范围取交集。模拟上下限包含，交集无宽度或无法生成十组有效随机小数时明确报错。10 人合计可以超过 1B，必须与各行相加一致；不裁剪真实记录，也不改变个人实际用量。

- `1M = 1,000,000`，`1B = 1,000,000,000`，采用十进制单位。
- 原始 Token 使用整数，例如 `823,473,219`；显示为 `823.47M`。Token 本身是计数，不生成 `0.5 Token`。
- 「不能是整数」按用户看到的 M/B 数值解释：统一使用两位小数的 M，避开 `100.00M`、`1.00B` 等整数展示及明显的整百万、整千万值。
- 原始数量与格式化结果同时校验，特别防止 `999.999M` 四舍五入成 `1000.00M`。虽然允许的上限是 1B，随机生成结果无需取到这个边界。
- 不使用等差数列、固定倍数或固定尾数。对不同档位加入随机扰动，生成独立的低位数字。
- 生成后按指标排序。相同原始值或显示值过于密集时，在有限次数内重新采样；无法满足所选范围时明确报错，不放宽边界、不无限循环。
- 生成、保存草稿、发布三处均执行同一份服务端校验。前端数字输入限制仅用于即时反馈。
- 请求次数保持整数，从同一批模拟用量按随机的单次 Token 量推导，避免每个人都使用相同的 Token/调用比例。

例如一组本月候选用量可以是 `823.47M`、`692.83M`、`531.26M`、`418.79M`、`306.42M`、`218.67M`、`146.93M`、`82.51M`、`37.28M`、`8.64M`。这只是展示示例，不是固定模板。

## 跨周期与相关数据

正式生成器以随机种子、版本和初始统计时间为输入，初始生成 94 个自然日的示例桶，再聚合四个周期。版本 4 保存一份版本 3 起点，按身份、日期和 5 分钟时间段复算后续增量及独立活跃时段。仅保存当前候选及固定大小的重放参数，不保存日桶、请求明细，也不每天追加存储文件。

- 今日是本周和本月的子集；本周、本月分别是累计的子集。本周可能跨月，因此不能通用地断言本周小于本月。
- 模拟用户的所有周期均校验单人 1M～1B；模拟累计的最高值仍不超过 1B。预算无法同时满足时拒绝生成，不通过最后裁剪汇总值来破坏加总关系。
- 主站时区决定周期边界。版本 4 跨天、跨周、跨月及跨年自动续接，草稿和回退版本也按其原时间线计算当前值；版本 1～3 快照仍当日有效。以 UTC 搜索本地日界限，夏令时重复小时不倒退，缺失小时不重复累计。
- 同一时间段内，刷新或切换周期不会重抽用量；经过时间段后才增长，允许暂停。展示页每 60 秒后台请求，隐藏或离线时暂停，回来更新，错误保留旧榜单并退避重试，身份失效停止请求。打开详情期间暂停自动更新。
- 保留身份重新生成不改写既有日桶；跨天累计的增量等于新增日用量之和。每日下限作为示例当天的初始额度，再加时段增量。累计无法容纳下一日时以新身份补位，旧身份不回退；末日增量限定在剩余额度内。只扩大有效区间时沿用原节奏；收紧有效区间或修改分布须生成新名单，否则返回 `SIMULATION_HISTORY_CONFLICT`，原草稿与发布均不改变。
- 混合模式展示页概览为「榜单 Token 用量」，管理预览另显示「上榜用户」；仅汇总当前显示的真实与模拟用户，不将模拟合计当作全站总量。
- 首版模拟榜单不显示排名涨跌、增长率或「新上榜」，避免没有上期基准的比较。真实模式保持现有计算方式。
- 用户侧保留轻量的「示例数据」标识，榜单规则随模式切换。
- 个人用量、近 7 天趋势和常用模型继续读取本人真实记录。混合榜中本人已入榜时显示「我的榜内排名」及定位按钮，名次与榜单行相同；未入榜仍显示「我的实际用量」。不返回混合榜的全站百分位、名次比较或追赶差距。
- 继续不查询、不生成、不返回消费金额、余额或充值数据。

## 筛选与混排规则

先按榜单下限筛选当前周期的真实 Token 总量，沿用现有的可用用户范围和管理员参与开关。包含下限；真实用户不受榜单上限限制，超过上限仍展示完整实际用量。单人模拟范围不参与真实用户筛选。另保留不按 Token 范围筛选的全站真实 Top 10，作为当前指标的竞争候选。

达到下限的真实用户少于 10 位时，先纳入，从符合两个区间交集的十位模拟候选中按固定种子选取补位用户，形成初始榜单。任何其他真实用户的 Token 用量严格超过该榜尾时，也加入竞争；重新排序取十位，可以挤出较低的模拟或真实行。全站真实 Top 10 已足以覆盖所有可能超过最终榜尾的真实用户，无需加载全体用户。兼容 API 的请求次数排序仍按请求数比较并保留相同入榜保障，页面固定请求 Token 排序。当前访问者身份不参与名单选择，所有用户看到同一套榜单。

真实用户不固定在前；同值仍并列，顺序按种子和身份决定，不按真实/模拟来源决定，最多展示十位。版本 3 起的补位及并列顺序不包含周期参数，各周期共用同一候选顺序；相同统计窗口与真实名单得到相同榜单。该规则保留了下限优先与模拟补位，不等于让全部模拟候选参与数学 Top 10 竞争。

达到下限的真实用户至少 10 位，或模拟行全部被其他真实用户挤出时，恢复全站真实 Top 10、全站概览、实际名次与比较。SQL 仍在截取十位之前按下限查询优先候选，避免遗漏有效用户；全站候选不受 Token 下限约束。个人面板提供 `inLeaderboard`、`boardRank`，与真实用量和请求数一起校验，使用唯一用户键定位，不能按脱敏邮箱判断身份。

本人统计与榜单使用相同时间截止点。迟到写入仍可能出现在缓存生成后，因此对本人榜单行、全站候选、优先候选及模型汇总交叉校验；不一致时清理共享缓存并重查，最多重试两次，仍冲突则返回 `SERVICE_BUSY`。这是检测后重读，不是数据库长期快照或秒级推送。默认 60 秒缓存与 60 秒页面轮询叠加，正常在线且查询成功时变化可能接近两分钟才显示；离线、隐藏或错误退避时会更久。

真实记录只在数据库聚合，额外返回最多 10 位达标真实用户，无需在应用中加载全体邮箱或明细。模拟身份不替换真实身份的用量；与真实脱敏邮箱显示重名时自动改用另一模拟名称。混合榜响应逐行保留来源，个人用量不经过模拟生成器。

新增候选使用算法版本 4，设置文件仍可重放版本 1、2、3 的当日快照，避免升级清空原有发布。保留旧身份升级时将其可复算历史作为起点；历史不符合范围时拒绝迁移，不重抽旧历史。旧快照保持其模拟数值，设置页提示重新生成并发布，之后启用自动增长及跨天续接。真实用户入榜修复对已有发布配置同样生效，无需重新生成。选择真实模式时沿用原始全站统计和排名。

## 草稿、发布与恢复

1. 管理员调整参数后点击「随机生成」。仅替换内存候选数据，用户仍看到已发布版本。
2. 可切换周期检查按 Token 排名的候选效果。生成参数再变化时标记「参数已修改，待生成」，禁止发布与参数不匹配的旧候选。
3. 「保存草稿」保存当前规则及候选，仍不影响用户榜单。
4. 「发布榜单」弹窗确认范围、身份数量和模式；再次验证管理员与候选数据，通过版本检查后一次性替换当前发布版本并使相关缓存失效。
5. 后续生成与草稿保存不改变已发布数据；只有下一次发布才替换。
6. 「恢复真实榜单」立即切回只读查询结果，清理模拟模式缓存，保留草稿方便之后预览。真实查询失败时显示错误，不偷偷回退到模拟榜单。
7. 可恢复上一发布版本，最多保留一个上一版本。

发布动作串行执行，不积累写入队列。客户端提交它读取的 `revision`；多个管理员同时操作或重试旧提交时返回 409，要求重新加载，防止覆盖或重复发布。前端禁用进行中的写按钮；发布清理缓存并递增缓存代次，在途旧查询也不能重新返回旧发布视图。

## 管理员授权

`src/sub2api-client.js` 保留主站验证过的 ID、邮箱和角色；普通会话响应只包含脱敏身份、短期会话令牌和到期时间。设置页通过受保护的管理员接口单独获取 CSRF Token。实际校验规则：

- 从主站 `/api/v1/auth/me` 的成功响应保留已经验证的 `role`。以当前主站定义的 `role === 'admin'` 授权；角色缺失、未知、停用或认证异常时拒绝访问。
- 不使用固定用户 ID、不信任 URL 的 `user_id` / `role`、浏览器存储或未经服务端验证的 JWT 声明。
- 所有 `/api/admin/*` 均执行管理员中间件；未登录 401，普通用户 403。菜单可见性不代替服务端授权。
- 获取后台设置、生成、保存、发布、恢复均重新向主站验证当前角色；会话中的旧管理员标记不应让已降权账号继续操作。
- 写接口除管理员校验外使用会话绑定的 CSRF Token，并校验完整同源 Origin。GET 不执行任何设置修改。
- 身份服务不可用时拒绝后台操作，不使用「最近是管理员」作为放行依据。
- 用户用量接口只返回当前生效的公共数据，不返回草稿、生成种子、后台配置、完整邮箱或管理员凭据。
- 正式设计不新增独立管理员账号密码，复用现有 SSO；对设置内容使用 `Cache-Control: no-store`。

已实现接口：

| 方法与地址 | 用途 |
| --- | --- |
| `GET /api/admin/session` | 实时验证管理员身份后提供短期会话 CSRF Token |
| `GET /api/admin/view` | 仅管理员获取设置表单，公共 HTML 不包含表单 |
| `GET /api/admin/settings` | 权限验证后读取草稿、发布状态与 revision |
| `POST /api/admin/simulation/preview` | 服务端按参数生成有界候选，返回预览及候选标识 |
| `GET /api/admin/leaderboard/preview` | 按 source、period、metric 读取真实 / 合并草稿预览 |
| `PUT /api/admin/settings/draft` | 校验后保存草稿，不发布 |
| `POST /api/admin/leaderboard/publish` | 发布服务端生成并校验过的候选 |
| `POST /api/admin/leaderboard/restore-real` | 切回真实榜单 |
| `POST /api/admin/leaderboard/rollback` | 恢复唯一一个上一发布版本 |

## 固定存储与部署影响

继续不新增数据库、不向 Sub2API 写入模拟用户或用量。默认全内存；设置 `USAGE_LEADERBOARD_SETTINGS_DIR` 并提供可写目录后，仅覆盖一个受大小限制的设置文件，内容是草稿、当前发布、上一发布、规则、种子、算法版本与更新时间。

- 每批最多四个周期、每期 10 条汇总。启动、保存、发布时严格校验并按种子重放；算法或时区改变导致旧数据不兼容时恢复真实模式，管理员需重新生成，不能静默重算旧数据。
- 整个设置文件限制 64 KiB；只覆盖写入，拒绝超限，不归档、不无限保留版本。
- 同目录固定名称的临时文件写入后原子替换；同一时刻最多一个写入，不不断产生带时间戳的文件。临时文件也受 64 KiB 限制。
- 磁盘写入失败时不改变内存中的已发布版本，并向管理员显示保存失败。
- 重启后读取并校验当前文件；文件缺失时默认真实模式。文件损坏时不宣称发布成功，设置页提示异常，并以真实数据模式启动。
- 需要重启保留设置时，仅增加一个小型可写配置目录挂载；容器其他目录继续只读，沿用已有日志大小上限和资源限制。
- 配置目录仅容器运行用户可写；不把管理数据目录放在静态资源目录。种子不包含邮箱或登录凭据。
- 如果选择完全不挂载，则设置和模拟数据只在内存，重启自动回到真实模式。两种行为应在部署文档中写清楚。

Compose 模板提供可选挂载注释，`.env.example` 包含设置目录说明，Dockerfile 包含受保护的 `views` 目录。管理页复用展示页的 Nginx 配置。配置文件只由单个服务进程管理，多个副本不共享该目录。

## 开发验收

- 普通用户没有设置入口，直达也看不到表单；绕过前端调用每个后台接口均返回 403。
- 伪造管理员参数、角色缺失、主站降权、主站认证失效及跨站写请求不能发布。
- 对不同随机种子、边界范围和时区验证所有周期的原始值及展示值，验证合计、排序、跨月边界和调用次数的一致性。
