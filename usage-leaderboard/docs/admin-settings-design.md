# 排行榜后台设置与实现规则

管理员设置入口为 `/#settings`，复用展示页的服务、域名及登录身份。

页面由服务端验证主站管理员角色后返回表单，数据生成、校验、草稿、发布、回退均通过正式接口完成。部署和操作见[模块 README](../README.md#管理员设置与真实用户优先)。

2026-10-16 开发验收：40 项自动测试、JavaScript 语法检查和 Compose 静态校验通过。已验证越界阻止发布、草稿隔离、真实用量保留、调用次数排序、恢复、回退及普通用户拒绝访问。桌面及 320px、390px 手机宽度无页面横向溢出。镜像发布与线上升级状态以 GitHub Actions 和实际部署为准。

## 页面与入口

- 延续现有排行页面：跟随系统主题，不添加 Logo、主题切换、系统名称或页脚宣传文字。
- 页面名称为「排行设置」。桌面采用左侧参数、右侧 Top 10 预览；手机按参数、预览、操作栏顺序排列。
- 顶部展示当前真实/模拟模式、发布版本及更新时间。草稿状态与已发布状态始终分别展示。
- 正式地址为 `https://实际排行域名/#settings`，复用当前站点、端口和 Nginx。
- 主站添加「排行设置」自定义菜单，可见角色选择「管理员」。普通用户的「用量排行」菜单保持原地址。
- 服务根据已经验证的权限决定是否展示设置导航和表单。普通用户直达设置地址只显示无权限状态，不能获取设置内容。

## 设置项

| 分区 | 控件 | 规则与默认值 |
| --- | --- | --- |
| 数据来源 | 真实用量 / 模拟榜单，分段选择 | 已发布默认真实；选择模拟只改草稿 |
| 生成范围 | 单人 Token 下限、上限，数字输入 | 硬限制 1M～1B；建议初始 1.37M～980.83M |
| 数值分布 | 自然梯度 / 差距接近 / 头部集中 | 默认自然梯度；影响数值分布，不允许突破边界 |
| 名单 | 保留当前名单，复选框 | 默认勾选；重新生成数值时保留模拟身份和脱敏邮箱 |
| 人数 | 固定 Top 10 | 首版固定 10 个模拟身份，避免无必要的配置 |
| 更新 | 手动生成与发布 | 首版不做后台自动增长、不按访问次数重新随机 |
| 预览 | 今日 / 本周 / 本月 / 累计 | 切换周期只切换视图，不重新生成名单或数值 |
| 排序 | Token 用量 / 调用次数，下拉选择 | 对同一份候选数据排序，不生成第二套数据 |

真实用户头像读取主站保存的图片，未设置或加载失败时显示默认用户图标；模拟用户统一使用默认图标。模拟身份默认生成 `ab***@example.com` 这样的脱敏形式，使用保留的示例域名，不读取真实用户邮箱来承载虚构用量。真实模式仍使用脱敏的注册邮箱。

## Token 的边界与随机性

边界指「每个模拟用户在每个可展示周期的 Token 汇总」，不是全站总和，也不限制真实用户的真实用量。10 人合计可以超过 1B，必须与各行相加一致。

- `1M = 1,000,000`，`1B = 1,000,000,000`，采用十进制单位。
- 原始 Token 使用整数，例如 `823,473,219`；显示为 `823.47M`。Token 本身是计数，不生成 `0.5 Token`。
- 「不能是整数」按用户看到的 M/B 数值解释：统一使用两位小数的 M，避开 `100.00M`、`1.00B` 等整数展示及明显的整百万、整千万值。
- 原始数量与格式化结果同时校验，特别防止 `999.999M` 四舍五入成 `1000.00M`。虽然允许的上限是 1B，随机生成结果无需取到这个边界。
- 不使用等差数列、固定倍数或固定尾数。对不同档位加入随机扰动，生成独立的低位数字。
- 生成后按指标排序。相同原始值或显示值过于密集时，在有限次数内重新采样；无法满足所选范围时明确报错，不放宽边界、不无限循环。
- 生成、保存草稿、发布三处均执行同一份服务端校验。前端数字输入限制仅用于即时反馈。
- 请求次数保持整数，从同一批模拟用量按随机的单次 Token 量推导，避免每个人都使用相同的 Token/调用比例。

例如一组本月候选用量可以是 `823.47M`、`692.83M`、`531.26M`、`418.79M`、`306.42M`、`218.67M`、`146.93M`、`82.51M`、`37.28M`、`8.64M`。这只是展示示例，不是固定模板。

## 跨周期与相关数据

正式生成器以随机种子、版本和固定统计时间为输入，生成固定 94 个自然日的模拟桶，再聚合出四个周期。只保存最终所需的有限结果，不保存日桶、请求明细，也不每天追加历史。

- 今日是本周和本月的子集；本周、本月分别是累计的子集。本周可能跨月，因此不能通用地断言本周小于本月。
- 所有周期均校验单人 1M～1B；累计的最高值仍不超过 1B。预算无法同时满足时拒绝生成，不通过最后裁剪汇总值来破坏加总关系。
- 主站时区决定周期边界。发布的是当日固定快照，跨天（含跨周、月、年）后自动恢复真实榜单，旧草稿及旧模拟回退版本均不可发布。管理员重新生成后再发布新的快照。
- 用户刷新、切换周期、切换排序不会变换模拟用量。同一发布版本的所有访问者获得相同的模拟用量，真实部分按正常缓存周期刷新。
- 混合模式的三项概览改称「榜单 Token 用量」「上榜创造者」「榜单调用次数」，仅汇总当前显示的真实与模拟用户，不将模拟合计当作全站总量。
- 首版模拟榜单不显示排名涨跌、增长率或「新上榜」，避免没有上期基准的比较。真实模式保持现有计算方式。
- 用户侧保留轻量的「示例数据」标识，榜单规则随模式切换。
- 「我的实际用量」、近 7 天趋势和常用模型继续读取本人真实记录。模拟模式隐藏本人排名、超越比例、追赶差距和「找到我的位置」，不把真实账号与模拟名单进行排名比较。
- 继续不查询、不生成、不返回消费金额、余额或充值数据。

## 真实用户优先规则

范围以所选周期的真实 Token 总量判断，沿用现有的可用用户范围和管理员参与开关。达到配置下限即优先保留，超过上限甚至超过 1B 的真实用户同样保留，不将其裁剪到模拟上限。低于下限的真实用户不预留名额。

达到下限的真实用户少于 10 位时，全数保留，模拟用户补足剩余名额，最后按 Token 或调用次数排序。同值并列，真实用户排前，稳定标识决定后续顺序。由于保留了真实名额，结果是「真实优先的混合榜单」，可能包含低于被舍弃模拟记录的真实用户，不宣称普通全体混排 Top 10。

达到下限的真实用户至少 10 位时，不再补模拟身份，从达标真实用户中按当前指标选取 10 位。与原有全站真实 Top 10 一致时，恢复全站概览、真实名次与比较。按调用次数排序可能使低 Token、高频用户进入全站 Top 10，此时仍优先保留达标用户，并只汇总当前榜单，隐藏个人名次比较，避免挤掉必须保留的真实用户。超过 10 位无法同时显示，依照当前指标与并列规则截取。

真实记录只在数据库聚合，额外返回最多 10 位达标真实用户，无需在应用中加载全体邮箱或明细。模拟身份不替换真实身份的用量；与真实脱敏邮箱显示重名时自动改用另一模拟名称。混合榜响应逐行保留来源，个人用量不经过模拟生成器。

## 草稿、发布与恢复

1. 管理员调整参数后点击「随机生成」。仅替换内存候选数据，用户仍看到已发布版本。
2. 可切换周期与指标检查候选效果。生成参数再变化时标记「参数已修改，待生成」，禁止发布与参数不匹配的旧候选。
3. 「保存草稿」保存当前规则及候选，仍不影响用户榜单。
4. 「发布榜单」弹窗确认范围、身份数量和模式；再次验证管理员与候选数据，通过版本检查后一次性替换当前发布版本并使相关缓存失效。
5. 后续生成与草稿保存不改变已发布数据；只有下一次发布才替换。
6. 「恢复真实榜单」立即切回只读查询结果，清理模拟模式缓存，保留草稿方便之后预览。真实查询失败时显示错误，不偷偷回退到模拟榜单。
7. 可恢复上一发布版本，最多保留一个上一版本。

发布动作串行执行，不积累写入队列。客户端提交它读取的 `revision`；多个管理员同时操作或重试旧提交时返回 409，要求重新加载，防止覆盖或重复发布。前端禁用进行中的写按钮；发布清理缓存并递增缓存代次，在途旧查询也不能重新返回旧发布视图。

## 管理员授权

`src/sub2api-client.js` 保留主站验证过的 ID、邮箱和角色；会话对浏览器只暴露脱敏身份与后台能力标记。实际校验规则：

- 从主站 `/api/v1/auth/me` 的成功响应保留已经验证的 `role`。以当前主站定义的 `role === 'admin'` 授权；角色缺失、未知、停用或认证异常时拒绝访问。
- 不使用固定用户 ID、不信任 URL 的 `user_id` / `role`、浏览器存储或未经服务端验证的 JWT 声明。
- 所有 `/api/admin/*` 均执行 `requireAdmin`；未登录 401，普通用户 403。隐藏导航只是界面行为，不代替服务端授权。
- 获取后台设置、生成、保存、发布、恢复均重新向主站验证当前角色；会话中的旧管理员标记不应让已降权账号继续操作。
- 写接口除管理员校验外使用会话绑定的 CSRF Token，并校验完整同源 Origin。GET 不执行任何设置修改。
- 身份服务不可用时拒绝后台操作，不使用「最近是管理员」作为放行依据。
- 用户用量接口只返回当前生效的公共数据，不返回草稿、生成种子、后台配置、完整邮箱或管理员凭据。
- 正式设计不新增独立管理员账号密码，复用现有 SSO；对设置内容使用 `Cache-Control: no-store`。

已实现接口：

| 方法与地址 | 用途 |
| --- | --- |
| `GET /api/admin/view` | 仅管理员获取设置表单，公共 HTML 不包含表单 |
| `GET /api/admin/settings` | 权限验证后读取草稿、发布状态与 revision |
| `POST /api/admin/simulation/preview` | 服务端按参数生成有界候选，返回预览及候选标识 |
| `GET /api/admin/leaderboard/preview` | 按 source、period、metric 读取真实 / 合并草稿预览 |
| `PUT /api/admin/settings/draft` | 校验后保存草稿，不发布 |
| `POST /api/admin/leaderboard/publish` | 发布服务端生成并校验过的候选 |
| `POST /api/admin/leaderboard/restore-real` | 切回真实榜单 |
| `POST /api/admin/leaderboard/rollback` | 恢复唯一一个上一发布版本 |

## 固定存储与部署影响

继续不新增数据库、不向 Sub2API 写入模拟用户或用量。默认全内存；设置 `USAGE_LEADERBOARD_SETTINGS_DIR` 并提供可写目录后，仅覆盖一个受大小限制的设置文件，内容是草稿、当前发布、上一发布、规则、种子、算法版本与更新时间。

- 每批最多四个周期、每期 10 条汇总。启动、保存、发布时严格校验并按种子重放；算法或时区改变导致旧数据不兼容时恢复真实模式，管理员需重新生成，不能静默重算旧数据。
- 整个设置文件限制 64 KiB；只覆盖写入，拒绝超限，不归档、不无限保留版本。
- 同目录固定名称的临时文件写入后原子替换；同一时刻最多一个写入，不不断产生带时间戳的文件。临时文件也受 64 KiB 限制。
- 磁盘写入失败时不改变内存中的已发布版本，并向管理员显示保存失败。
- 重启后读取并校验当前文件；文件缺失时默认真实模式。文件损坏时不宣称发布成功，设置页提示异常，并以真实数据模式启动。
- 需要重启保留设置时，仅增加一个小型可写配置目录挂载；容器其他目录继续只读，沿用已有日志大小上限和资源限制。
- 配置目录仅容器运行用户可写；不把管理数据目录放在静态资源目录。种子不包含邮箱或登录凭据。
- 如果选择完全不挂载，则设置和模拟数据只在内存，重启自动回到真实模式。两种行为应在部署文档中写清楚。

Compose 模板提供可选挂载注释，`.env.example` 包含设置目录说明，Dockerfile 包含受保护的 `views` 目录。管理页复用展示页的 Nginx 配置。配置文件只由单个服务进程管理，多个副本不共享该目录。

## 开发验收

- 普通用户没有设置入口，直达也看不到表单；绕过前端调用每个后台接口均返回 403。
- 伪造管理员参数、角色缺失、主站降权、主站认证失效及跨站写请求不能发布。
- 对不同随机种子、边界范围和时区验证所有周期的原始值及展示值，验证合计、排序、跨月边界和调用次数的一致性。
- 参数变更使旧候选失效；草稿不影响发布；发布原子切换；缓存不混用真实与模拟版本。
- 实际用量及身份数据保持真实且脱敏，模拟数据不进入主站表，也不进入个人排行比较。
- 重启、写入失败、损坏文件、并发管理员与重复提交具有明确结果；文件和内存大小有上限。
- 桌面、手机与系统深浅色下，参数、Top 10、错误提示和发布确认框均可操作且不重叠。
