# 用户画像页面设计方案

## 页面定位

在运营中心“用户分析”之后新增“用户画像”tab。“用户分析”继续处理新增、活跃和注册留存；“用户画像”处理每个用户如何使用平台 / 模型、消费贡献，以及可解释的行为分层。管理员从整体构成进入具体用户，无需跳转到不同模块拼接信息。

采用现有后台的浅色底、绿色主操作、顶部横向导航，搭配低饱和珊瑚色、绿色、蓝色和紫色区分平台。平台颜色在环图、模型条、用户堆叠条和详情中保持一致。主体采用平整的分析区与表格，只有四个重复概要指标使用独立卡片。长表在移动端局部横向滚动；其他内容自然堆叠。

## 主要视图

1. 范围与概要：近 7 / 30 天或自定义范围，计费类型与平台；区间活跃用户、实际消费、人均消费、多平台使用率。
2. 平台与模型偏好：平台环图与 Top 5 模型横条并列，支持请求 / Token / 实际消费三个口径；其他模型汇总保留完整分母。
3. 消费集中度：用户按消费排序后的前 20%、中间 30%、剩余用户贡献。显示实际人数，百分比人数向上取整，避免小样本误导。
4. 运营关注：最近 7 天明显下降、余额预计不足 3 天；点击筛选用户明细。
5. 用户画像明细：身份、平台堆叠占比与主要模型、消费额度、占当前统计范围消费的比例、请求数、活跃天数、解释性标签。支持搜索、排序、分页、导出当前筛选全部用户。
6. 用户详情抽屉：平台与模型占比、Token 构成；每日消费 / 请求趋势、活跃日历、当前余额、最近使用与注册时间。保留当前主页面日期、计费、平台与占比口径。

## 指标口径

| 指标 | 分子 / 计算方法 | 分母 / 边界 |
| --- | --- | --- |
| 平台 / 模型请求占比 | 该平台 / 模型请求数 | 当前范围全部请求 |
| 平台 / 模型 Token 占比 | 输入 + 输出 + 缓存读取 + 缓存创建 | 当前范围全部四类 Token |
| 平台 / 模型消费占比 | 该平台 / 模型实际消费额度 | 当前范围总实际消费 |
| 用户消费占比 | 单用户实际消费 | 当前范围总实际消费，用户搜索与标签不改变分母 |
| 用户详情内占比 | 单用户在平台 / 模型的对应指标 | 该用户在当前范围的对应指标 |
| 人均消费 | 当前范围实际消费合计 | 当前范围去重活跃用户，不是全部注册用户 |
| 多平台使用率 | 在至少两个平台有请求的用户 | 当前范围去重活跃用户 |
| 高消费 | 当前范围消费排序前 20% 的正消费用户 | 人数向上取整，属于分层而非人工价值评分 |
| 活跃下降 | 最近 7 天请求比前 7 天下降至少 50% | 前 7 天至少 100 请求；固定 14 天窗口，遵循平台筛选 |
| 余额可用天数 | 当前余额 / 最近 7 天日均余额消费 | 仅按量付费；消费涵盖该用户所有平台，不随平台筛选缩小 |

消费额度沿用运营中心 `actual_cost` 口径，包含按量与订阅；不与充值实收、标准计价 `total_cost` 或账号成本混用。单位先展示“额度”，正式接入时核验部署的额度单位，不擅自换算为人民币或美元。

排除 ID 1 管理员。日期起止均包含，时区使用站点配置，demo 为 Asia/Shanghai。零分母显示“—”；无使用记录显示空状态，历史缺失应显示不可用，不伪装成零值。

余额是当前快照，不是所选日期的历史余额。订阅用户不将订阅额度消费用于余额寿命推算。demo 的每个用户使用一个示例计费类型；正式实现按请求 `billing_type` 筛选，兼容同一用户混合计费。

## 数据接入评估

| 数据 | 计划来源 | 已知约束 |
| --- | --- | --- |
| 用户身份、注册、当前状态 / 余额 | `users` | 只展示管理员分析所需字段，删除用户须保留独立标识以便对账 |
| 用户 / 模型 / 日 / 计费细分 | `usage_logs` | 默认仅保留 30 天，按明细保留策略约束日期 |
| 用户请求模型 | 优先 `requested_model`，回退 `model` | 按用户请求模型展示；不把路由后的模型悄悄替换为请求模型 |
| 平台 | 按日志关联的分组 / 平台字段核验 | 当前 schema inspector 尚未登记平台关联表；开发前核对日志与 `groups.platform` / 历史平台字段，不能仅凭模型名推断 |
| 长期去重活跃 | `usage_dashboard_daily_users` | 能用于活跃，但不能还原已清理的用户模型消费 |
| 余额估算 | 当前 `users.balance` + 近 7 天余额计费实际消费 | 开发前核验余额计费枚举与额度单位，订阅不参与 |
| Token 构成 | 四类 Token 明细 | 不包装成请求级缓存命中率；图片 / 视频不宜只按 Token 衡量 |

当前默认仅设计近 30 天完整画像。若需要 90 天 / 半年模型与消费画像，应另行确认延长明细保留或保存聚合快照的方案；现有站点日汇总无法按用户和模型补回历史数据。

## 确认后开发范围

第一版覆盖当前 demo 的核心数据与交互：tab、四项概要、平台 / 模型占比、消费集中度、用户明细与详情，以及解释性分层。新增运营中心只读画像接口，复用现有管理员认证、SQL 参数化、范围校验、缓存和 ECharts / Lucide。正式上线验证汇总与明细对平、不同分母、混合计费、管理员排除、零消费、删除用户、未知平台、缺失明细和日期时区边界。

运营关注与余额估算需要真实 schema 核验后接入；无法取得必要数据时显示不可用。请求成功率、P95 时延与“流失概率”不在本版承诺范围：不能从现有用量日志直接得出请求成功率，也不使用未经验证的概率或评分。

此次仅交付视觉与交互 demo，正式服务代码、导航、数据库和部署均未修改。
