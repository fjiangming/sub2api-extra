# 降智检测

降智检测是 Sub2API Extra 的独立服务。当前登录用户的短期 Token 只用于校验身份，以及读取该用户通过 `GET /api/v1/groups/available` 有权查看的分组；模型检测统一使用管理员配置的分组专用 Key，不会读取、创建或消费登录用户的 Key。

## 权限边界

| 能力 | 管理员 | 普通用户 |
|---|---:|---:|
| 查看自己有权分组的共享检测结果 | 是 | 是 |
| 在结果页修改配置或发起检测 | 否 | 否 |
| 在管理页立即检测 | 是 | 否 |
| 在管理页人工复核检测状态 | 是 | 否 |
| 在管理页清理检测历史 | 是 | 否 |
| 访问 `/admin/config` 及其页面资源 | 是 | 否 |
| 读取或修改检测配置 | 是 | 否 |

结果页与管理页是两个独立入口。`/results` 对所有已登录用户保持同一套只读界面，即使管理员打开结果页也不会收到配置入口、专用 Key 状态或手动检测能力。`/admin/config`、管理脚本和所有 `/api/admin/*` 接口都在服务端执行登录校验与实时管理员角色复核。所有配置写入和手动检测还要求当前会话的 CSRF Token，并受请求频率限制。

Sub2API 菜单的角色可见性只负责入口展示，不能单独作为安全边界；真正的越权防护由本服务端完成。普通用户即使猜到管理地址、携带自己的 Token 或直接调用管理接口，也会得到 `403`。旧的 `/api/groups/:groupId/runs` 手动检测接口已移除。

结果列表、详情、预览和下载均按以下交集授权：

```text
管理员已启用的分组 ∩ 当前登录用户在 Sub2API 中有权访问的分组
```

随机预览 Token 只是结果定位符，不能替代登录态与分组权限。HTML 作品使用 sandbox iframe 和独立 CSP 展示，禁止联网、表单、对象和外层页面访问。

### 只读页面的剩余风险

- 检测结果是分组内共享数据：任何当前仍有该分组权限的用户都可以查看管理员专用 Key 生成的答案和文件。检测提示词不得包含密码、Token、个人信息或其它不应向分组成员公开的内容。
- 只读结果详情会展示规则名称、通过状态、得分和判定说明，但不会返回提示词、规则匹配值或完整配置快照。规则名称同样不得填写秘密信息。
- 人工复核状态、复核理由和复核时间会展示给有该分组权限的用户；复核理由不得填写账号、Key、个人信息或内部敏感信息。复核管理员身份只保存在服务端，不会返回普通结果接口。
- Sub2API 自定义菜单会在首次跳转 URL 中携带短期 Token。服务会立即换取本地会话、清理地址栏并设置 `Referrer-Policy: no-referrer`，但反向代理仍可能记录首个请求的完整查询串。生产环境必须使用 HTTPS，并在代理访问日志中隐藏或删除 `token`、`access_token` 参数。
- 只读不等于匿名：结果、详情、预览和下载仍要求有效登录态，并在每次访问时重新计算用户可见分组。用户被移出分组或管理员停用分组后，旧预览地址也不再可访问。

## 可视化配置

管理员从 Sub2API 的“降智检测管理”菜单直接进入管理页。管理页支持：

- 启用需要检测的平台；
- 为平台配置默认的模型、请求协议、提示词、输出类型、推理强度、最大输出量和判定规则；
- 查看该平台下 Sub2API 返回的全部分组，并选择允许检测的分组；
- 在任一分组后的设置按钮中建立独立检测配置，使同一平台下的不同分组使用不同模型、题目、输出方式和判定规则；未建立独立配置的分组继续继承平台默认；
- 为每个启用分组填写独立的完整专用 Key；
- 配置 `Asia/Shanghai` 时区下每天一个或多个固定时间，或按分钟、小时、天设置检测间隔；
- 使用已经保存的题目和分组专用 Key 发起单次立即检测。
- 对已产生判定的历史记录进行人工复核，并可随时撤销以恢复自动结论；
- 按分组查看历史记录，勾选一条或多条记录批量删除，或清空该分组全部已结束记录；排队和检测中的任务不会被清理。

支持 OpenAI Responses、Chat Completions、Anthropic Messages、Gemini generateContent 和 Images Generations。OpenAI 协议的推理强度支持 `minimal`、`low`、`medium`、`high`、`xhigh` 和 `max`。输出可以是直接答案、HTML、图片或通用 Base64 文件；图片、文本、JSON、PDF、音视频可预览，其它文件可下载。

## 判定规则

判定分为两层。内置完整性检查只确认响应非空、声明的输出类型可解析，以及图片或文件可以解码；完整性不足会记为“无法判定”，不会直接指控模型降智。题目内容是否合格由当前分组的有效规则决定：分组有独立配置时使用独立规则，否则使用平台默认规则。

每条规则可设置为“核心规则”或“辅助规则”并分配权重。核心规则失败会直接判为“疑似降智”；核心规则全部通过后，按通过权重计算 0 至 100 分。达到正常分数线为“正常”，不高于降智分数线为“疑似降智”，处于两个阈值之间为“无法判定”。支持最小/最大字节数、精确文本、包含文本、匹配/禁止正则、HTML CSS 选择器、可选 SVG 数学关系、JSON Schema、MIME 类型和图片尺寸。高风险正则会在保存时被拒绝。

SVG 数学检测默认关闭，只有管理员在对应平台的判定规则中单独开启后才会执行。它直接解析 SVG 坐标和声明式 `<animate>`、`<animateTransform>`，不会启动浏览器、执行生成内容中的脚本或保存截图。支持元素距离、上下左右关系、横纵对齐、保持在 `viewBox` 内、最小位移、最小旋转量和动画首尾距离。采样点限制为 2 至 24 个；复杂 `path` 或 `g` 可以使用 `data-anchor-x`、`data-anchor-y` 指定判定锚点，使用 `data-bbox="x y width height"` 指定本地包围盒。选择器不唯一、坐标不可解析、含脚本、CSS 动画、`animateMotion`、`set`，或超过 2 MB、10000 个 SVG 节点、50000 次几何操作的资源上限时，数学规则会记为“无法计算”，整次结果进入“无法判定”而不是误判为降智。关闭开关时已配置的 SVG 数学规则不参与评分，其他规则保持原有行为。

分组综合状态使用当前题目配置下的有效检测确认。首次正常结果会建立正常状态，正常状态下默认最近 3 次中至少 2 次疑似降智才确认降智，确认降智后连续 2 次正常才恢复；“无法判定”和“检测异常”不参与确认。提示词、模型、协议、推理强度、输出上限或规则发生变化后，旧配置下的结果不会混入新配置的综合状态。每次检测都会保存当时的配置快照、得分和逐条规则结果。

### 分组独立配置

平台区域左侧的“平台默认检测配置”是该平台所有分组的继承模板。要让某个分组使用不同模型或题目，在右侧分组列表点击设置图标，编辑完整检测配置后点击“应用独立配置”，再点击页面顶部“保存配置”。分组行会显示“独立检测配置”；在同一弹窗点击“恢复平台默认”并保存即可取消覆盖。

独立配置包含模型、协议、提示词、输出类型、推理强度、最大输出 Token、MIME 类型和全部判定规则。自动检测、立即检测、结果页模型信息以及综合状态都使用该分组当前的有效配置。升级前的分组不会自动产生独立配置，因此行为保持不变并继续继承原平台配置。

管理员可在配置页的分组“历史”弹窗中对已产生判定的记录进行人工复核，将最终状态设为“正常”“疑似降智”或“无法判定”，并必须填写复核理由。人工状态会参与降智率和综合判定，但不会覆盖数据库中的自动状态、自动评分或规则证据；撤销复核即可恢复自动结论。排队中、检测中和请求异常记录不能人工改写。复核接口仍要求管理员身份、CSRF 令牌和当前分组管理权限，普通结果页只读展示复核结论及原自动状态。

### 鹈鹕自行车 HTML 示例

在管理页进入目标平台的“检测题配置”，将输出类型设为 `HTML`，提示词填写：

```text
创建一个完整、可直接在浏览器打开的 HTML 文件，使用内联 SVG 绘制一只鹈鹕骑自行车的二维循环动画。
只输出 HTML 源码，不要使用 Markdown 代码块，不要解释。
SVG 必须设置 viewBox；鹈鹕主体使用 id="pelican"，自行车主体使用 id="bicycle"，两个车轮使用 class="wheel"。
至少使用一组 CSS @keyframes，让鹈鹕、自行车或车轮产生持续循环动画。
所有 HTML、CSS 和 SVG 必须内联，不得引用任何外部脚本、图片、字体或网络资源。
```

设置正常分数线 `90`、降智分数线 `60`、观察最近次数 `3`、确认降智次数 `2`、恢复连续正常次数 `2`，然后按顺序添加以下规则：

| 规则名称 | 类型 | 级别 | 权重 | 配置值 |
|---|---|---|---:|---|
| HTML 内容完整度 | 最小字节数 | 辅助 | 10 | `4000` |
| 完整 HTML 文档 | HTML 选择器 | 核心 | 10 | 选择器 `html`，最少 `1` |
| 带 viewBox 的 SVG 场景 | HTML 选择器 | 核心 | 15 | 选择器 `svg[viewBox]`，最少 `1` |
| 鹈鹕主体 | HTML 选择器 | 核心 | 20 | 选择器 `#pelican`，最少 `1` |
| 自行车主体 | HTML 选择器 | 核心 | 20 | 选择器 `#bicycle`，最少 `1` |
| 两个自行车车轮 | HTML 选择器 | 核心 | 10 | 选择器 `.wheel`，最少 `2` |
| 定义 CSS 关键帧 | 包含文本 | 核心 | 7 | `@keyframes` |
| 应用 CSS 动画 | 匹配正则 | 核心 | 8 | `animation(?:-name)?\s*:` |
| 不引用外部资源 | HTML 选择器 | 核心 | 10 | 选择器 `[src^="http"], [href^="http"], [src^="//"], [href^="//"]`，最少 `0`、最多 `0` |

新安装且尚未保存 OpenAI 平台配置时会自动带出这一模板；已有平台配置不会被升级过程覆盖，需要在管理页手动调整后保存。

### 鹈鹕自行车 SVG 数学检测示例

需要进一步检查脚踏接触和动画几何时，将提示词调整为以下约束，并删除原来要求 CSS `@keyframes` 的两条规则：

```text
创建一个完整、可直接在浏览器打开的 HTML 文件，使用单个内联 SVG 绘制一只鹈鹕骑自行车的二维循环动画。
只输出 HTML 源码，不要使用 Markdown 代码块，不要解释，不得引用外部资源。
只使用 SVG 的 animate 或 animateTransform 制作声明式循环动画，不使用 JavaScript、CSS animation、CSS transform 或 foreignObject。
SVG 必须设置 viewBox。实际可见元素必须使用以下唯一 ID：pelican、bicycle、front-wheel、rear-wheel、left-foot、right-foot、left-pedal、right-pedal；两个车轮同时使用 class="wheel"。
left-foot、right-foot、left-pedal、right-pedal 必须用 data-anchor-x 和 data-anchor-y 标记各自实际接触点；复杂的 pelican 和 bicycle 分组使用 data-bbox="x y width height" 标记其本地包围盒。
左右脚在整个动画周期中分别保持在对应踏板上，两个车轮中心同高并持续旋转，主体始终位于 viewBox 内，动画首尾连续。
```

在“判定规则”中开启“SVG 数学检测”，设置动画采样点 `12`、关系通过比例 `90%`，然后按需添加：

| 规则名称 | 数学关系 | 源元素 | 目标元素 | 尺寸参照 | 阈值 |
|---|---|---|---|---|---:|
| 左脚踩左踏板 | 距离不超过阈值 | `#left-foot` | `#left-pedal` | `#front-wheel` | `0.08` |
| 右脚踩右踏板 | 距离不超过阈值 | `#right-foot` | `#right-pedal` | `#front-wheel` | `0.08` |
| 车轮中心同高 | 纵向中心对齐 | `#front-wheel` | `#rear-wheel` | 留空 | `4` |
| 鹈鹕位于自行车上方 | 位于目标上方 | `#pelican` | `#bicycle` | 留空 | `0` |
| 自行车保持在画面内 | 保持在 viewBox 内 | `#bicycle` | 留空 | 留空 | `0` |
| 前轮持续旋转 | 旋转不少于阈值 | `#front-wheel` | 留空 | 留空 | `300` |
| 鹈鹕动画首尾连续 | 首尾位置接近 | `#pelican` | 留空 | `#front-wheel` | `0.05` |

配置尺寸参照后，阈值按参照元素最大宽高一半的比例计算；例如车轮直径为 `80` 时，阈值 `0.08` 表示允许距离 `3.2` 个 SVG 单位。没有尺寸参照时阈值直接使用 SVG 坐标单位，旋转规则的阈值固定使用角度。

OpenAI Responses 检测使用 SSE 流式请求，并且只有收到 `response.completed` 后才会保存和展示答案；`response.incomplete`、`response.failed` 或没有完成标记的断流不会把残缺 HTML 当成有效结果。该方式已通过 Sub2API 公网入口实测，原本约 125 秒触发 `HTTP 524` 的完整 HTML 请求可以在同一次推理中持续接收事件并最终得到完整文档。

只有能够确认请求尚未送达的建连失败，或明确返回的 HTTP 429、503，才会在单次检测总时间预算内按 `1、2、4、8、16` 秒退避并最多自动重试 5 次。收到成功 HTTP 响应头、`response.created` 或其它模型事件后，连接中断都不会重新提交推理；请求是否送达无法确认时同样停止重提，避免同一次任务重复计费。当前 Sub2API 对后台 Responses 和 `GET /v1/responses/{id}` 的实测结果分别为 `400` 和 `404`，因此服务不会假装可以恢复服务端任务；流式 `HTTP 524` 也不会盲目重试。鉴权、配置和响应格式错误同样不会重试。

取消选择分组并保存后，该分组会停止调度，其专用 Key 会被清除，历史轻量判定和独立检测配置继续保留；重新启用时需要重新填写专用 Key。手动检测不会改变自动计划中的下一次执行时间。

## 专用 Key

每个目标分组应使用独立服务账号创建一个专用 Key。Sub2API Key 与分组绑定，不同分组不能复用同一个 Key。

Key 提交后使用 AES-256-GCM 加密写入 SQLite，并绑定对应分组 ID；加密主密钥首次启动时随机生成在数据目录的 `.credential-key` 文件中，文件权限会收紧为仅服务进程可读写。浏览器只会收到“已配置/未配置”，后端不会回显、记录日志或把明文 Key 写入数据库。

备份时必须同时保护数据库和 `.credential-key`。丢失 `.credential-key` 后已有 Key 无法解密，服务会停止对应检测并要求管理员重新配置；仅泄漏数据库文件不会直接得到明文 Key。

## 环境变量

从模板创建环境文件：
services:
  degradation-detector:
    image: ghcr.io/fjiangming/sub2api-extra:degradation-detector-latest
    container_name: sub2api-degradation-detector
    restart: unless-stopped
    ports:
      - "127.0.0.1:9873:9873"
```bash
cp degradation-detector/.env.example degradation-detector/.env
```

环境文件只需配置服务可访问的 Sub2API 地址：

```dotenv
SUB2API_BASE_URL=http://host.docker.internal:8080
```

平台、检测题、分组、专用 Key 和自动检测计划不再从环境变量读取。旧版 `DEGRADATION_DETECTOR_GROUP_KEYS_JSON`、`DEGRADATION_DETECTOR_SUPPORTED_PLATFORMS`、`DEGRADATION_DETECTOR_TESTS_JSON` 和间隔配置会被忽略，需要由管理员在配置页重新保存。

## 部署

```bash
docker compose --env-file compose.services.env --profile degradation-detector up -d degradation-detector
```

服务固定映射到 `127.0.0.1:9873`。通过 HTTPS 反向代理后，在 Sub2API 自定义菜单中分别配置两个入口。

普通用户模块：

```text
标签：降智检测结果
URL：https://detector.example.com/results?token={token}&theme={theme}
可见角色：全部已登录用户
```

管理员模块：

```text
标签：降智检测管理
URL：https://detector.example.com/admin/config?token={token}&theme={theme}
可见角色：仅管理员
```

两个入口都兼容 `token` 与 `access_token` 参数名，并在换取本地短期会话后立即从地址栏移除上游 Token。管理入口会先在服务端验证 Token 对应用户确实仍为管理员，再创建本地会话和返回页面。生产环境使用 Secure 和 Partitioned Cookie；反向代理必须保留 HTTPS 协议信息。

首次部署时结果页为空是正常状态。管理员从独立管理入口保存至少一个平台、分组及其专用 Key 后，该分组才会出现在只读结果页并进入自动调度。

当前会话、SQLite 写入和调度器按单实例设计，请只运行一个服务副本。数据卷 `sub2api-extra_degradation-detector-data` 必须持久化。

```bash
cd degradation-detector
npm ci
npm test
```

```powershell
$env:NODE_ENV='development'
$env:DEGRADATION_DETECTOR_DEMO_MODE='true'
$env:PORT='9873'
node src/server.js
```
