# 降智检测

降智检测是 Sub2API Extra 的独立服务。当前登录用户的短期 Token 只用于校验身份，以及读取该用户通过 `GET /api/v1/groups/available` 有权查看的分组；模型检测统一使用管理员配置的分组专用 Key，不会读取、创建或消费登录用户的 Key。

## 权限边界

| 能力 | 管理员 | 普通用户 |
|---|---:|---:|
| 查看自己有权分组的共享检测结果 | 是 | 是 |
| 在结果页修改配置或发起检测 | 否 | 否 |
| 在管理页立即检测 | 是 | 否 |
| 在管理页人工复核检测状态 | 是 | 否 |
| 在管理页清理检测历史 | 是 | 否 |
| 访问 `/admin/config` 及其页面资源 | 是 | 否 |
| 读取或修改检测配置 | 是 | 否 |

结果页与管理页是两个独立入口。`/results` 对所有已登录用户保持同一套只读界面，即使管理员打开结果页也不会收到配置入口、专用 Key 状态或手动检测能力。`/admin/config`、管理脚本和所有 `/api/admin/*` 接口都在服务端执行登录校验与实时管理员角色复核。所有配置写入和手动检测还要求当前会话的 CSRF Token，并受请求频率限制。

Sub2API 菜单的角色可见性只负责入口展示，不能单独作为安全边界；真正的越权防护由本服务端完成。普通用户即使猜到管理地址、携带自己的 Token 或直接调用管理接口，也会得到 `403`。旧的 `/api/groups/:groupId/runs` 手动检测接口已移除。

结果列表、详情、预览和下载均按以下交集授权：

```text
管理员已启用的分组 ∩ 当前登录用户在 Sub2API 中有权访问的分组
```

随机预览 Token 只是结果定位符，不能替代登录态与分组权限。HTML 作品使用 sandbox iframe 和独立 CSP 展示，禁止联网、表单、对象和外层页面访问。

### 只读页面的剩余风险

- 检测结果是分组内共享数据：任何当前仍有该分组权限的用户都可以查看管理员专用 Key 生成的答案和文件。检测提示词不得包含密码、Token、个人信息或其它不应向分组成员公开的内容。
- 只读结果详情会展示规则名称、通过状态、得分和判定说明，但不会返回提示词、规则匹配值或完整配置快照。规则名称同样不得填写秘密信息。
- 人工复核状态、复核理由和复核时间会展示给有该分组权限的用户；复核理由不得填写账号、Key、个人信息或内部敏感信息。复核管理员身份只保存在服务端，不会返回普通结果接口。
- Sub2API 自定义菜单会在首次跳转 URL 中携带短期 Token。服务会立即换取本地会话、清理地址栏并设置 `Referrer-Policy: no-referrer`，但反向代理仍可能记录首个请求的完整查询串。生产环境必须使用 HTTPS，并在代理访问日志中隐藏或删除 `token`、`access_token` 参数。
- 只读不等于匿名：结果、详情、预览和下载仍要求有效登录态，并在每次访问时重新计算用户可见分组。用户被移出分组或管理员停用分组后，旧预览地址也不再可访问。

## 可视化配置

管理员从 Sub2API 的“降智检测管理”菜单直接进入管理页。管理页支持：

- 启用需要检测的平台；
- 为平台配置默认的模型、请求协议、提示词、输出类型、推理强度、最大输出量和判定规则；
- 可选开启满血 AI 或兼容 HTML 审核服务，并为平台或分组配置独立的审核接口与专用 Key；
- 查看该平台下 Sub2API 返回的全部分组，并选择允许检测的分组；
- 在任一分组后的设置按钮中建立独立检测配置，使同一平台下的不同分组使用不同模型、题目、输出方式和判定规则；未建立独立配置的分组继续继承平台默认；
- 为每个启用分组填写独立的完整专用 Key；
- 配置 `Asia/Shanghai` 时区下每天一个或多个固定时间，或按分钟、小时、天设置检测间隔；
- 使用已经保存的题目和分组专用 Key 发起单次立即检测。
- 对已产生判定的历史记录进行人工复核，并可随时撤销以恢复自动结论；
- 按分组查看历史记录，勾选一条或多条记录批量删除，或清空该分组全部已结束记录；排队和检测中的任务不会被清理。

支持 OpenAI Responses、Chat Completions、Anthropic Messages、Gemini generateContent 和 Images Generations。OpenAI 协议的推理强度支持 `minimal`、`low`、`medium`、`high`、`xhigh` 和 `max`。输出可以是直接答案、HTML、图片或通用 Base64 文件；图片、文本、JSON、PDF、音视频可预览，其它文件可下载。

## 判定规则

判定分为两层。内置完整性检查只确认响应非空、声明的输出类型可解析，以及图片或文件可以解码；完整性不足会记为“无法判定”，不会直接指控模型降智。题目内容是否合格由当前分组的有效规则决定：分组有独立配置时使用独立规则，否则使用平台默认规则。

每条规则可设置为“核心规则”或“辅助规则”并分配权重。核心规则明确失败会直接判为“疑似降智”；全部规则都可计算时，按通过权重计算 0 至 100 分。存在无法计算的规则时，系统分别按“未知规则全部失败”和“未知规则全部通过”计算最低分、最高分与可计算覆盖率：最低分仍达到正常线才可判为“正常”，最高分仍不高于降智线才可判为“疑似降智”，其余情况为“无法判定”；核心规则无法计算时不会判为正常。支持最小/最大字节数、精确文本、包含文本、匹配/禁止正则、HTML CSS 选择器、可选 SVG 数学关系、JSON Schema、MIME 类型和图片尺寸。高风险正则会在保存时被拒绝。

用于模型能力比较时，不要把输出长度、固定命名、检测锚点或指定实现方式设置为核心规则。这些项目只决定判定器能否读取作品，并不直接证明模型能力；一旦设为核心规则，格式差异会先于“无法计算”被记为疑似降智。能力检测应优先使用辅助规则和分数区间，让检测协议不兼容的结果进入“无法判定”。

SVG 数学检测默认关闭，只有管理员在对应平台的判定规则中单独开启后才会执行。它直接解析 SVG 坐标和声明式 `<animate>`、`<animateTransform>`，不会启动浏览器、执行生成内容中的脚本或保存截图。支持元素距离、上下左右关系、横纵对齐、保持在 `viewBox` 内、最小位移、最小旋转量和动画首尾距离。采样点限制为 2 至 24 个；复杂 `path` 或 `g` 可以使用 `data-anchor-x`、`data-anchor-y` 指定判定锚点，使用 `data-bbox="x y width height"` 指定本地包围盒。

数学阈值支持三种基准：“SVG 坐标绝对值”直接使用当前坐标单位；“viewBox 短边比例”以根 SVG 的 `viewBox` 宽高中较小的一项归一化；“参照元素半尺寸比例”沿用旧版按参照元素最大宽高一半归一化的方式。能力检测优先使用 `viewBox` 短边比例，它不依赖车轮内部使用圆形还是复杂路径绘制。

不支持的 SVG 特性按规则依赖范围隔离：其它部位合法的 `d` 路径动画不会再让脚踏距离、踏板位移或车轮旋转规则失效；只有规则直接依赖无法解析的路径形状、变换或包围盒时，该条规则才会记为“无法计算”。脚本和 CSS 动画可能影响整张场景，仍会使数学证据不可用。选择器不唯一、相关坐标不可解析，或超过 2 MB、10000 个 SVG 节点、50000 次几何操作的资源上限时也会安全返回“无法计算”，并通过分数区间决定最终状态。关闭开关时已配置的 SVG 数学规则不参与评分，其他规则保持原有行为。

分组综合状态使用当前题目配置下的有效检测确认。首次正常结果会建立正常状态，正常状态下默认最近 3 次中至少 2 次疑似降智才确认降智，确认降智后连续 2 次正常才恢复；“无法判定”和“检测异常”不参与确认。提示词、模型、协议、推理强度、输出上限或规则发生变化后，旧配置下的结果不会混入新配置的综合状态。每次检测都会保存当时的配置快照、得分和逐条规则结果。

### 能力评估边界

单个 SVG 题目不能科学地测量模型的通用“智商”，也不能证明模型身份或整体能力。它只能观察模型在固定提示词下的任务理解、空间关系推理、动画规划、代码生成和指令遵循表现。为了尽量减少评估失真，应遵守以下原则：

- 提示词只描述任务目标，不提前告诉模型脚应该如何运动、车轮应该如何运动等待测答案；
- 判定规则保存在服务端，不会随模型请求发送，用自然隐含的行为作为隐藏评分标准；
- 只保留低资源解析必需的元素标记和动画协议，并且不把这些技术标记当作降智能力证据；
- 不使用输出字节数、代码复杂度、固定构图或装饰数量作为模型能力代理；
- 比较不同分组时保持提示词、模型、推理强度、最大输出 Token、采样点和规则完全一致；
- 使用多次结果确认趋势，不用单次作品给模型整体能力下结论。

当前 SVG 数学检测不渲染画面，也不识别造型、美感、遮挡和动作自然度。`data-anchor-*` 等属性是模型声明的几何信息，只能作为低成本近似证据。若要评估开放式视觉质量，应使用不带解析协议的简短提示词，并由视觉模型或人工复核；这种开放式结果不能仅靠当前数学规则自动定性。

### 可选视觉审核

管理员在 `/admin/config` 的“平台默认检测配置”或分组独立配置中展开“视觉审核”，开启开关后保存。默认关闭，关闭时继续使用原有规则；普通用户只能查看结果，无法读取或修改审核 API、审核要求和凭据。无需新增 `.env` 配置，也不会在服务器启动浏览器、执行生成代码或截图。

提供两种协议，均发送完整 HTML 源码给审核服务，不直接调用只接受图片的 OpenAI 视觉模型 API。实际视觉分析、渲染和评分由外部服务负责，其内部算法和准确率需要单独验证。

满血 AI 的配置如下：

| 配置项 | 填写内容 |
| --- | --- |
| 输出类型 | HTML |
| 启用视觉审核 | 开启 |
| 审核协议 | 满血 AI / 异步任务 |
| 审核 API 地址 | `https://manxue.ai/api/v1/tests` |
| 审核专用 Key | 接口无鉴权时留空；需要鉴权时填写该审核服务自己的 Key |
| 检测基准 | `pelican` |
| 判定方式 | 以视觉审核为准 |
| 审核总超时 | `120` 秒，可配置 5 至 600 秒 |
| 轮询间隔 | `2` 秒，可配置 1 至 30 秒 |

后台按教程提交 `{"benchmark":"pelican","html":"完整作品源码"}`，收到任务 ID 后查询同一 API 地址下的 `/{id}`。`queued`、`pending`、`running` 继续等待；只有任务 ID 和 benchmark 匹配、状态为 `succeeded` 且 `assessment.quality` 为 `normal` 或 `degraded` 时才形成有效判定。两者分别映射为“正常”和“疑似降智”。独立 SVG 会添加最小 HTML 外壳，已有完整 HTML 保留原文，不重画或修补作品。

自建或其它兼容审核服务选择“兼容 HTML 审核 / 同步返回”，填写完整 HTTPS API 地址，可配置模型名称和审核要求。请求格式为：

```json
{
  "benchmark": "pelican",
  "html": "完整作品源码",
  "model": "可选的审核模型名称",
  "instructions": "可选的审核要求"
}
```

未填写的 `model` 和 `instructions` 不会发送。接口应同步返回 `{"assessment":{"quality":"normal"}}` 或 `{"quality":"degraded"}`；只有这两个质量枚举有效，不能用 HTTP 200、布尔值或未知值代表通过。如果返回 `status`，必须为 `succeeded`；如果返回 `benchmark`，必须与配置一致。

“以视觉审核为准”允许不配置本地题目规则；已有本地规则仍执行并保留逐条证据，但不决定最终状态。“共同判定”需要两个判定器都有正常结论才记正常；在审核完成且结论有效时，任一判为疑似降智则记疑似降智；视觉正常但本地无法判定时，综合为无法判定。审核失败、超时、未知结论、任务不匹配或不能送审时，无论本地评分多高均记“无法判定”，不计入有效降智率或确认/恢复次数。管理员仍可人工复核。结果页的折叠证据分别展示审核结论和本地规则评分，不把本地分数冒充视觉评分。

为兼容安全 HTML 审核，送审作品只能使用内联 HTML、SVG、CSS 和声明式动画；脚本、事件属性、外部资源、iframe、foreignObject、危险动画属性和不完整内容会停止送审并展示原因，不能因此判降智。原作品保留，仍可在现有隔离预览中查看。建议使用简短提示词：

```text
创建一个完整 HTML，使用内联 SVG 绘制一只鹈鹕骑自行车的二维循环动画。
只输出 HTML 源码，使用 SVG 原生动画或内联 CSS 动画，不使用 JavaScript 或外部资源。
```

采用“以视觉审核为准”时，不需要固定 ID、数学锚点或原来的六条数学规则；可关闭 SVG 数学检测，现有规则也可以保留作为辅助证据。比较不同分组时，保持提示词、生成模型参数、审核服务和基准一致。

审核 Key 使用现有凭据主密钥独立加密，绝不使用或转发分组生成 Key、当前用户 Key 或登录 Token。留空保留同一接口已保存的审核 Key，勾选“清除”可删除；更换协议或 API 地址后不会沿用旧 Key。分组独立配置可填写自己的审核 Key，也可在相同接口下继承平台审核 Key，保存后独立加密。历史快照不保存明文 Key 或凭据密文。更换审核配置后，旧配置结果不会混入当前综合状态。

所有审核地址必须是无查询参数、无内嵌凭据的 HTTPS 公网地址；后台校验 DNS 并固定连接 IP，禁止私网、回环、链路本地地址和重定向。响应最多 256 KB，作品最多 1 MB，整个提交和轮询共用总超时。提交只执行一次，不自动重发或重新生成作品；提供审核幂等标识，但不能保证第三方去重或免费。源码会发送给管理员指定的第三方，第三方留存不受本站历史清理控制，检测题不得包含秘密或个人资料。

### 分组独立配置

平台区域左侧的“平台默认检测配置”是该平台所有分组的继承模板。要让某个分组使用不同模型或题目，在右侧分组列表点击设置图标，编辑完整检测配置后点击“应用独立配置”，再点击页面顶部“保存配置”。分组行会显示“独立检测配置”；在同一弹窗点击“恢复平台默认”并保存即可取消覆盖。

独立配置包含模型、协议、提示词、输出类型、推理强度、最大输出 Token、MIME 类型、全部判定规则和视觉审核设置。自动检测、立即检测、结果页模型信息以及综合状态都使用该分组当前的有效配置。升级前的分组不会自动产生独立配置，因此行为保持不变并继续继承原平台配置。

管理员可在配置页的分组“历史”弹窗中对已产生判定的记录进行人工复核，将最终状态设为“正常”“疑似降智”或“无法判定”，并必须填写复核理由。人工状态会参与降智率和综合判定，但不会覆盖数据库中的自动状态、自动评分或规则证据；撤销复核即可恢复自动结论。排队中、检测中和请求异常记录不能人工改写。复核接口仍要求管理员身份、CSRF 令牌和当前分组管理权限，普通结果页只读展示复核结论及原自动状态。

### 长期运行与历史保留

管理员在 `/admin/config` 展开“历史保留与维护”，调整保留策略后点击“保存配置”。这些设置存放在数据库中，不增加 `.env` 配置项；普通用户不能访问或修改。升级后默认启用以下策略：

| 项目 | 默认值 | 范围 |
| --- | --- | --- |
| 详细历史保留天数 | 90 天 | 1 至 3650 天 |
| 每组详细历史上限 | 2000 条 | 60 至 10000 条 |
| 每组作品保留数量 | 60 份 | 60 至 2000 份，不能超过详细历史上限 |

超过天数或条数上限的旧记录会分批清理，但每组最近 60 条记录、排队和检测中的任务始终受保护。关闭“自动清理详细历史”后，详细历史继续累积；作品过期清理、残留文件清扫和数据库维护仍运行。低频分组的最近 60 条可能超过配置天数，这是为了保留结果页可见区域的完整历史。

自动清理前会将累计检测次数、正常次数、有效判定次数和当前配置的综合判定状态汇总到每组一条记录中，因此累计降智率不会因清理而重置，当前配置的确认和恢复过程也会保留。已清理的记录不能查看作品、逐条证据或人工复核；更换检测配置后，旧配置的归档判定状态不会参与新配置确认。管理员勾选删除仅移除所选详细记录；“清空历史”同时清空该组保留的详细记录、累计统计和归档判定状态，活动任务仍然保留。

结果页展示最近 60 条实际记录；累计次数包含自动清理前的记录，超过可见窗口时显示 `LATEST 60 OF N RESULTS`。管理员历史弹窗分别标注详细记录数和仅保留累计统计的数量。

后台维护在服务启动后执行，通常每小时运行一轮。每批最多处理 20 个分组，每组最多归档 200 条详细记录或清理 200 条过期作品；积压任务每分钟继续，分组之间让出事件循环。作品清理同时覆盖保存在 SQLite 中的 HTML、文本和附件目录中的图片、文件。残留文件分批扫描，每批最多 500 个，只有至少一小时未修改且没有任何记录引用的普通文件才会移除；不会递归进入子目录或跟随符号链接。删除失败的残留文件会在后续巡检重试，维护不发起模型请求。

结果摘要使用最多 128 个分组的内存缓存；检测、人工复核、删除、作品过期或配置变更后立即失效。列表与管理员历史查询仅读取摘要字段，作品正文在查看单条结果时加载。综合判定逐条迭代状态，避免一次把全部历史加载到内存。

没有检测任务时进行 SQLite 检查点维护。空闲页达到 8 MB 后，每天最多执行一次空间回收；新数据库使用增量回收，每次最多回收 2048 页，未回收的空闲页可供后续写入复用。旧数据库首次满足回收条件时会在空闲期执行一次 `VACUUM` 并转换为增量回收，期间可能有短暂页面响应延迟和额外磁盘 I/O，需要可用空间完成数据库重建。配置页显示最近维护时间与本批清理数量。Docker 日志默认按每文件 10 MB、最多 3 个文件轮转。

拉取新镜像会更新服务代码，但不会更新服务器上的 Compose 文件；日志轮转设置需同步本服务的 `compose.yaml`，再重建容器才会生效，无需删除数据卷。

默认策略限制固定分组和输出大小下的历史增长，但不会使磁盘、CPU 或内存消耗为零；保留数量、单份作品大小、启用分组数以及访问量仍然决定实际占用。原有数据卷应继续保留，数据库迁移自动执行。

### 鹈鹕自行车结构检查示例

下面是新安装时 OpenAI 平台自动带出的结构连通性模板，用于确认模型能够返回完整 HTML、SVG 和动画代码。它包含固定命名、最小字节数和指定 CSS 实现，因此适合接口与结构检查，不应单独用于推断模型的通用能力。

在管理页进入目标平台的“检测题配置”，将输出类型设为 `HTML`，提示词填写：

```text
创建一个完整、可直接在浏览器打开的 HTML 文件，使用内联 SVG 绘制一只鹈鹕骑自行车的二维循环动画。
只输出 HTML 源码，不要使用 Markdown 代码块，不要解释。
SVG 必须设置 viewBox；鹈鹕主体使用 id="pelican"，自行车主体使用 id="bicycle"，两个车轮使用 class="wheel"。
至少使用一组 CSS @keyframes，让鹈鹕、自行车或车轮产生持续循环动画。
所有 HTML、CSS 和 SVG 必须内联，不得引用任何外部脚本、图片、字体或网络资源。
```

设置正常分数线 `90`、降智分数线 `60`、观察最近次数 `3`、确认降智次数 `2`、恢复连续正常次数 `2`，然后按顺序添加以下规则：

| 规则名称 | 类型 | 级别 | 权重 | 配置值 |
|---|---|---|---:|---|
| HTML 内容完整度 | 最小字节数 | 辅助 | 10 | `4000` |
| 完整 HTML 文档 | HTML 选择器 | 核心 | 10 | 选择器 `html`，最少 `1` |
| 带 viewBox 的 SVG 场景 | HTML 选择器 | 核心 | 15 | 选择器 `svg[viewBox]`，最少 `1` |
| 鹈鹕主体 | HTML 选择器 | 核心 | 20 | 选择器 `#pelican`，最少 `1` |
| 自行车主体 | HTML 选择器 | 核心 | 20 | 选择器 `#bicycle`，最少 `1` |
| 两个自行车车轮 | HTML 选择器 | 核心 | 10 | 选择器 `.wheel`，最少 `2` |
| 定义 CSS 关键帧 | 包含文本 | 核心 | 7 | `@keyframes` |
| 应用 CSS 动画 | 匹配正则 | 核心 | 8 | `animation(?:-name)?\s*:` |
| 不引用外部资源 | HTML 选择器 | 核心 | 10 | 选择器 `[src^="http"], [href^="http"], [src^="//"], [href^="//"]`，最少 `0`、最多 `0` |

新安装且尚未保存 OpenAI 平台配置时会自动带出这一模板；已有平台配置不会被升级过程覆盖，需要在管理页手动调整后保存。

### 鹈鹕自行车能力优先 SVG 数学检测

需要在不使用视觉模型的前提下比较空间推理和动画实现能力时，应新建或覆盖当前分组的完整检测配置，并清空原有全部规则。不要继承上面的最小字节数、固定结构、CSS 关键帧或核心选择器规则。

OpenAI 分组的基础配置使用：请求协议 `OpenAI Responses`、输出类型 `HTML`、推理强度 `Max`、最大输出 Token `16384`，文件 MIME 类型留空。对比其它分组时可以使用其支持的协议和推理强度，但同一轮横向比较必须保持模型、推理强度、输出上限和规则一致。

提示词填写：

```text
创建一个完整、可直接在浏览器打开的 HTML 文件，使用单个内联 SVG 绘制一只鹈鹕骑自行车的二维循环动画。
请自行决定构图、造型、部件关系、动作和动画细节。只输出 HTML 源码，不得引用外部资源。

为兼容低资源自动检测，动画使用 SVG animate 或 animateTransform，不使用 JavaScript、CSS animation、CSS transform、animateMotion、set 或 foreignObject。
请为画面中实际可见且参与动画的前轮、后轮、左脚、右脚、左踏板、右踏板分别设置唯一 ID：front-wheel、rear-wheel、left-foot、right-foot、left-pedal、right-pedal。将 ID 设置在能够代表对应部件整体运动的元素或分组上；脚和踏板使用 data-anchor-x、data-anchor-y 标记各自用于几何计算的代表点。
```

提示词没有告诉模型脚踏关系、踏板运动方式或车轮运动方式，这些待测行为只存在于服务端规则中。固定 ID、锚点和声明式动画是当前静态解析器所需的最小协议，不作为独立得分项。

在“判定规则”中开启“SVG 数学检测”，设置动画采样点 `12`、关系通过比例 `90%`，并添加以下全部规则。所有规则都必须选择“辅助规则”，权重合计 `100`。已有旧配置需要删除四条规则中的 `#front-wheel` 尺寸参照，并按表格改用 `viewBox 短边比例`：

| 规则名称 | 数学关系 | 级别 | 权重 | 源元素 | 目标元素 | 阈值基准 | 尺寸参照 | 阈值 |
|---|---|---|---:|---|---|---|---|---:|
| 左脚与左踏板保持接近 | 距离不超过阈值 | 辅助 | 20 | `#left-foot` | `#left-pedal` | viewBox 短边比例 | 留空 | `0.01` |
| 右脚与右踏板保持接近 | 距离不超过阈值 | 辅助 | 20 | `#right-foot` | `#right-pedal` | viewBox 短边比例 | 留空 | `0.01` |
| 左踏板产生有效位移 | 位移不少于阈值 | 辅助 | 10 | `#left-pedal` | 留空 | viewBox 短边比例 | 留空 | `0.05` |
| 右踏板产生有效位移 | 位移不少于阈值 | 辅助 | 10 | `#right-pedal` | 留空 | viewBox 短边比例 | 留空 | `0.05` |
| 前轮产生有效旋转 | 旋转不少于阈值 | 辅助 | 20 | `#front-wheel` | 留空 | SVG 坐标绝对值 | 留空 | `300` |
| 后轮产生有效旋转 | 旋转不少于阈值 | 辅助 | 20 | `#rear-wheel` | 留空 | SVG 坐标绝对值 | 留空 | `300` |

设置正常分数线 `90`、降智分数线 `60`、观察最近次数 `3`、确认降智次数 `2`、恢复连续正常次数 `2`。在全部规则都可计算时，该权重设计允许一个权重为 `10` 的次要动作失败后仍为正常；单个权重为 `20` 的主要关系失败会进入无法判定；累计失败权重达到 `40` 时才会进入疑似降智，并仍需最近 3 次中出现 2 次才确认综合状态。若一条权重为 `10` 的辅助规则无法计算，分数区间为 `90` 至 `100`，最低分已达到正常线；若一条权重为 `20` 的辅助规则无法计算，分数区间为 `80` 至 `100`，结果保持无法判定。

不要为这些 ID 额外添加核心 HTML 选择器规则。ID、锚点、坐标或相关动画协议无法解析时，受影响的数学规则会返回“无法计算”，再按最低分、最高分和可计算覆盖率判定，避免检测协议差异被误报为疑似降智。

能力优先配置有意移除了以下项目：最小输出字节数与代码复杂度不代表能力；车轮中心同高属于特定构图而非骑车动画的必要条件；“鹈鹕位于自行车上方”和 `data-bbox` 依赖模型自报的近似包围盒；静止元素也能通过首尾位置接近，因此该规则不能证明动画循环。造型是否像鹈鹕、骑行动作是否自然以及画面是否美观，继续由结果预览和人工复核判断，不计入低资源自动分数。

例如 `viewBox="0 0 1000 720"` 的短边为 `720`：接近阈值 `0.01` 表示允许距离不超过 `7.2` 个 SVG 单位，位移阈值 `0.05` 表示要求最大位移不少于 `36` 个 SVG 单位。旋转规则的阈值固定使用角度。旧版“参照元素半尺寸比例”仍然兼容，但复杂分组可能包含静态或动态路径，不建议再用整个车轮分组作为尺寸参照。

OpenAI Responses 检测使用 SSE 流式请求，并且只有收到 `response.completed` 后才会保存和展示答案；`response.incomplete`、`response.failed` 或没有完成标记的断流不会把残缺 HTML 当成有效结果。该方式已通过 Sub2API 公网入口实测，原本约 125 秒触发 `HTTP 524` 的完整 HTML 请求可以在同一次推理中持续接收事件并最终得到完整文档。

只有能够确认请求尚未送达的建连失败，或明确返回的 HTTP 429、503，才会在单次检测总时间预算内按 `1、2、4、8、16` 秒退避并最多自动重试 5 次。收到成功 HTTP 响应头、`response.created` 或其它模型事件后，连接中断都不会重新提交推理；请求是否送达无法确认时同样停止重提，避免同一次任务重复计费。当前 Sub2API 对后台 Responses 和 `GET /v1/responses/{id}` 的实测结果分别为 `400` 和 `404`，因此服务不会假装可以恢复服务端任务；流式 `HTTP 524` 也不会盲目重试。鉴权、配置和响应格式错误同样不会重试。

取消选择分组并保存后，该分组会停止调度，其专用 Key 会被清除，历史轻量判定和独立检测配置继续保留；重新启用时需要重新填写专用 Key。手动检测不会改变自动计划中的下一次执行时间。

## 专用 Key

每个目标分组应使用独立服务账号创建一个专用 Key。Sub2API Key 与分组绑定，不同分组不能复用同一个 Key。

Key 提交后使用 AES-256-GCM 加密写入 SQLite，并绑定对应分组 ID；加密主密钥首次启动时随机生成在数据目录的 `.credential-key` 文件中，文件权限会收紧为仅服务进程可读写。浏览器只会收到“已配置/未配置”，后端不会回显、记录日志或把明文 Key 写入数据库。

备份时必须同时保护数据库和 `.credential-key`。丢失 `.credential-key` 后已有 Key 无法解密，服务会停止对应检测并要求管理员重新配置；仅泄漏数据库文件不会直接得到明文 Key。

## 部署

```bash
docker compose --env-file compose.services.env --profile degradation-detector up -d degradation-detector
```

服务固定映射到 `127.0.0.1:9873`。通过 HTTPS 反向代理后，在 Sub2API 自定义菜单中分别配置两个入口。

普通用户模块：

```text
标签：降智检测结果
URL：https://detector.example.com/results?token={token}&theme={theme}
可见角色：全部已登录用户
```

管理员模块：

```text
标签：降智检测管理
URL：https://detector.example.com/admin/config?token={token}&theme={theme}
可见角色：仅管理员
```

两个入口都兼容 `token` 与 `access_token` 参数名，并在换取本地短期会话后立即从地址栏移除上游 Token。管理入口会先在服务端验证 Token 对应用户确实仍为管理员，再创建本地会话和返回页面。生产环境使用 Secure 和 Partitioned Cookie；反向代理必须保留 HTTPS 协议信息。

首次部署时结果页为空是正常状态。管理员从独立管理入口保存至少一个平台、分组及其专用 Key 后，该分组才会出现在只读结果页并进入自动调度。

当前会话、SQLite 写入和调度器按单实例设计，请只运行一个服务副本。数据卷 `sub2api-extra_degradation-detector-data` 必须持久化。
