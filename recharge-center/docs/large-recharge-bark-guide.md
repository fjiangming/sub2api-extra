# 大额充值 Bark 提醒配置手册

此功能只在充值中心的管理员“到账审核”页面配置，适用于 `personal_manual`、`personal_transfer_auto` 和 `personal_accountlog_static`。普通用户不可见，也不能调用对应接口。它参考供应商监控的 Bark 推送协议，在充值中心独立实现，不共享其他服务的数据库、密钥或通知配置。

## 1. 从 iPhone 获取 Device Key

1. 在 iPhone App Store 安装 Bark，打开应用并允许系统通知。
2. 使用 Bark 默认官方服务器，查看应用首页提供的推送地址。格式通常为 `https://api.day.app/<DeviceKey>/推送内容`。
3. 只复制 `api.day.app/` 后、下一个 `/` 前的那一段作为 Device Key。不要粘贴整个 URL、示例消息、括号或斜杠。应用版本若直接显示 Device Key，可直接复制该值。
4. 此 Key 是推送凭据，持有者可以向该设备发送提醒。不要放入公共截图、Git、聊天记录或普通日志。本功能固定使用官方 `https://api.day.app/push`，不支持自建 Bark 服务器地址。

Bark 只用于通知，不需要申请支付宝产品，也不会取得付款判断权。

## 2. 在到账审核页设置

1. 以 Sub2API 管理员进入充值中心，打开“到账审核”。
2. 在“大额充值提醒”填写金额阈值和 Device Key，先保持“启用提醒”关闭并保存。
3. 点击“测试提醒”，确认 iPhone 收到“充值中心 Bark 测试”。修改尚未保存时，测试按钮不可用。
4. 打开“启用提醒”，再次保存。后续符合条件的成功充值将自动入队发送，无需值守或额外监听设备。

| 页面项目 | 作用及填写方式 |
| --- | --- |
| 启用提醒 | 默认关闭；打开后只检查此后完成入账的订单。创建订单时关闭、完成时已开启，也会按完成时配置检查。 |
| 单笔充值大于（元） | 默认 `1000.00`，支持 `0.01` 至 `1000000.00`，最多两位小数。按人民币实际支付金额判断，严格大于，不是大于等于，也不是每日累计。 |
| Bark Device Key | 上一步取得的设备 Key，使用字母、数字、下划线或连字符，共 6–256 位。首次必须填写；保存后不回显，留空会保留已有 Key。填写新 Key 将替换旧值。 |
| 清除已保存的 Device Key | 先关闭提醒，再勾选并保存。不能在启用状态清空，也不能同时填写新 Key 并清除。 |
| 保存 | 保存开关、阈值和 Key；普通刷新、切换页面不会保存未提交的改动。 |
| 测试提醒 | 只向已保存的 Key 发一条固定测试消息，即使开关关闭也可测试；不会创建订单或改余额。每来源 IP 15 分钟最多 5 次。 |
| 最近提醒 | 显示最近一笔大额提醒的等待、发送中、已发送或失败状态；点击审核页刷新按钮重新读取。没有历史提醒时显示 Key 配置状态。 |

固定参数无需填写：地址 `https://api.day.app/push`，通知级别 `timeSensitive`（时效性通知），分组 `Sub2API 充值中心`。能否显示锁屏、横幅和声音，还取决于 iOS 对 Bark 的通知、专注模式及时效性通知权限；不使用“重要警报”或连续响铃。

## 3. 哪些充值会提醒

只有既有收款核验成功、Sub2API 兑换结果核验通过并完成入账的个人模式订单才触发。提醒以本单实际支付金额为准，个人模式与到账额度固定为 1:1。

| 阈值 | 单笔实付金额 | 结果 |
| --- | --- | --- |
| 800.00 | 799.99 | 不提醒 |
| 800.00 | 800.00 | 不提醒 |
| 800.00 | 800.01 | 充值完成后提醒 |

发生同额冲突而分配了额外分角时，以最终应付且已核验的实付金额判断。例如目标 `800.00`，本单实付 `800.01`，超过 `800.00` 阈值会提醒。

未付款、取消、过期但未入账、待核验、履约结果不确定以及异常支付宝流水均不发送“大额充值提醒”；异常继续走原邮件 / Webhook。普通支付宝支出不属于充值。人工核验或恢复后确实完成入账的订单，同样可以触发。Sub2API 原生充值入口、官方支付模式及历史完成订单不在本功能监听范围。

通知包含金额、触发时阈值、订单号、下单用户 ID、完整下单邮箱及北京时间付款时间；老订单没有完整邮箱时明确提示未记录。这里的下单账号不等同于已核验的支付宝付款人。正文会经 Bark 官方服务及 Apple 推送传输，可在 iOS“设置 → 通知 → Bark → 显示预览”调整锁屏可见范围。

## 4. 持久化与失败处理

- 不增加必填环境变量，不需要另起通知容器。升级时只更新充值中心，保留原数据卷及 `RECHARGE_CENTER_SECRET`。启动自动执行版本 12 增量迁移，Key 以 AES-256-GCM 密文保存于原账本。
- 与订单完成一起持久化提醒任务，后台每 5 秒处理一次；不会等待 Bark 返回才宣布付款成功。阈值记录为该任务触发时的值，不随后续修改改写；实际投递使用当时最新保存的 Device Key。
- 同一订单唯一入队；重复流水、重复确认或刷新不会新增任务。网络 / 超时、HTTP 429 / 5xx 或 Bark 临时错误最多尝试 3 次，首次失败后至少等待 15 秒，第二次失败后至少等待 30 秒；永久拒绝不重试。
- 服务重启保留待发队列，过期发送租约会恢复；关闭开关会取消待发通知，不影响订单或余额。已经发送的请求不能保证撤回，达到失败上限的通知不会因重新开启自动补发。
- 网络超时或退出发生在 Bark 已接受消息后时，重试可能出现重复手机通知；推送成功也不保证手机当时已联网或显示提醒。通知状态不能作为补款依据，充值仍以订单与 Sub2API 兑换记录为准。

## 5. 常见问题

| 现象 / 错误代码 | 检查方式 |
| --- | --- |
| 看不到配置 | 确认使用 Sub2API 管理员身份和个人码模式；普通用户与官方支付模式不显示到账审核。 |
| `LARGE_RECHARGE_BARK_CONFIG_INVALID` | 检查金额范围、两位小数、Key 是否只有允许字符；启用前先保存有效 Key，清除前关闭开关。 |
| `LARGE_RECHARGE_BARK_NOT_CONFIGURED` | 尚未保存 Device Key，先填写并保存再测试。 |
| `LARGE_RECHARGE_BARK_FAILED` | Bark 未确认成功或连接失败；在 iPhone 核对默认官方服务器及 Key，检查服务器能否访问 `api.day.app:443`。错误不显示原始响应，以免泄露 Key。 |
| `LARGE_RECHARGE_BARK_TIMEOUT` | 超过发送期限，默认 5 秒，沿用 `RECHARGE_CENTER_ALERT_TIMEOUT_MS`；检查服务器 DNS、出站 HTTPS 和网络。测试不会自动重试，订单通知按队列有限重试。 |
| `ALERT_RESPONSE_TOO_LARGE` | Bark 响应超过 64 KiB，已拒绝；检查是否存在异常代理或网络返回，不按成功处理。 |
| `BARK_TEST_RATE_LIMITED` | 测试过于频繁，等待该 15 分钟窗口结束。Nginx 开启受信代理时仍使用现有客户端 IP 策略。 |
| `ALERT_DISABLED` | 关闭提醒后尚未发送的任务已取消。 |
| `BARK_DELIVERY_INTERRUPTED` | 上次发送中断；未到 3 次的任务会在服务恢复且启用时继续尝试。 |
| 页面显示已发送但手机没弹窗 | 已发送只代表 Bark 接口确认。检查 iPhone 网络、Bark 通知权限、专注模式、时效性通知和锁屏预览。 |

提醒失败不会撤销充值、重复发额度或阻止后续正常付款。保留原账本与审计，根据订单号核对；不要根据推送是否到达手工修改用户余额。
