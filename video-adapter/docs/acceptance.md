# 验证与上线验收

本地开发验证使用隔离的 PGlite PostgreSQL 引擎和禁止外部连接的 HTTP Mock。不会使用生产数据库、真实供应商 Key 或付费生成接口。演示模式只绑定回环地址。

## 自动验证

运行 `npm ci`、`npm run check` 和 `npm test`。测试覆盖：

| 范围 | 核心断言 |
|---|---|
| 入场计价 | 按条/按秒、30 秒全量计价、分辨率、分组/渠道优先级、用户/视频/高峰倍率 |
| 利润 | 人民币汇率、额外费用、成本卡过期、充值折扣、毛利、安全缓冲、成本预算 |
| 资金 | 创建前冻结、余额/额度并发保护、重放不重复冻结、拒绝操作完整回滚 |
| 原生策略 | Key 权限、订阅拒绝、平台配额拒绝、全局/分组 RPM 与原生 Redis Key 共享 |
| 故障 | 创建回执丢失、原凭证与原始字节重试、不支持幂等时不重试、租约丢失、停用供应商 |
| 结算 | 不依赖客户轮询、不会重复扣费、失败未退款保留资金、确认退款只退一次 |
| 安全 | 凭证加密、任务归属、IP ACL、SSRF、下载重定向不带凭证 |
| 下载 | HEAD、额度包含失败请求、拒绝无效内容并取消上游流 |
| 生命周期 | 缓存失效积压不发单、缓存失败保留队列、停机等待领取、端口占用清理资源 |

这些验证不代表已经完成真实 PostgreSQL/Redis 跨进程验证或付费供应商验收。生产容器使用 PostgreSQL 驱动，不使用 PGlite。Docker Compose 配置校验不等同于镜像构建和容器启动成功。

## 单供应商验收

1. 使用生产数据库副本和独立 Key，先保持所有供应商/型号关闭。确认 schema 校验成功，原站服务正常，最小权限账号能完成冻结和缓存失效。
2. 在 sub2api 设置专用视频分组、明确售卖价和白名单，使用停用调度的日志归属账号。保留用户原有额度与限流策略；不允许为了验收绕过保护。
3. 核实型号规格、费用是否随素材/时长/分辨率变化、报价单位、实际扣款、失败退款、文件保留期、幂等及速率限制。成本卡覆盖最坏费用和汇率，填写证据与有效期；支持幂等时还要填供应商承诺的最短 `idempotencyRetentionSeconds`。
4. 计算充值后的最坏收入实现系数，设置运营成本、毛利和单笔/每日预算。低于成本的倍率应能明确拒绝，且供应商后台没有新任务或扣款。
5. 只启用一款模型，以最低允许规格生成一次。客户创建后停止查询，仍应看到后台结算、原生用量与供应商单据一致。
6. 重复相同 Key、幂等键和原始字节，确认只有一个任务和一笔扣款；改字节应返回冲突。断网恢复时检查原任务，不能换幂等键补单。
7. 核实失败任务的资金回执。无明确退款证据应进入核查；明确释放/全额退款应返还客户余额和额度，并保留审计。
8. 验证下载凭证、跨用户隔离、Range 和下载额度，确保运营成本覆盖允许的带宽。检查所有原生视频路径都经过适配服务，管理路径不暴露公网。

XCM 文档未提供统一可靠的资金状态和创建幂等承诺，因此样例采用 `manual`，成功任务也需要核实上游账单后结算。只有取得可执行的成本上限合同后，才可启用 `bounded_success`；此模式自动结算时记录保守成本上限。灵速采用 `funds_status`，也仍需真实小单确认字段和实际资金行为。

## 持续运维

每天处理 `review`、供应商熔断、缓存积压和退款审计。已完成资金状态型任务只自动审计七天；更晚的退款按供应商账单另行处理。保留数据库、成本卡和加密密钥备份，未处理完冻结任务前不能移除模块或删除原站身份。

适配服务会按核实的成本合同拒绝无利润、无资金或无法确定价格的新增任务。供应商违规涨价、合同外扣费、错误现金折算或管理员直接改余额属于外部财务风险，不能靠协议适配承诺绝对消除。
