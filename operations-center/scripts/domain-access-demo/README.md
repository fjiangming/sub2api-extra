# 域名访问交互 Demo

仅用于确认运营中心新模块的布局、字段与交互。正式功能尚未开发，不修改 Sub2API 源码，不连接生产数据，不启用服务器日志采集，不发送通知。

## 启动

在 `operations-center` 目录执行：

```powershell
node scripts/domain-access-preview.cjs
```

默认地址为 `http://127.0.0.1:19898/`，端口被占用时自动尝试后续端口，实际地址以终端输出为准。仅监听 loopback，复用已安装的 Express、Lucide 和 ECharts，不新增依赖。可使用 `DOMAIN_ACCESS_PREVIEW_PORT` 指定其他端口。

## 预览范围

- 用户列表：两个关注域名、日期及快捷时段、用户 / 邮箱 / Key 搜索、使用与通知状态筛选、排序、分页、跨页选择、CSV 导出。
- 用户详情：保留记录中的首次 / 最后访问、新旧域名请求、Key 分布、单次请求、唯一身份关联链及通知记录。
- 访问明细：已确认、等待关联、身份冲突及匿名访问，HTTP 与流式状态分别显示，同次上游多次尝试仅计一个入口请求。
- 历史线索：Host 与 Referer 分别展示，不能确认的记录不进入用户通知名单；管理员订单不推断普通用户身份。
- 通知草稿：选择已确认用户、编辑及纯文本预览、本机保存、再次编辑、删除、模拟标记已通知。所有行为均不发送消息。
- 采集状态：正常、中断、未配置场景，覆盖缺口与保留设置；尚未配置时不显示旧数据为已确认访问。
- 响应式：保留既有运营中心导航、颜色、Lucide 图标与控件，手机用户行直接显示状态和次数，详情使用可关闭抽屉；支持深色模式与键盘操作。

固定观察时点为北京时间 `2026-11-13 15:00`，生成 24 个虚构用户、6,025 条入口请求和 5 条历史样例。邮箱全部使用 `example.com`，来源 IP 使用文档保留网段，无真实用户、API Key 或正文。

筛选期间的请求数与迁移观察状态按所选日期计算；累计确认用户、首次和最后访问按模拟采集以来的保留记录计算。“近期仅见新域名”不保证所有设备均已迁移。

草稿、通知状态和模拟保留设置仅写入浏览器的 `sub2api-domain-access-demo-v1` 存储项，可在“采集状态”重置。演示场景与筛选在刷新后恢复默认。预览服务器只提供明确的静态资源，没有 API 路由；页面 CSP 禁止业务网络请求、外部脚本及表单导航。

## 浏览器验收

使用已有 Playwright 与 Chromium；环境中没有默认浏览器时，分别通过 `PLAYWRIGHT_MODULE_PATH` 和 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定已安装路径：

```powershell
node scripts/domain-access-browser-check.cjs
```

检查脚本启动并关闭独立随机端口预览，覆盖 1440 / 1920 / 1024 / 390 / 320 像素及深色模式；验证筛选与空状态、分页选择、身份证据、未知身份隔离、草稿保存 / 刷新 / 通知状态、CSV、采集中断与未配置、日期校验、布局和图表像素。截图和导出文件保存在系统临时目录，不读取业务数据库。

正式接入方案见 [`docs/domain-access-audit-plan.md`](../../docs/domain-access-audit-plan.md)。本目录未被正式服务引用，也不在运营中心 Dockerfile 的复制范围内。
