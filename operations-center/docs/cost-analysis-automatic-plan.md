# 成本分析自动统计与简洁现金收支方案

状态：已在现有运营中心实现消费毛利、简洁现金收支及累计净结余。2026-11-02 用户进一步确认现金统一按人民币原数值计算，本文件同步该口径；原交互 demo 的分币种 / 汇率演示不再代表当前现金规则，实际操作与兼容边界见[成本分析操作与统计口径](cost-accounting.md)。

## 目标与范围

成本分析打开即可查看自动消费统计，不再填写期初、分类旧账、核验每笔额度的实收、关联凭证或维护费用分摊。根据用户补充，保留原有简单收支记录和现金流统计：只记录实际收付事实，系统自动汇总，不恢复精细核算流程。默认资金时区当月一日至今天、趋势按日；保留日 / 周 / 月 / 年统计、自定义日期、用户搜索分页、兑换明细与供应商日消费下钻。

采用已确认的消费口径：消费毛利 = 主站实际消费 - 启用供应商实际消费。充值额度、线上支付实收和当前余额分别表示不同事实，不能与消费毛利相加减。既有运营中心、供应商监控及只读主站连接继续使用，不增加独立财务服务。

前一轮已制作方案和示例 demo；本轮按用户确认实施正式应用，保留主站只读边界和历史数据，不自动提交 / 推送或部署。

## 移除与替代

| 现有内容 | 新方案 |
| --- | --- |
| 精细核算、确认收入、经营利润视图 | 移除；统一展示消费毛利，不再按付费余额池确认收入 |
| 用户期初、待确认实收价值、核算起点 | 移除；消费统计直接按所选日期读取，不需要人工补历史起点 |
| 旧记录逐笔分类、赠送 / 纠错 / 测试审批 | 移除；自动展示原始额度变动，不据此推断现金收入 |
| 逐笔实收核验、付款确认、凭证关联 | 移除；现金账只记实际收付，不要求核验额度池或分摊 |
| 订阅服务期间确认、每日收入分摊 | 移除；订阅的主站用量计入消费，支付售价只在原订单中展示 |
| 运营费用归属期间、年费 / 月费分摊 | 移除；服务器、域名等费用在实际付款日记一次现金支出，不按月摊销 |
| 手工退款核算、原单关联和额度池冲减 | 移除；保留原系统已记录的负向额度和退款事实，各自按原单位展示 |
| 记一笔、新增收入 / 支出 | 默认供应商付款；支出只选供应商并填人民币金额、实际日期，系统命名；收入保留项目名称，不再选择币种 |
| 待核验清单、期初核对、分类待办 | 移除；改为简短的同步状态与只读缺失原因，后台自动重试 |
| 当前用户余额扣减本期利润 | 移除；用户余额与上游余额独立展示 |
| 原手工收入、供应商支出、自定义费用 | 按原 ID、收支方向、金额原数值和发生日期延续为人民币现金账，原始币种留档；不重复导入或计入消费毛利 |

范围仅限成本分析。计费核查、CSV 补记、原收款与入账模块及主站资金契约不在本次删改范围内。

## 页面结构

主页面仅保留“消费毛利”和“现金收支”两个视图，共用日期与粒度，默认消费毛利；现金收支统一人民币，无币种筛选。查询与刷新为可选查看操作，不是生成统计的必需步骤。

1. 四个核心指标：主站消费、供应商消费、消费毛利、消费毛利率。点击可以下钻所选范围的每日来源。
2. 一行辅助数据：本期充值额度、当前用户余额、当前上游余额；各自可打开只读明细。余额注明快照时间，不随筛选伪装成历史期末。
3. 消费与毛利趋势：三条同源序列，支持日 / 周 / 月 / 年合并；无成本日期断线，不用插值推断缺失金额。
4. 明细区：每日明细与供应商汇总两个查看标签，切换不改变筛选或指标口径。每日明细固定按日，15 条分页；供应商汇总保留原账号范围和缺失日期。
5. 页面底部：默认折叠的统计范围与数据来源；历史手工记录在现金收支中延续，原记录快照可只读查看。

现金收支视图依次展示收入、支出、净现金流、累计净结余四个指标，桌面将累计净结余放在净现金流右侧，手机按两列排列。前三项展示所选期间，累计净结余固定展示全历史。下方为现金趋势、收支记录列表和“记一笔”入口；列表支持收入 / 支出、来源、搜索和分页。点击前三张卡片筛选相应记录，点击累计卡片查看独立的全历史组成，点击记录详情查看原记录。供应商汇总也可直接发起该供应商的支出记录。不增加“确认”“分类”“补期初”“保存核算”“重算审批”等按钮。自动刷新、失败重试和归档在后台执行。

## 现金收支

净现金流 = 本期现金收入 - 本期现金支出。按实际收付款日期统计，不扣用户余额，不计上游未消耗余额，不与消费毛利相加。供应商充值是付款日的现金支出，上游实际消耗是消费毛利的成本，两者分属两个视图，不能重复扣除。

累计净结余 = 全历史累计入账 - 全历史累计支出 - 当前用户余额。该卡片统一人民币，截至当前时刻；不受日期、日 / 周 / 月 / 年粒度、列表搜索 / 收支 / 来源影响。当前用户余额继续采用现有口径：排除 ID 1 管理员及已删除用户，只读当前余额，不直接扣改余额。修改所选月份不会把历史余额重复扣入本月经营结果；累计净结余与本期净现金流、消费毛利分别展示，也不称作经营净利润。

累计入账与支出复用同一防重现金来源，包含历史保留的线上实收和手工账；历史用户删除不移除已发生收付。全历史统计从完整保存的收支来源聚合，独立于前端所选时间范围，不能只累加当前页或所选月份。记录新增、修改、删除以及余额快照更新后自动刷新累计值。点击卡片展示累计入账、累计支出、当前余额、结果及快照时间，长篇口径默认收起。

现金采用用户确认的人民币原数值约定：历史 100 USD 计为人民币 100 元，其他币种及缺币种也按原数值计人民币；旧现金汇率和 FINANCE_CASH_EXCHANGE_RATES 不再用于现金计算，无需修改配置。原始币种 / 审计保留，不批量重写历史；供应商实际消费的倍率和监控汇率仍按原规则使用。历史收支尚未同步完整、实际退款金额缺失或当前余额读取失败时，累计净结余保留未知；缺币种 / 旧现金汇率不再阻断统计。

| 项目 | 来源与处理 |
| --- | --- |
| 自动现金收入 | 主站有真实付款证据的支付订单，按唯一订单 ID、`pay_amount` 原数值、`paid_at` 计人民币；包括余额充值与订阅已付款，排除 ID 1；取消 / 未支付订单不计 |
| 线下 / 其他收入 | 管理员实际收到款后记一笔；不需要补期初或核验每条兑换，支持可选备注和来源单号 |
| 供应商支出 | 选择监控目录中的供应商，填写实际付款人民币金额、日期；供应商停用不影响已经发生的付款，供应商目录缺失时仍可记自定义支出 |
| 自定义支出 | 自定义项目，如服务器、域名、短信、推广、人工，按实际付款日期和金额统计 |
| 实际现金退款 | 上游接口确有实际退现金额、退款时间和唯一退款事件时自动记支出；只有退额度或估算比例时不推算退现金额，有实际退款可记简单支出 |
| 旧收支账 | 复用原收入 / 供应商支出 / 自定义支出记录，不复制成新金额；已存在的明确非现金标记和来源关联沿用，不再要求逐条分类 |

`redeem_codes.value` 是额度，管理员加余额也可能是赠送、纠错，不能自动当现金；线上支付及其兑换只认支付一次。兑换额度继续在消费页独立展示并支持下钻。线下收款若主站没有记录真实现金金额，系统不能自动得知，保留简单录入，不伪造“全部自动取得”。负向额度调整不自动当现金退款。

每次提交自动生成幂等键，保存中禁用提交按钮，重试沿用原键。自动记录不可编辑；手工记录支持修改和带确认的删除，合计即时刷新。可选来源单号若已对应自动订单或已有手工记录，提示现有记录并阻止重复新增；没有单号的两笔同金额收付不能凭金额或时间擅自合并。用户不必为防重填写复杂凭证关系。

本期现金、趋势、列表和详情统一人民币，合并所有原始币种的金额原数值；新增或修改保存为 CNY，不使用供应商充值倍率换算现金。日期筛选、本期三张卡片、趋势和列表使用同一范围，累计卡片使用上文独立的全历史口径；保存发生在当前范围之外时，自动切到该记录日期并定位记录，避免“新增后看不到”。搜索或收支筛选只影响列表，前三张卡片保持所选日期的完整汇总，界面区分期间合计和列表筛选小计。

自动现金来源失败时保留已知手工账，但完整现金收入和净流入标记为来源缺失，不能用部分数据冒充完整现金流。没有自动支付记录时显示“自动收款 0”，同时保留手工收入；这不表示所有兑换都是赠送或所有线下收入均已录入。净现金流不是经营净利润，也不展示所谓“现金利润率”。

## 指标与自动来源

| 指标 | 自动来源与边界 |
| --- | --- |
| 主站消费 | 主站 `usage_logs.actual_cost` 按资金日汇总，排除 `user_id=1`；包含余额、订阅和赠送产生的实际计费额度，保留已删除用户用量 |
| 主站请求数 | 同范围非 ID 1 的实际用量记录数，不等同成功率 |
| 供应商消费 | 仅“启用定时检查”的供应商账号日汇总，包含账号全部 Key；Sub2API 取 `total_actual_cost`，New API 取消费 `quota / quota_per_unit` |
| 供应商 CNY 成本 | 使用该日已留存且有效的充值倍率、原币种及汇率折算；有真实依据才展示完整 CNY 金额，不用今天的倍率补过去 |
| 消费毛利 | 主站消费减供应商 CNY 消费；任一来源缺失时相应日期为未知 |
| 消费毛利率 | 合计消费毛利 / 合计主站消费；主站消费不大于零时为空，不平均每日百分比 |
| 本期充值额度 | 已使用且 `used_at` 有效的 `balance` / `admin_balance` 带符号 `value`，排除 ID 1；按 `used_at` 所属日期统计 |
| 线上支付实收 | 仅从实际已支付订单的 `pay_amount + paid_at` 展示，金额原数值计人民币；计入现金收入并可在充值下钻关联查看，不与兑换额度相加 |
| 累计净结余 | 全历史现金入账减全历史现金支出，再减当前非 ID 1 且未删除用户余额；统一 CNY、截至当前，不受日期或列表筛选影响，不改写任何余额 |
| 用户余额 | 当前未删除、非 ID 1 用户的 `balance` 合计及读取时间；删除用户残留可独立查看，不计入当前用户总余额 |
| 上游余额 | 监控最新启用账号余额，显示原币金额和已有倍率折算估值、时间；过期或缺折算依据时不冒充当前完整估值 |

“充值额度”不是已确认现金。管理员线下加余额、赠送或修正都会按原有余额记录自动展示，但不要求管理员分类，也不声称每条都是现金实收。并发、邀请、订阅等非余额兑换的 `value` 不当金额。

订阅售价与订阅消耗不是同一单位。订阅使用的 `actual_cost` 纳入消费口径；订阅现金支付在现金账按付款日展示，不需要人工服务期，也不按用量倒推订阅收入。

无法自动取得的服务器账单、域名费用、人工、推广、线下实收与线下退款不推断，允许实际收付后简单记账。本方案不展示“净利润”“现金净利”或含义不明的“实际利润”；消费毛利尚未扣除上述其他费用。

## 防重与历史

自动兑换以原记录 ID 唯一保存并更新；线上支付以订单 ID 唯一保存。用户列表和记录列表使用同一统计来源与日期边界。线上支付及其关联兑换是两种事实，分别展示，永不相加成一个总收入。现金账沿用已保存的来源关联 / 排除事实，自动发现唯一订单关联后只保留一份现金贡献；源记录仍保留查看，不按相似金额猜测去重。

负向余额调整按带符号额度处理，不直接当现金退款。主站退款字段若表示额度或比例估算，只展示其明确单位，不据此声称取得实际退现金额。相同用户 ID 的记录可汇总，身份已删除或缺失时保留 ID 和原事件金额。

保留 `cost-ledger.json`、`daily-profit.sqlite`、`accounting.sqlite` 及已有审计，不物理删除旧分类、期初或凭据。旧日报继续直接读取，不受人工核算起点约束；新页面不运行旧额度池分摊或期初核验。原账本的收支方向、原币、日期和稳定 ID 在现金账延续；精细核算中生成的迁移副本不再次相加。旧分类和期初不参与消费毛利，不要求先处理旧账才可使用。

后续实现可复用现有持久来源层保存自动兑换与订单，不依赖精细核算的分类结果；重启 / 升级不丢统计。已同步事件在源站删除后保留原记录；源站尚未同步就已清理的记录不能凭空恢复。已明确的源记录更正按原 ID 替换，不追加第二笔金额。

## 自动运行与异常

- 按 `FINANCE_TIMEZONE` 每日 01:00 归档昨日；停机漏跑自动补排，历史查询读本地归档，不串行查询整月上游。
- 当天实时读取，复用短期缓存；页面可见时约每分钟自动更新，离开页面停止前台轮询。刷新图标可提前读取，不要求人工统计。
- 历史缺口、暂时超时和限流由后台按原退避策略补拉，队列和租约持久化；同一日期唯一覆盖，防止重复汇总和旧任务覆盖。
- 充值、用户余额、上游余额独立加载。一个辅助来源失败不会遮挡消费统计；一个供应商失败仍显示其他供应商已取得金额。
- 有缺失日期时，整期成本 / 毛利为未知；同时显示“完整日期毛利小计”及完整天数，不能把小计冒充整月利润。日详情显示已取得成本和缺失供应商，不把已知部分当完整总额。
- 未来日期不查询或计入已发生统计；真实零消费与尚未取到数据明确区分。时区边界、周一分周和月 / 年汇总沿用原约定。
- 日报保留当日纳入供应商、倍率和汇率快照。停用供应商不默默改变历史成本；新日期按当前启用范围。成本汇总不同时叠加 Key 日志、采购账本和供应商充值。
- 仅展示“同步中”“自动重试”“历史数据缺失”等来源状态，不再生成手动财务待办。认证撤销、接口不支持或源数据已删除无法靠重试修复，展示准确原因；必要连接配置仍在原供应商监控 / 系统设置维护，不新增成本分析核验流程。

## 实施边界

已在现有 operations-center 内精简页面与成本核算调用。复用 `/api/cost-analysis/daily-profit`、供应商目录、余额、自动兑换及原收支账，增加持久支付事实与现金汇总接口。页面移除分类、期初、政策和分摊写入入口，只保留简单现金记账及受管理员权限 / CSRF 保护的修改、删除与审计；不触及计费补记或主站写接口，旧核算 API 为兼容保留。

累计净结余使用独立的全历史只读汇总，不向该汇总传入页面日期 / 分页 / 搜索条件；缓存或增量聚合沿用稳定来源 ID，账本变更时失效，当前余额单独刷新。避免为了展示累计卡片向浏览器传全历史明细，也不逐日请求全部历史上游消费，因为此卡片扣的是现金支出。

保留现有连接地址、Token、时区和有效汇率配置，无需重新核对历史账目才可使用。若需持久化新的自动来源，采用非破坏性迁移；保留原数据卷，保留旧账和已归档日报。对缺少历史依据的成本保留未知，不能承诺升级后自动还原不存在的数据。
