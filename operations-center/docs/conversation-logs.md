# 对话日志接入

本模块随 `fjiangming/sub2api-extra` 的 main 发布，配套 `fjiangming/sub2api` 的 dev 采集器。主站负责鉴权后识别用户和旁路读取上游正文，运营中心负责独立归档、策略、脱敏和查询，不写主站业务表，不参与余额或计费。主站新 dev 基于上游新 main，不包含此前旧 dev 的计费恢复定制；运营中心既有模块遇到缺少旧 API 时沿用其不可用 / 降级处理。

## 待确认的接入配置

先更新两个程序，再接入私有网络。以下是参考配置，本次不会应用到服务器。

主站环境变量：

```dotenv
CONVERSATION_LOGS_URL=http://operations-center:9872
CONVERSATION_LOGS_TOKEN=<独立随机值，至少32字符>
```

运营中心环境变量：

```dotenv
CONVERSATION_LOGS_TOKEN=<与主站相同的值>
OPERATIONS_CENTER_DATA_DIR=/app/data
OPERATIONS_CENTER_IMAGE=ghcr.io/fjiangming/sub2api-extra:operations-center-latest
```

`operations-center` 主机名要求两个容器共享可解析的私有 Docker 网络；分开运行时，应先核查网络、服务名和已有挂载。主站 URL 仅允许 HTTPS 或私有 / loopback HTTP，不经系统代理、不跟随重定向。不要向公网额外开放采集端口。现有管理员登录 / SSO 和 CSRF 保护继续适用，采集 token 不具备管理员读取权限。

先在“对话日志 → 保存策略”选择排除用户、采集模型、保存版本和容量，再启用保存。默认关闭，原文与脱敏双副本、保留 7 天、容量 10 GiB、预留磁盘 2 GiB、单条上限 8 MiB、空间不足停止正文。单条上限最多 16 MiB；磁盘不足会标记正文缺失或拒收，不阻断推理。

排除按主站鉴权用户 ID，覆盖其全部 API Key。采集前、发送前和接收端入库前检查，策略读取失败则停止本次采集。保存排除后，尚未入库的记录也会丢弃；不新增正文、用户元数据、索引、会话和该用户缺口。已存在的历史归档不会隐式删除，仍按当前保留期清理。主站原有业务用量和原生诊断记录属于原有功能，不受本归档开关控制。

## 采集模型

在“保存策略 → 采集模型”开启“仅记录所选模型”，每行填写一个模型名（最多 100 个、每个最多 200 字符），另可勾选“Kimi K3 及后续版本”。名单为空且 Kimi 未勾选时不记录任何模型；关闭筛选则恢复按其他保存条件采集。

按网关实际发送给上游的模型匹配，不使用客户端改写前的别名，也不改变原始正文或模型字段。忽略大小写及空格；Fable5 / Fable5.1 和 Opus5 / Opus5.5 兼容 `claude-fable-5` / `claude-fable-5-1` 和 `claude-opus-5` / `claude-opus-5-5`，Gemini carbon 对应 `gemini-carbon`。其他模型与版本按名单精确匹配，不自动包含 Fable5.2、模型日期后缀或其他 Gemini 版本。Kimi 范围包含 K3、K3.1、K4 等后续版本及常见版本后缀，不包含 K2 系列。

新建归档的建议名单为 `gpt-6-astra`、`gpt-6-sol`、`gpt-6.1-sol`、`gpt-5.6-sol`、`claude-fable-5`、`claude-fable-5-1`、`claude-opus-5`、`claude-opus-5-5`、`gemini-carbon`，并勾选 Kimi K3 及后续版本。旧加密策略升级时保持原采集范围，模型筛选默认关闭，需显式保存新策略；旧客户端未提供模型配置时保留当前模型设置。

主站完成模型识别后、排队发送前及运营中心入库前分别检查；不匹配或无法识别时不新增正文、元数据、索引、会话或该模型缺口。在途旧策略记录也必须符合当前名单。HTTP 从实际请求体或 Gemini / Vertex 的 `/models/` 路径取值；WebSocket 兼容顶层 / response 内的模型及同租约后续消息段的模型继承。识别观察使用原有有界内存，不写原文磁盘临时文件。模型识别只影响归档，不阻断正常推理；超限截断且无法识别模型时不归档。

用户排除始终优先，即使模型已选中仍不采集该用户。历史记录不因名单变化被删除，仍可读取；当前名单外的历史记录不能通过重新处理写入新副本。启用此功能需更新主站采集器和运营中心。

## Raw 和完整性

保存的是网关实际发往上游的请求正文、HTTP transport 暴露给网关的响应正文，以及上游 WebSocket 应用消息。保留原字节，不对原文 JSON 解析后重新序列化；未知字段、大整数、数值写法、空白和 SSE 顺序保留。入库 envelope 用 base64 承载字节，下载 `.raw` 时还原原字节，页面附 SHA-256。

这是应用正文归档，不是 TCP / TLS 抓包，不保存 Authorization 等 HTTP Header 或 URL 查询参数。若底层 HTTP transport 已自动解压，保存其解压后的原正文；若仍带 Content-Encoding，则保存压缩字节。查看支持 UTF-8、gzip、br、deflate；不支持的编码和二进制可在“仅原文”模式保存 / 下载。不会为了采集修改原有压缩协商或推理请求。

HTTP 每次真实 RoundTrip 独立保存，包括 TLS 指纹请求、账号切换和 Grok 回退。同次入站共享随机请求编号。WebSocket 在当前租约 / relay 边界归属身份；保留消息方向、次序和相对时间。池化连接不会沿用连接创建者的用户身份；WebSocket Host 无可靠采集值时显示未提供。只保留一个完成事件以内的消息段，连接关闭前未见结束事件会标记不完整。

会话只使用客户端 `session-id` 经按用户、Key 加盐 HMAC 的标识关联，不按文本相似、时间或 IP 猜测。未提供标识的请求仍可独立查询。同会话内同次请求的重试不重复计算请求数。排除 / 策略读取失败的持续 WebSocket 连接需要重连后恢复采集。

“完整采集”表示已读完上游应用字节或见到该 WebSocket 段的结束事件，不代表模型成功或业务计费成功。提前关闭、读取错误、超限、队列满和进程异常均可能缺失。采集总内存预算 64 MiB、单条有界、队列 32、单异步发送 worker，无原文磁盘 spool，不补发推理。每次新尝试及发送前策略读取超时为 200ms，发送超时 2s；异常仅影响归档。采集端累计丢弃数不附用户身份，重启后归零、多个主站实例仅显示最近上报值。

## 脱敏与存储

三种模式：原文 + 脱敏副本、仅脱敏副本、仅原文。默认邮箱、电话、常见密钥字串、IPv4 规则，可配置最多 10 条字面量文本替换。规则并非通用隐私识别器，姓名、地址、自定义凭据等应按实际内容增加规则。相同值使用同一 HMAC 占位符，不落盘保存反向映射。

脱敏定位 JSON 字符串 token，保留字段名、数值写法及未改动部分。保护角色、消息 / 工具关联 ID、工具名、模型和签名字段；结构标识不参加自动敏感匹配，避免时间戳 ID 被误当电话。OpenAI Responses / Chat、Claude 和 Gemini 的常见流式文本按消息组拼接后脱敏，再映射回原事件。支持多行 SSE data、CR / LF / CRLF、NDJSON 和文本；保留 SSE 包装、事件顺序和扩展字段。工具 arguments / output 只有确实为合法内嵌 JSON 才递归，普通工具文字及不完整参数片段按字符串替换，不删除整轮消息。支持运行时可用的 zstd 解压；原文下载始终保留压缩字节。

按用户明确指定的异常策略，自定义规则与结构字段冲突、无效 JSON、编码 / 解压或二进制处理失败时，保留完整的 **AES-GCM 加密原文**（包括“仅脱敏”模式），不生成不完整的脱敏副本。页面正文旁显示安全的异常分类与“重新处理”按钮，不在异常文本中泄露原始片段。采集完整性与处理状态独立：读取完整但处理失败的记录仍是完整采集。容量、磁盘或采集器未取得的字节不能靠异常回退补齐。

重新处理采用点击时的最新脱敏规则，但保留该记录原有保存模式和采集策略版本；独立记录处理策略版本及时间。成功后才原子替换副本，“仅脱敏”模式同时移除临时原文；双副本继续保留原文。再次失败保留原文并更新异常。管理员会话、CSRF、频率限制、策略 / 记录版本校验和空间预检均生效；当前已排除用户不允许重处理。开关关闭仍允许管理员处理未排除的已有历史，不产生新采集。旧 `redaction_failed` / 超限记录若没有保留原文，不能重处理或恢复。

配套主站更新后，单条上限按 Request + Response 累计计算，超限保留有界字节前缀；内存不足保留此前已取得部分，WebSocket 只保留完整的既有消息，不清空整条记录。均标记不完整，并继续沿用 64 MiB 内存 / 32 队列边界，不影响原请求。截断的 JSON 或压缩字节可能再次处理失败，此时仍保留收到的原始部分。

归档位于数据卷 `conversation-logs/archive.sqlite`，正文和策略使用 AES-256-GCM，随机 key 位于同目录 `archive.key`；元数据索引用于查询。目录 0700、key / 主库 0600，沿用容器数据卷所有权。**备份必须保留完整目录和 key**；运行中使用 SQLite 备份或停服后复制完整卷，不能只复制主库。已有数据库缺 key 时拒绝初始化，不生成新 key 冒充可读。

保留期每分钟和入库时执行；容量按数据库 / WAL / SHM 实际占用及可用磁盘检查。淘汰为有界批次，不能保证立即回收所有 SQLite 文件空间。缩短保留期或选择淘汰会影响历史记录。管理员原文下载包含敏感内容；本功能不会额外记录管理员原文读取审计。

## 日志推送

在“对话日志 → 推送策略”保存 Webhook、S3 兼容存储和发送设置。推送独立于保存开关，默认关闭；当前采集器不需要修改或重新发行，无新增主站环境变量。仅升级运营中心并保留原数据卷 / `archive.key`。关闭采集不会阻止管理员推送已有历史，关闭推送则暂停队列。

1. 配置接收目标，可同时启用两类目标。Webhook 使用 HTTPS URL 与可选 Bearer Token；S3 使用 Endpoint、Region、Bucket、对象前缀和静态 / 临时访问凭据，MinIO 等可选择 Path Style。Bucket 必须已存在，所用凭据需具备目标前缀的 PutObject 权限。
2. 选择“脱敏副本”或“原文”。默认脱敏，不重新改写正文；所选副本不存在会跳过，处理异常的原文不会自动替代脱敏副本。原文可能包含敏感信息，须明确选择。用户排除和模型名单对历史 / 自动 / 重试任务同样生效，变更名单不会删除历史或撤回外部副本。
3. 保存后可“测试连接”，仅发送 `sub2api.conversation.test.v1` 虚构诊断 envelope；S3 会留下 `test-*.json` 对象，不读取历史正文。
4. 勾选“自动推送新日志”后，从此次开启之后的新归档开始。关闭期间的历史不自动补发；开启状态下进程重启会继续原扫描位置和持久任务。存量日志在“历史批量推送”按日期、模型 / 请求搜索、用户、Key、协议、完整性筛选，选择目标后预览、勾选确认并加入队列。每批最多 10,000 条日志，多目标各产生一个任务；已存在的相同任务不重复新增。

凭据与独立推送策略保存在原归档 SQLite 的 AES-GCM 加密表内，管理员 API 仅返回“已设置”。输入留空保留原凭据；清除须勾选清除选项。S3 Session Token 可单独清除，Access / Secret Key 可独立填写新值；清除全部凭据前需关闭 S3 目标（如果是唯一目标，同时关闭推送）。策略版本冲突须重新读取。目标变更后旧任务不会转发到新地址，副本更新后旧任务不会偷偷改发新版；需按新策略重新预览创建批次。

公网目标要求 HTTPS；私网 / loopback 和 HTTP 需要显式勾选“允许私有网络目标 / HTTP”。每次实际发送重新解析并检查所有 DNS 地址，固定本次连接 IP；链路本地 / 云元数据、组播和未指定地址始终禁止，不跟随 HTTP 或 S3 重定向。URL 不含鉴权、查询参数或 fragment，Webhook 鉴权放入专用 Token 字段。没有使用环境代理或 AWS 默认凭据链。

原 SQLite 内的队列仅保存正文引用和任务状态，不复制正文、不建立明文临时文件，不向采集请求内发送外部网络请求。串行后台 worker 有超时、有限指数退避、队列上限与租约恢复。网络故障、408、429、5xx 自动重试，其他 4xx / 重定向 / 禁止地址停止；可以在推送记录手动重试失败任务，使用原幂等标识。队列满时自动扫描停在未排队位置，腾出空间后续扫；原日志仍可能先被原保留期 / 容量策略淘汰，过期记录和关联任务会一并清理，不能将本功能当成无限期备份。

批次取消只取消未完成任务。配置 / 采集名单变化和正常退出会中止在途发送，但已发出的字节不能撤回；目标可能已接收而回执丢失，因此是**至少一次**投递。Webhook 接收端必须按 `Idempotency-Key` 去重，同一任务重试时该值和 `delivery_id` 保持相同。S3 固定对象名为 `<prefix>/<UTC日期>/<delivery_id>.json`，同任务重试覆盖同一 key；开启版本控制的 Bucket 仍可能保留多个对象版本。关闭运营中心或进程异常后的未知送达会沿用原标识重试，不承诺恰好一次。

外部副本的访问控制、保留期、删除和加密由接收系统负责；本地淘汰或用户排除不会远程删除已送达对象。Webhook 仅以 2xx、S3 以成功 PutObject 回执确认送达，不检查下游是否已完成入库或后续处理。目标返回正文和原始错误不会落入任务表，只保存固定错误码与 HTTP 状态。

### 接收格式

Webhook POST 与 S3 JSON 对象使用相同 envelope：

```json
{
  "schema": "sub2api.conversation.v1",
  "delivery_id": "<稳定的64位十六进制任务ID>",
  "source": "masked",
  "metadata": { "id": "<归档ID>", "model": "gpt-6-astra", "at": 1700000000000, "encoding": "", "complete": true },
  "body_encoding": "base64",
  "request": "<Request字节的base64>",
  "response": "<Response字节的base64>",
  "frames": [],
  "checksums": { "request": { "bytes": 0, "sha256": "<摘要>" }, "response": { "bytes": 0, "sha256": "<摘要>" }, "frames": [] }
}
```

`metadata` 包含原归档的用户 / Key / 上游账号、请求 / 会话、协议 / Host / path、采集策略 / 完整性 / 处理异常等字段。Request / Response 是原已保存副本的完整字节，未解析重排 JSON；base64 解码后数值拼写、空格、未知字段和 SSE 包装保持。原文 `encoding` 保留响应压缩标识，脱敏副本为已处理的 UTF-8 字节。WebSocket `frames` 逐项保留 `direction`、`at`、`binary` 和 base64 `body`，校验数组与消息一一对应。示例省略其余元数据，`bytes` 和摘要由真实内容计算。

管理员接口均位于 `/api/conversation-logs/push`，需要现有管理员会话，写请求还需 CSRF；采集令牌不能访问。策略 `GET/PUT /policy`，状态分页 `GET /jobs`，历史 `POST /preview` → `POST /batches`，批次 `GET /batches/:id` / `POST /batches/:id/cancel`，单任务 `POST /jobs/:id/retry`，诊断 `POST /test/:destination`。批次提交使用客户端 UUID 和预览 token，相同 UUID / 参数重复提交返回原批次；策略 / 内容版本改变须重新预览。没有新增公开正文下载端点。

## 发布与验收

大正文初次仅加载前 64K 字符的文本预览，不重复携带整段 base64；“查看完整”按钮按需展开，复制与下载始终读取完整内容。预览不改变保存正文、原始字节、SHA-256、脱敏规则或排除名单。邮箱规则按 `@` 定位并从固定位置校验域名，流式替换统一拼接，避免长文本和大量替换阻塞运营中心。

主站 dev 推送触发 Fork Dev Release，单元 / race 测试、前端构建、五平台压缩包及 SHA-256 校验、双架构镜像运行验证通过后发布。GitHub Release 为三段数值版本，兼容原生更新器；镜像为 `ghcr.io/fjiangming/sub2api:<version>`，最新成功版本更新 `dev`、`latest`。主站更新来源、版本菜单和安装脚本均指向本 fork，旧上游缓存不会复用。

本仓库 main 推送沿用 Docker images 流程，运行运营中心完整测试后构建原生 linux/amd64 和 linux/arm64 镜像，检查 SQLite、源码 revision、对话归档模块和导航资源，再发布 `ghcr.io/fjiangming/sub2api-extra:operations-center-latest`、`operations-center-main` 及 `operations-center-sha-<短SHA>`。不再维护本仓库独立 dev 分支或 dev 发布流程；主站仍保留其独立 dev 分支。

主站左上角更新仅升级主站程序。运营中心需要按原 Compose 项目单独更新，保留完整原数据卷及归档 key；沿用 `operations-center-latest` 的部署无需切换镜像通道。新版运营中心即使尚未接入采集也会显示“对话日志”入口，实际保存仍需上面的连接 / token 配置和管理员启用策略。源代码发布不自动操作服务器。

本地 `npm test`、`npm run check`；`npm run preview:conversations` 启动隔离的正式页面预览（默认 `http://127.0.0.1:19907/preview`），仅虚构数据和临时 SQLite。`npm run check:conversations-ui` 通过 Playwright 检查下载原字节、会话、排除与模型配置保存 / 重载、名单外零新增、空名单 / Kimi 范围、XSS、退出清理及窄屏布局，可用 `PLAYWRIGHT_MODULE_PATH` / `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定已有运行时。

`npm run check:conversation-push-ui` 额外用 loopback 接收器验证 Webhook / S3 签名、诊断、自动 / 历史 / 去重、失败 / 重试、凭据留空和离开 / 退出清理，覆盖 1440 / 390 / 320px 及系统深色；不会发送生产正文或连接真实存储。发布前仍需原有 CI / 原生镜像运行检查，源码和本地测试通过不等于已发布或部署。
