# 供应商分组每日消费

入口：运营中心 → 成本分析 → 供应商分组消费。按资金时区选择一天，每个供应商单独展示对照表：**主站账号（含账号消费）、上游供应商分组、主站合计、上游分组消费和差额**。展开账号查看实际请求所属主站分组的消费，不需要通过 Key 尾号识别账号。

同一个上游 Key 对应的多个主站账号分别列出，账号在多个主站分组中的实际消费累加。点击上游分组可查看全部账号、按主站分组汇总和最近七日归档；关联核对与简称 / 差额提醒通过工具按钮进入，设置保存后持久生效并记录管理员审计。

列表只展示有关联主站账号的上游分组，账号当天零消费也保留；没有任何主站关联的上游分组不进入列表、分页及供应商合计。在用分组的上游消费仍包含该上游分组全部 Key，不按账号数量重复累计。名称已唯一定位供应商，但 Key 或分组无法核验的账号，在同一供应商下单列“上游分组待核对”。当前分组已唯一定位、全天身份历史未核验的账号仍在对应分组列出，展示账号全天实际消费并标记“全天归属待核对”，不声称全天都属于当前分组，不核定受影响分组及供应商差额。

每页最多 20 行，每个在用上游分组及每家供应商的待核对汇总各占一行；每行首页最多预览 10 个账号，更多账号通过“查看全部”按页读取。分组主站合计包含该组全部账号，供应商合计包含全部分页的在用分组及待核对账号。任一在用分组上游缺失或存在待核对账号时，上游合计保持未知，另显示已取得的小计；任一分组不可比或刷新失败时，供应商合计差额保持未知。

## 匹配与金额

- 账号名称包含供应商全名时优先定位供应商；统一大小写、全半角并忽略空格和标点。兼容去除 API 后缀以及管理员明确配置的简称，停止自动截取半名和单词片段。仅名称候选唯一即可在该供应商下展示账号，仍须完整 Key 指纹唯一核验上游分组，才进入对应分组的主站消费合计。多供应商候选且无法由 Key 确认时保留在“账号关联核对”，不任意归属。
- 账号凭据的 `api_key` 只在只读查询进程中生成 SHA-256 指纹；去除 Bearer 和 sk- 前缀，以适配 New API 的带 / 不带前缀形式。脱敏值、短值和缺失 Key 不参与匹配。页面不返回完整 Key、指纹或认证凭据。
- 同一个上游 Key 只计一次上游消费，所有已匹配主站账号的用量累加；同一账号跨主站分组按 `usage_logs.group_id` 拆分，不乘以 `account_groups` 关联数。停用或已删除账号仍保留发生过的消费。
- 主站金额使用 `usage_logs.actual_cost`，排除 `user_id=1`；沿用现有成本分析人民币原数值口径。上游金额按实际发生的上游分组读取实际消费，再用当日已确认充值倍率和汇率折 CNY。
- 消费差额 = 已关联主站消费 − 上游实际消费；差额率 = 差额 / 主站消费。主站为零时差额率为空。未分摊充值抽奖、服务器等其他费用，不能直接当成漏记金额或经营净利润。
- 只有来源、关联与 Key 覆盖完整的分组计算差额。有 Key 未关联、疑似相关账号待核对、同 Key 当日跨多个上游分组无法分配、源明细清理或上游缺能力时保持未知。主站来源不完整时，账号合计与分组拆分也保持未知；确认零和未知分别展示。
- 提醒针对上游超出主站消费，金额和比例同时达到阈值时标为“上游偏高”；默认 10 CNY、5%。设置只影响监控标记，不发送通知或执行补扣。

## 归档与完整性

今天按需和后台每分钟采集；资金时区 01:00 后首次归档昨天，同一天自动重试补缺。所有历史页面刷新只读 `supplier-group-costs.sqlite`；没有归档显示历史缺失，不重新拉取历史上游或按当前账号 / Key 关系倒推。更早缺口只能从可信备份恢复。

归档重试冻结已确认的上游值和名称 / 分组关联，允许不完整主站来源补齐；已完整的历史主站来源遇失败继续保留。首次观察时账号更新时间晚于首条用量、缺可信更新时间，或当日观察到名称 / Key 改变时保留待核对。已有可信当日观察且名称 / Key 不变时，其他字段更新导致 updated_at 推后不再单独否决关联；已记录的真实变化或历史依据不足不会自动清除。后一天轮换不会覆盖已观察的前一天身份。该功能无法重建上线前已清理的用量或此前没有归档的 Key 关系。

主站读取使用只读 REPEATABLE READ 事务、每条 SQL 5 秒超时，核对资金日涉及的所有原生日桶与明细计数。已发生用量的账号记录彻底缺失时，主站来源也不认定完整。单日最多 10,000 个账号、50,000 条账号 / 主站分组汇总；超过上限整次失败，不使用截断数据。后台统计整体最多 45 秒，失败保留上次快照且本次差额不核定，停止和来源 / 时区变化后的迟到结果不能落库。

## 配套与上游能力

需同时更新 **operations-center 和 provider-monitor**，沿用现有持久数据卷、数据库只读连接和集成 Token / 管理员 SSO，无新环境变量、主站迁移或资金写入。普通供应商同步会在脱敏前保存完整 Key 指纹；升级后需完成一次正常目录同步。上游只返回脱敏 Key 时无法生成指纹，关联将保持待核对。

监控新增 `GET /api/integrations/group-daily-costs`，SSO 对应 `/api/group-daily-costs`，参数为单日 `from=to`、`timezone`、`currency=CNY`，仅昨天初始归档额外传 `archive=1`。受保护的服务间响应含 Key 指纹，浏览器只读运营中心脱敏报表：`GET /api/cost-analysis/supplier-groups`；设置为管理员和 CSRF 保护的 `PUT /api/cost-analysis/supplier-groups/settings`。

报表分组列表包含脱敏账号预览 `groups[].accounts`、预览截断标记 `accountsTruncated` 和跨页完整的 `providerSummaries`。`pendingProviders[]` 返回当前分页的未定位分组账号预览；`providerSummaries[].pendingAccountCount` 与 `summary.pendingAccountCount` 只计未定位分组数量。已定位分组而全天身份未核验的账号返回 `historyVerified=false` 及原因，组状态为 `history_unverified`；两类问题均进入 `summary.issueCount` 和 `issuesOnly=1` 的核对列表。`groupId` 配合 `view=accounts` 按分组账号分页，`view=mapping&providerId=...&issuesOnly=1` 分页查看待核对账号；`view=local` 返回主站分组及账号名称。原 `view=keys` 和按 groupId 直接查询兼容。本次需配套更新运营中心与供应商监控，无数据库迁移、新增配置或资金写入；历史仅投影既有快照，不用当前目录重建关系。

Sub2API 今日采集需要账号凭据及完整的 `/api/v1/usage` 明细，支持日期 / 时区和记录 ID 升降序分页。先固定最新记录 ID 和当时总条数，再按 ID 升序读取至该记录；账号、Key 和实际分组消费均从同一批明细汇总，采集期间追加的新 ID 留到下次刷新。已核验截点随原快照保存，后续从边界页验证原锚点，再只累加新增记录，不重复计费或扫描全天；相同条数和锚点只需读取头部即可复用，重启继续使用原截点。严格检查分页、ID 顺序 / 唯一性、边界 / 终点锚点及条数、账号、Key、分组、日期和实际消费；每次最多读取 20,000 条新增记录（首次无截点时为当天全部），因此已有有效截点的日累计可超过 20,000 条；按响应体大小预算限制每页最多 500 条、后续最多三页并发。首次接入时全天已超过上限或原截点失效则保持未知，不跳页冒充完整。未知或已删除 Key 的消费仍计入账号总量，目录不能覆盖时禁止比较。昨天初始归档沿用 `usage/dashboard/snapshot-v2` 分组查询和 Key 日汇总的严格相等检查，并保留已知值冻结及仅补未知 Key 的规则。

New API 使用账号凭据、严格额度单位和当日消费日志的 `token_id` / `group` / 唯一日志 ID，校验分页总数，最多 100 页 / 10,000 条日志。上游清理、缺字段、重复日志、分页缺口或不支持记录排序时保持未知，不回退到当前分组估算。其他适配器暂显示来源不可用。记录 ID 截点依赖上游正常追加日志，不是跨 HTTP 请求的数据库事务；无法重建被改写或清理的历史。凭据在每个活动读取上下文内仅缓存一份解密结果，每次请求前仍读取当前密文和配置，人工修改使在途读取失败；自动 Token 轮换沿用并发协调，不新增进程级明文缓存。

监控每份请求最多 8.5 秒，最多 3 个供应商及每供应商 3 个 Key 并发；单供应商最多 6 秒。每供应商最多 500 个 Key、总计 1,000 条 Key / 分组记录。完整归档不重查，部分归档只补未知 Key；历史零消费必须已有当日分组观察，不能用今天目录倒推。Key 合计必须覆盖整个上游账号日汇总；同一上游账号重复配置为多个供应商时不允许比较。

今日分组消费查询失败且没有旧快照时，仍返回目录内已有的完整 Key 指纹和当前分组，所有金额 / 请求数保持未知，不保存为成功消费快照。目录分组仅供当日关联展示，不证明全天真实分组消费；组状态保留来源缺失及核验原因。历史、昨天首次归档和跨日失效不使用今日目录兜底，也不扩大上游请求期限或取消迟到写入保护。

本地演示：`npm run preview:supplier-groups`，仅使用隔离 PGlite、SQLite 和模拟供应商，不连接生产；默认 http://127.0.0.1:19882/preview。浏览器回归为 `npm run check:supplier-groups-ui`，可用 `PLAYWRIGHT_MODULE_PATH` 和 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定现有 Playwright / Chrome。
