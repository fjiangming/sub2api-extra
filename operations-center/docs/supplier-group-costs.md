# 供应商分组每日消费

入口：运营中心 → 成本分析 → 供应商分组消费。按资金时区选择一天，每个供应商单独展示对照表：上游分组、主站对应账号消费、主站合计、上游分组消费和差额。主站直接显示账号名称与合计，展开账号查看实际请求所属主站分组的消费，不需要通过 Key 尾号识别账号。

同一个上游 Key 对应的多个主站账号分别列出，账号在多个主站分组中的实际消费累加。点击上游分组可查看全部账号、按主站分组汇总和最近七日归档；关联核对与简称 / 差额提醒通过工具按钮进入，设置保存后持久生效并记录管理员审计。

分组列表按每页最多 20 组展示，同一供应商的分组连续排列；每组首页最多预览 10 个账号，更多账号通过“查看全部”按页读取。列表限制不截断金额：分组主站合计包含该组全部账号，供应商合计包含所选供应商全部分组，跨页时会标明完整分组数。供应商任一分组的上游消费缺失时，上游合计保持未知，另显示已取得的小计；任一分组不可比或刷新失败时，供应商合计差额保持未知。

## 匹配与金额

- 账号名称先匹配供应商全名，再使用分词、去除 API 后缀、至少半个名称的连续片段或管理员设置的简称形成候选；仍须完整 Key 指纹交叉核验唯一供应商和上游分组。名称相似或 Key 尾号相同不足以确认归属。
- 账号凭据的 `api_key` 只在只读查询进程中生成 SHA-256 指纹；去除 Bearer 和 sk- 前缀，以适配 New API 的带 / 不带前缀形式。脱敏值、短值和缺失 Key 不参与匹配。页面不返回完整 Key、指纹或认证凭据。
- 同一个上游 Key 只计一次上游消费，所有已匹配主站账号的用量累加；同一账号跨主站分组按 `usage_logs.group_id` 拆分，不乘以 `account_groups` 关联数。停用或已删除账号仍保留发生过的消费。
- 主站金额使用 `usage_logs.actual_cost`，排除 `user_id=1`；沿用现有成本分析人民币原数值口径。上游金额按实际发生的上游分组读取实际消费，再用当日已确认充值倍率和汇率折 CNY。
- 消费差额 = 已关联主站消费 − 上游实际消费；差额率 = 差额 / 主站消费。主站为零时差额率为空。未分摊充值抽奖、服务器等其他费用，不能直接当成漏记金额或经营净利润。
- 只有来源、关联与 Key 覆盖完整的分组计算差额。有 Key 未关联、疑似相关账号待核对、同 Key 当日跨多个上游分组无法分配、源明细清理或上游缺能力时保持未知。主站来源不完整时，账号合计与分组拆分也保持未知；确认零和未知分别展示。
- 提醒针对上游超出主站消费，金额和比例同时达到阈值时标为“上游偏高”；默认 10 CNY、5%。设置只影响监控标记，不发送通知或执行补扣。

## 归档与完整性

今天按需和后台每分钟采集；资金时区 01:00 后首次归档昨天，同一天自动重试补缺。所有历史页面刷新只读 `supplier-group-costs.sqlite`；没有归档显示历史缺失，不重新拉取历史上游或按当前账号 / Key 关系倒推。更早缺口只能从可信备份恢复。

归档重试冻结已确认的上游值和名称 / 分组关联，允许不完整主站来源补齐；已完整的历史主站来源遇失败继续保留。主站账号当日更新晚于首条用量、观察到名称 / Key 改变，或无可信更新时间时保留待核对；后一天轮换不会覆盖已观察的前一天身份。该功能无法重建上线前已清理的用量或此前没有归档的 Key 关系。

主站读取使用只读 REPEATABLE READ 事务、每条 SQL 5 秒超时，核对资金日涉及的所有原生日桶与明细计数。已发生用量的账号记录彻底缺失时，主站来源也不认定完整。单日最多 10,000 个账号、50,000 条账号 / 主站分组汇总；超过上限整次失败，不使用截断数据。后台统计整体最多 45 秒，失败保留上次快照且本次差额不核定，停止和来源 / 时区变化后的迟到结果不能落库。

## 配套与上游能力

需同时更新 **operations-center 和 provider-monitor**，沿用现有持久数据卷、数据库只读连接和集成 Token / 管理员 SSO，无新环境变量、主站迁移或资金写入。普通供应商同步会在脱敏前保存完整 Key 指纹；升级后需完成一次正常目录同步。上游只返回脱敏 Key 时无法生成指纹，关联将保持待核对。

监控新增 `GET /api/integrations/group-daily-costs`，SSO 对应 `/api/group-daily-costs`，参数为单日 `from=to`、`timezone`、`currency=CNY`，仅昨天初始归档额外传 `archive=1`。受保护的服务间响应含 Key 指纹，浏览器只读运营中心脱敏报表：`GET /api/cost-analysis/supplier-groups`；设置为管理员和 CSRF 保护的 `PUT /api/cost-analysis/supplier-groups/settings`。

报表分组列表增加脱敏账号预览 `groups[].accounts`、预览截断标记 `accountsTruncated` 和跨页完整的 `providerSummaries`。`groupId` 配合 `view=accounts` 按账号分页，按全部上游 Key 关联的主站账号统一读取；`view=local` 同时返回账号名称。原 `view=keys` 契约仍兼容，归档、匹配与计费逻辑不变。本次账号展示升级只需更新 operations-center，不新增环境变量、数据库迁移或 Provider Monitor 改动；首次启用该功能仍需完成下述两组件配套。

Sub2API 需要账号凭据及兼容的 `usage/dashboard/snapshot-v2` 分组查询和 Key 日汇总；必须返回完整的实际分组金额 / 请求数并与 Key 汇总一致。New API 使用账号凭据、严格额度单位和当日消费日志的 `token_id` / `group` / 唯一日志 ID，校验分页总数，最多 100 页 / 10,000 条日志。上游清理、缺字段、重复日志或分页变化会保持未知，不回退到当前分组估算。其他适配器暂显示来源不可用。

监控每份请求最多 8.5 秒，最多 3 个供应商及每供应商 3 个 Key 并发；单供应商最多 6 秒。每供应商最多 500 个 Key、总计 1,000 条 Key / 分组记录。完整归档不重查，部分归档只补未知 Key；历史零消费必须已有当日分组观察，不能用今天目录倒推。Key 合计必须覆盖整个上游账号日汇总；同一上游账号重复配置为多个供应商时不允许比较。

本地演示：`npm run preview:supplier-groups`，仅使用隔离 PGlite、SQLite 和模拟供应商，不连接生产；默认 http://127.0.0.1:19882/preview。浏览器回归为 `npm run check:supplier-groups-ui`，可用 `PLAYWRIGHT_MODULE_PATH` 和 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定现有 Playwright / Chrome。
