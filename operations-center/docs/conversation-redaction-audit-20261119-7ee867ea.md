## 已确认的误替换

### 工具名称及其正文引用

135 个 personal 值全部来自请求的 135 个工具定义名称，没有一个来自人员姓名字段。`tools[i].name` 中的 `Read`、`Bash`、`Write`、`Agent` 等被替换为个人信息占位符；随后值学习又把说明、历史消息和回答中相同单词一起替换，合计 496 次。

具体例子：`Read` 被记录为 personal 156 次，`Bash` 42 次，`Write` 24 次，`Agent` 22 次。本条 Response 中的替换也是普通工具名 `Read`，不是人员信息。

原始 Request 的 910 条消息和工具定义中，共找到 421 次原生 `tool_use`：原文全部能找到同名工具定义。副本保留了 421 个调用名称，却把 135 个定义名称全部改掉，因此 421 次调用均无法再按名称找到定义。外层 JSON 键集合、数组长度和层次比较未发现变化，但协议语义已经不一致，不能只以 JSON 能解析认定副本完好。

### 数字被识别为电话

82 个 phone 值的上下文包括：

- `2026-11-17`、`1900-01-01` 等日期，以及代码里的日期格式模板和带时间的日期前缀。
- 文件名中的紧凑日期、回归证据时间戳、版本后缀。
- `ps` / `lsof` / 端口列表中跨列拼在一起的 PID、CPU / 内存数字、文件大小、队列长度。
- 浏览器 `--field-trial-handle`、`--launch-time-ticks`、`--trace-process-track-uuid` 等参数。
- 普通 UUID、UUID 的纯数字片段、测试用全零 UUID。
- SQL advisory lock 的数字、网页 URL 的 `pageId`、Cron 时间表达式、字节转储。

这些上下文没有表明它们是电话号码；某些业务标识是否另需保护，应由其实际用途决定，不能靠 phone 类别直接认定。当前正则只要求一段较长的数字 / 空格 / 连字符 / 括号组合，连分列数据和 UUID 片段也会命中。

## 应继续保护与不能忽略的部分

登录命令和工具结果中有实际密码、JWT / 认证令牌、数据库连接认证信息；这些继续脱敏有必要。`device_id` 是客户端持久标识，`session_id` 可关联会话，使用稳定占位符具有隐私价值，但后者不应被描述为已经确认的登录密钥。人员邮箱及实际内部 / 远端网络信息也应结合策略保留保护。

误报很多不代表漏报已经消除：这份副本仍可看到一些本机用户名、工作目录及业务引用，不能宣称其已完全匿名化。

本条存在 `OPAQUE_SIGNATURE`。只读调用现有副本选择逻辑，结果为 `source=original`、`fallbackReason=INSPECTION_INCOMPLETE`、`blocked=''`。也就是说，按当前“脱敏优先、不可用则原文”的规则，选择导出 / 推送这条时会回退原文；本轮没有触发实际输出，也没有检查或断言它已对外发送。这个回退行为与副本过度替换是两个独立问题。

## 根因与建议修复范围

1. `conversation-sensitive.js` 的 personal 通用字段包含 `name`，原生 Claude 工具定义 `tools[i].name` 未纳入精确协议路径保护。应保护工具定义、工具选择和调用关联字段；不能放行任意业务对象的 name / id。
2. `conversation-redaction.js` 的 learn 会把误识别的结构值加入全局替换表，放大为正文中的同词替换。应仅传播已确认的敏感实体，并排除协议值、代码符号、普通短词和占位示例。
3. 电话识别需结合字段 / 标签、号码校验与上下文，排除确定的日期、UUID、格式模板、进程表、时间戳和运行参数；不能简单以 8 位以上数字认定电话。
4. secret 文字规则需要标签边界和语法上下文，区分工作目录变量、赋值、比较、变量引用、Cookie 名称及真实凭据，保留对代码中真实字面量秘密的保护。
5. 金融和证件规则需要上下文约束；Git SSH URL 应按其协议解析；回环 / 未指定地址可单独处理，实际私网和公网地址维持策略保护。
6. 增加虚构的同结构回归数据，验证工具定义与 421 次调用的对应关系、日期 / 代码保持、真实秘密仍被替换、SSE 事件与消息顺序不变。修复后提高脱敏引擎版本，再由保留原文重建历史副本。本条有原文可以重建；仅剩旧副本的其他记录无法可靠逆推原值。

上述修复可以只落在运营中心，不需要修改 sub2api 转发链路。副本是在归档处理阶段生成，本条误替换不表示当时发给上游的原请求被改写；但会降低副本用于分析、训练或回放的质量。

检查结束时主站和运营中心均为 running / healthy；临时诊断进程结束，未复制原始正文或加密密钥到工作区。这里只新增此匿名化分析报告及维护台账，不提交 / 推送、修改生产记录或部署。
