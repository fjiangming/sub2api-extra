# 2026-11-17：升级后图片触发的处理异常

用户反馈升级后仍有 `UNINSPECTABLE_CONTENT`，页面同时显示“上游已完成”。本轮只读核对生产版本，并在服务器内存中诊断有限失败样本；正文、图片、URL、密钥和敏感值不导出，不更改生产配置、日志、策略或服务。截图 ID 前缀未命中当前记录，因此使用同类失败记录定位，不能声称已重放截图原条目。

## 运行版本与根因

运营中心 revision 为 `b8f58f53bbb84c8f195e56f9770ea27c7b687b5b`，脱敏引擎为 4，保存策略为 7，确认用户已升级到上一轮发布。保存策略版本不是引擎版本。主站与运营中心均 healthy；诊断前后容器身份、启动时间不变。

原引擎对以下真实图片字段报告 `UNINSPECTABLE_CONTENT`：

| 协议位置 | 安全诊断结果 |
| --- | --- |
| `input[n].content[m].image_url` | 父类型 `input_image`，`data:image/...;base64,...` 图片引用；GPT 和 Kimi 均出现 |
| `input[n].output[m].image_url` | 父类型 `input_image`，上层为 `custom_tool_call_output`，有字符串 `call_id`；工具返回多张图片 |

图片本身无法通过文本规则识别证件、人脸、截图文字等敏感信息，旧保护确实被触发；这不是 EOF 识别失效、字段丢失或未拉取新版。旧引擎在图片处终止整次处理，仅保留加密原文，其余可读文字也没有生成副本。原来的传输异常与应用完成证据仍是独立状态。

## 本地兼容与只读重放

引擎 v5 仅对已识别的确切协议位置原样保留图片，继续处理可读文字，单独记录 `OPAQUE_IMAGE`。补充 Responses 消息、`function_call_output / custom_tool_call_output` 多模态输出、WS create 包装，以及 Chat / Claude 的消息图片；不放行未知媒体字段、工具内嵌 JSON 伪装、任意加密值或与图片冲突的自定义规则。

使用当前已安装镜像启动临时诊断容器，代码覆盖仅在进程内存中加载：网络关闭、根文件系统和生产卷只读、0.25 CPU、256 MiB 内存、160 MiB V8 old-space、32 个 PID 限制，固定四条记录，单条解码预算 24 MiB，外层有期限，退出清理容器。未调用 ingest / retry / initialize，不写回重放结果。

## 保存、隐私与上线边界

图片、图片 URL 和加密推理内部仍未检查。含警告的可读副本仅供管理员查看，即使“仅脱敏”也保留精确加密原文，webhook / S3 / JSONL 的脱敏推送全部拒绝，既有队列再次核验；不会自动改发原文。图片 URL 中的凭据也可能保留，因此不能把“处理异常”消失当作完全脱敏。

不做 OCR、图片解码、转换、重压缩或外部下载，不增加 sub2api 的采集 / 推理工作。副本会增加归档 CPU / IO 和存储占用，既有独立工作进程、容量 / 内存保护和正常对话优先策略继续有效；无法承诺共享资源成本为零。图片兼容不改变 `complete / reason`，真实断流缺失字节仍无法补回。

本轮没有部署、重启或更新生产配置，没有重处理 / 删除生产历史。升级运营中心后，新日志按 v5 处理；旧记录需要管理员显式点击单条“重新处理”，或在采集状态启动后台兼容检查，不会因升级自动全库重写。
