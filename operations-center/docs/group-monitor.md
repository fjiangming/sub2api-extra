# 分组监控

在运营中心的“分组监控”Tab 查看所有未删除的主站分组、各组启用账号数、模型请求结果，以及启用账号倍率高于分组的异常记录。页面沿用管理员登录 / SSO、CSRF 和现有主站只读数据库连接。

## 配置与检测

1. 在分组“详情”选择该组可用的检测模型、请求协议，并填写专门为此组创建的普通主站 API Key。服务会验证 Key 当前属于此组、启用且未过期、所属用户启用；不能使用另一个分组的 Key 或管理员 Token。留空保留原 Key，勾选“移除”清除已保存的 Key。
2. 使用“重测”或“立即巡检”。请求经过 `SUB2API_BASE_URL`（未设置时使用 `SUB2API_PUBLIC_URL`）的正常主站路由，不直接调用上游账号，不新增管理员测试、改价或资金接口。主站按该 Key 的正常用量和账单规则处理，建议使用专用检测用户并控制额度。
3. 在“巡检设置”开启自动请求巡检。默认关闭；间隔 1–1440 分钟（默认 5）、超时 1–120 秒（默认 30）、并发 1–5（默认 2）、最大输出 16–512 Token（默认 128）。倍率扫描不受此开关影响，约每分钟单独读取一次。

自动协议为：Anthropic / Claude 模型使用 `/v1/messages`，OpenAI 使用 `/v1/responses`，Gemini / Antigravity 使用 Gemini `generateContent`，其他平台使用 `/v1/chat/completions`。合成分组或平台的模型协议有特定要求时可手动选择四种协议。模型名使用分组对外的真实可用名称；检测不绕过模型白名单、额度、客户端限制或平台限制。只检测所选一个模型，单组生成成功不代表该组每个模型、每个账号均可用，也不伪造命中账号。

只有 HTTP 成功且响应中包含预期协议的有效生成文本才通过，HTML 登录页、空正文、错误 JSON、空生成、超时和超大响应均不会记为成功。响应最多读取 256 KiB，记录状态 / HTTP / 耗时 / 协议 / 模型 / 请求编号，不保存模型生成正文或上游错误正文；不跟随重定向、不自动重试生成 POST，避免丢回包后重复调用。停止会取消在途检测并停止后续排队，已发出的主站请求仍可能产生用量。

未配置模型 / Key、无启用账号、分组停用、待检测和检测受阻分别显示。修改模型、协议或 Key 会递增配置版本，之前结果仍在历史中，但不再算作当前配置通过。每次发起请求前再次只读验证 Key 归属，Key 被重新分组、停用、过期或用户停用时直接阻断。主站 / 数据库目标切换使用独立范围的参数、Key 和历史；在途任务检测到切换后中断。

## 倍率异常

- 对每个 `account_groups` 关联，比较未删除且 `accounts.status = active` 的账号 `rate_multiplier` 与所属分组默认文本 `rate_multiplier`；严格大于即异常，相等不异常，0 倍率有效。账号调度开关单独显示，不代替账号启用状态。
- 同一账号加入多个分组时逐组核验，既可能在一组异常、另一组正常。分组停用仍核验其中启用账号；停用 / 错误状态账号、软删除账号与已删除分组不参与。
- 倍率缺失、负值或无效时单列“待核验”；分组 0 倍率时显示差值，不计算除以 0 的超出百分比。比较使用十进制，不受浮点误差影响。不把用户专属、高峰、图片或视频倍率混入该规则，也不推断净利润或替代主站利润调度控制。
- 每次完整快照更新持续异常的最后核验时间，保留首次发现时间；条件不再触发则结束该异常，再次触发生成新的记录。已恢复记录也可能来自账号停用、移出分组或删除，详情明确显示当前归属与当时记录。
- 数据源失败、权限不足或超过 5,000 个分组 / 50,000 个关联时保留旧快照和异常，不以部分 / 空结果假称恢复；页面显示读取失败或过期。快照超过三分钟为过期，手动“重新核验”可重读。

## 保存与升级

只更新运营中心，保留完整数据目录中的 `group-monitor.sqlite`、WAL 文件和现有 `settings.key`。专用 Key 使用 AES-256-GCM 加密，绑定主站范围与分组，不回显给浏览器或进入检测记录。模型参数、巡检设置与历史存储在运营中心独立 SQLite；自动清理 30 天前的请求、已解除异常和任务记录，未解除异常不按日期删除。服务重启时将未完成任务标为中断，不自动重放在途生成请求。

不新增运行依赖、必填环境变量或主站表结构。读取角色需对 `public.groups`、`public.accounts`、`public.account_groups`、`public.api_keys`、`public.users` 具备 SELECT 权限；现有系统设置创建的只读角色已授权 public 表，手工缩减过权限的角色需要补足。此模块只读主站，不写账号、倍率、余额或使用记录；请求用量由主站原生网关正常创建。

## 本地验证

```bash
npm run check
node --test --test-concurrency=1 tests/group-monitor.test.js
npm run preview:group-monitor
```

预览使用临时 PostgreSQL 兼容数据库、独立临时 SQLite 与 loopback 模拟网关，访问输出地址的 `/preview` 自动登录；不读取 `.env` 或连接生产。默认端口 19922 被占用时自动选择下一个端口。浏览器检查沿用仓库的 `PLAYWRIGHT_MODULE_PATH`、`PLAYWRIGHT_CHROMIUM_EXECUTABLE` 可选配置，执行 `npm run check:group-monitor-ui` 验证桌面、嵌入宽度、390px / 320px 与系统深色下的实际页面。

管理员 API：`GET /api/group-monitor`、`GET/PUT /api/group-monitor/groups/:id`、`PUT /api/group-monitor/policy`、`GET /api/group-monitor/findings`、`GET /api/group-monitor/findings/:id`、`POST /api/group-monitor/scan`、`POST /api/group-monitor/runs`、`POST /api/group-monitor/runs/:id/cancel`。所有写操作需要 CSRF，限每分钟 30 次；请求 / 异常列表支持服务端筛选分页（最多 100 条 / 页）。
