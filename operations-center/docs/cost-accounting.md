# 成本分析操作与统计口径

成本分析仅有“消费毛利”和“现金收支”，无需核验期初、分类旧账或设置核算起点。默认资金时区当月一日至今天，趋势按日；可选上月、本年、自定义日期和日 / 周 / 月 / 年粒度。每日明细固定按日分页，长说明默认折叠。

## 消费毛利

| 指标 | 来源 |
| --- | --- |
| 主站消费 | `usage_logs.actual_cost`，排除 `user_id=1`，包含余额、赠送和订阅使用，保留已删除用户历史 |
| 供应商实际消费 | 启用定时检查的供应商账号日汇总，包含账号全部 Key，按该日历史倍率及有效汇率折 CNY |
| 消费毛利 | 主站消费减供应商实际消费 |
| 消费毛利率 | 合计毛利除以合计主站消费，不平均每日百分比；分母不大于零时为空 |
| 本期充值额度 | 已使用 `balance` / `admin_balance` 的带符号 `value`，按 `used_at` 资金日筛选，排除 ID 1 |
| 当前用户余额 | 当前未删除、非 ID 1 用户的 `balance` 合计，附快照时间；不是所选期间期末余额 |
| 当前上游余额 | 监控最新启用账号快照、原币余额及已有倍率折算估值；不保证等于可退现金 |

点击四张指标卡可查看每日数据；日详情查看各供应商实际消费及来源状态。下方可切“每日明细 / 供应商汇总”，供应商行可直接记支出。充值额度支持用户分页、搜索及逐条兑换下钻，余额支持用户分页、搜索。

充值额度不是现金收入，订阅用量也不是订阅售价。用户余额、供应商充值和其他手工收支均不加减消费毛利；服务器、域名、人工等费用尚未计入毛利。因此页面不将该指标称为经营净利润。

缺主站明细、上游成本或历史折算依据时，相应金额和整期毛利为空，同时展示标明天数的完整日期小计；已取得的单家供应商金额保留。认证、连接、限流或历史缺口显示来源状态，后台重试，不生成逐笔财务核验待办。辅助充值 / 余额独立加载，失败不会遮挡消费统计。

## 现金收支

四张卡片依次为本期现金收入、本期现金支出、净现金流、累计净结余。前三张按所选日期和原币种；列表支持收支、来源、搜索及分页，这些列表筛选不改变期间合计。现金趋势与卡片使用同一来源。

| 来源 | 现金处理 |
| --- | --- |
| 线上余额充值和订阅付款 | 有 `paid_at` 的已付款订单按 `pay_amount`、唯一订单 ID 和原币种计收入，排除 ID 1 |
| 已付款尚未兑换 / 履约失败 | 原已收款仍计收入，是否已生成兑换不影响实际收款 |
| 退款申请、处理中或失败 | 原已收款保留；未取得实际退款金额与事件时不凭额度推算现金支出 |
| 兑换和管理员加余额 | 只作为额度，不能与付款重复算钱；线下实收可简单记一笔 |
| 线下 / 其他收入 | 管理员记录真实已收到金额及日期，不要求核算额度池或补服务期间 |
| 供应商付款 | 从监控目录选择供应商，按实际付款日记支出；停用不抹去过去付款 |
| 自定义支出 | 服务器、域名、带宽、短信、推广、手续费、人工等按实际付款日记一次，不摊销 |
| 实际现金退款 | 沿用旧账已保存的明确实际退款；新退款可简单记现金支出，来源单号 `refund:支付订单ID` 可消除对应原退款额度的不确定性 |

净现金流 = 本期现金收入 - 本期现金支出。供应商充值是现金支出，上游实际消耗是消费成本，两种视图分别统计，不重复相减。主站 `refund_amount` 表示退款额度，不能按比例估算为实际退现金；对应实际金额缺失时相关现金净额保留未知。只有退额度而无现金退款事件的负向兑换，不自动产生现金支出。

“记一笔”选择收入 / 支出，填写项目、实际日期、金额，币种默认 CNY。支出可选供应商付款或自定义，来源单号和备注选填。支持手工记录修改、确认删除，自动来源只读；不需要期初、分类、凭证核验或分摊。未来日期拒绝保存。

提交 UUID 防重，重试保持原请求内容，保存中禁用重复提交。填写的来源单号若与已有订单、兑换关联或手工记录一致会阻止新增；同金额但无单号的独立收付不会被擅自合并。后到的自动订单若匹配已有手工来源，只计一次贡献，两条原记录均保留并注明合并原因。

保存后自动切到对应日期 / 币种并定位该记录，避免新增后被原筛选隐藏；可清空列表搜索查看全部。修改、删除立即更新期间汇总和累计净结余，审计保留操作者、时间和前后值。

## 累计净结余

`全历史累计入账 - 全历史累计支出 - 当前用户余额`。

当前余额明确只查询 `users.id <> 1 AND users.deleted_at IS NULL`，不直接修改任何余额。已删除用户发生过的收付和兑换历史仍保留，当前余额不再纳入；其他管理员 ID 按普通用户处理。

累计卡片固定 CNY，位于净现金流右侧；不受日期、趋势粒度、现金币种、记录搜索、收支或来源筛选影响。服务端聚合全历史，浏览器无需下载全历史明细。点击查看累计收入、累计支出、当前余额、结果、原币拆分和快照时间。

非 CNY 现金使用实际发生日的现金汇率，不使用供应商充值倍率或监控展示汇率。CNY 固定为 1；已有有效历史现金汇率快照沿用，缺失时从运营中心 `.env` 的可选设置读取：

```dotenv
FINANCE_CASH_EXCHANGE_RATES=[{"currency":"USD","rate":7.2,"from":"2026-01-01","to":"2026-12-31"}]
```

`rate` 是 1 单位原币兑换的 CNY；日期包含首尾，同币种区间不可重叠，省略 `to` 表示持续有效。按真实历史金额设置，修改后重启运营中心。Compose 已通过 `env_file` 读取，无需另改 Compose。只有 CNY 收支可保持默认 `[]`；原币现金流不依赖该配置。

全历史自动收款尚未同步、缺原币 / 历史现金汇率、实际退款金额或当前余额时，累计结果为空并显示原因。已知原币收支仍可查看，不把缺失当零。累计净结余是当前现金与未消费余额的比较，不表示本月经营利润。

## 历史兼容与自动运行

保留原数据卷及 `cost-ledger.json`、`daily-profit.sqlite`、`accounting.sqlite`，升级仅在原 SQLite 内创建现金来源和幂等表。旧手工收入、供应商支出、自定义费用按稳定 ID、原币和付款日期延续；旧有效非现金 / 未支付 / 重复标记与明确实际现金金额继续使用，迁移副本不再累加。旧分类、期初、政策、经营结果及审计不物理删除，新页面不再调用旧加权分摊引擎。

每日 01:00 归档昨日、今天实时、历史读本地。旧日报不受核算起点限制，不为了缺逐用户核算来源重拉整月；漏跑、历史缺口、失败退避和租约继续自动执行。每批最多三天，原作用域和日报唯一覆盖保持。日 / 周 / 月 / 年曲线均由同一每日来源合并；缺失日期断线。

现金订单和已使用余额兑换按 ID 分页、有界扫描，断点保存，后台每分钟同步并单实例合并并发。完成历史扫描前不冒充完整现金。订单、兑换保留已同步快照，源站删除后不抹去旧事实；原记录更正按原 ID 替换，不追加第二笔。页面可见时自动刷新，离开停止轮询；历史同步期间今天仍至少每分钟读取一次实时消费。源记录在首次同步前已清理的历史无法恢复。

本轮只需更新运营中心，无新增运行依赖。沿用主站只读连接、资金时区、监控地址和持久集成 Token。供应商监控需已支持账号每日消费与财务余额接口；Sub2API 用 `total_actual_cost`，New API 用消费 `quota / quota_per_unit`，不按 Key 日志重复相加。连接、CMD Token 和监控折算配置见 [README](../README.md#供应商同步配置)。现金汇率与上述监控汇率是两种独立配置。

SQLite 使用 WAL，备份请用一致性备份 API，或停服务后备份完整数据目录，不能只复制运行中的主库。

## API 与验证

所有新接口沿用运营中心管理员会话，写入需 CSRF，现金接口为 `no-store`：

- `GET /api/cost-analysis/daily-profit`：自动消费、归档、完整日期小计及趋势。
- `GET /api/cost-analysis/automatic-income/users` 和 `/users/:userKey/records`：持久兑换来源下钻。
- `GET /api/cost-analysis/cash/report`：原币期间汇总、趋势、筛选分页及独立全历史累计。
- `GET /api/cost-analysis/cash/balances`、`/provider-balances`：独立当前快照。
- `GET /api/cost-analysis/cash/records/:key`：只读原记录和变更历史。
- `POST /api/cost-analysis/cash/records`、`PUT /records/:key`、`DELETE /records/:key`：简单记账；自动记录禁止改删，手工删除留审计。

旧 `/accounting/*` 和旧收支 API 为兼容与历史保留，不用于新页面核算。运行 `npm test`、`npm run check`；`npm run preview:accounting` 启动本地模拟主站 / 上游及真实 SQLite、PostgreSQL 兼容读源预览。`npm run check:accounting-ui` 需要 Playwright，支持 `PLAYWRIGHT_MODULE_PATH`、`PLAYWRIGHT_CHROMIUM_EXECUTABLE`，验证桌面、390px、320px 和系统深色偏好下的交互、图表与布局；不连接生产。
