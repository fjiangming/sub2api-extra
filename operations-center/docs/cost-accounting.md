# 经营核算操作与口径

成本分析分为经营分析、现金收支、余额与核对，默认本月截至今天、按日展示。经营金额统一 CNY，日期按 `FINANCE_TIMEZONE`；可选上月、本年、自定义范围和日 / 周 / 月 / 年趋势，日明细固定按日。长说明默认折叠。

## 收入、成本与利润

| 指标 | 核算规则 |
| --- | --- |
| 用户消费额度 | 主站 `usage_logs.actual_cost`，排除 ID 1，保留已删除用户历史；仅作额度参考 |
| 付费余额消费收入 | 按每位用户额度池中的未确认实收价值，以每日加权平均分配至余额实际消费 |
| 订阅收入 | 核验支付实收和实际服务期间后按自然日分摊，不用订阅消费额度充当售价 |
| 其他确认收入 | 已交付服务按所属期间分摊，已消费服务退款冲减收入 |
| 本期确认收入 | 付费余额消费收入 + 订阅分摊 + 其他已履约收入 - 对应退款 |
| 供应商实际成本 | 启用定时检查的供应商账号日汇总，经已确认历史充值倍率及汇率折算 |
| 其他运营费用 | 服务器、域名、手续费、推广、人工 / 外包等按所属期间分摊，未付款费用也可确认 |
| 服务毛利 | 确认收入 - 供应商实际成本 |
| 本期经营利润 | 确认收入 - 供应商实际成本 - 其他运营费用 |
| 经营利润率 | 经营利润 / 确认收入；确认收入不大于零时留空 |

实付 100 获得 120 额度，消耗 60 确认 50 收入；其余 50 留待后续消费确认并跨月延续。当天已核验入账先并入用户额度池，再分配当天消费。赠送 / 排除的测试额度不创造收入，对应真实上游费用仍计成本。管理员不产生客户消费收入，但其调用产生的上游成本仍保留。

订阅续费可能叠加原服务期间，不能盲目用支付日期加套餐天数推断服务期；在抽屉确认原售价和起止日期。免费订阅可补录零售价服务记录并附证据。费用与订阅按自然日分摊，8 位金额最小单位的余数依次分配至前几日，合计严格等于原金额。

趋势、日表、指标共用经营日报。点击指标和日详情可看用户消费、供应商拆分、费用与收入分摊、关联记录和问题。缺少确认收入、费用归属、用量覆盖或供应商成本时，相关金额和完整利润为待核验；已核验日期小计明确标注天数，利润率按合计金额计算。

## 现金与额度

实收取真实 `payment_orders.pay_amount + paid_at`、已核验线下收款和其他实际收款；退款取核验的实际退现金额；现金支出取实际付款日的供应商充值和费用。净现金流 = 实收 - 退款 - 现金支出，不能与消费收入相加。

“自动额度入账”取已使用 `balance` / `admin_balance` 的带符号 `value`，不再称现金收入。并发、订阅、邀请等兑换值不是金额，不纳入。管理员加余额可能为线下充值、赠送或纠错，必须分类。

在线支付通过同一用户及唯一非空 `recharge_code` 关联额度，现金仅计支付一次。线下收款可直接分类原兑换记录，或新增收款并关联 `redeem:记录ID`，只能选一种；重复关联会被拒绝。旧手工收款已与新来源重复时，分类为“关联已有业务”并选择已确认收款，保留凭据而不再计钱，不按金额 / 日期相似擅自去重。

直接确认兑换收款后不能再次关联手工收款，已有手工关联的兑换也不能再次直接确认。若同步后才发现对应线上支付，先前关联的手工收款会转为待核验，需将其改为关联线上订单的重复凭证，处理前不输出完整实收合计或利润。

自动额度卡片保留“用户分页 / 搜索 → 每条兑换记录分页”下钻，范围与返回状态保留。来源已同步后删除用户或源兑换记录，不自动抹去运营中心原记录；尚未同步且已在源站删除的历史不能恢复。

## 核对与记账

首次启用的核算起点为资金时区本月一日，可在折叠设置中修改。起点前已有用户必须据证据逐个确认期初额度及其中待确认实收价值，即使为零也需核验；明确在起点后创建的用户按零期初开始。不能把当前余额当作过去期初，未知创建时间或已删除身份也不擅自认定零期初。

初始余额、首次绑定赠送、邀请返利转余额可能没有兑换记录，需要补录赠送或额度纠错，不能创造现金收入。当日会比较核算余额与主站快照，不一致时提示核对。历史没有精确时点快照时，期初 / 期末显示不可回溯；当前用户余额、删除账户残留余额和上游预付估值单独展示，均不扣减本期利润。

“记一笔”默认 CNY，外币必须明确“1 单位原币折合多少 CNY”，保留原币金额与核验汇率。类型决定统计作用：

| 类型 | 填写与作用 |
| --- | --- |
| 供应商充值 | 从监控目录选供应商，填实付金额和付款日；只计现金支出，实际使用才计成本 |
| 运营费用 | 分类、金额、所属起止日、付款状态及付款日；按所属期间分摊，不重复计上游充值 |
| 客户充值收款 | 同一用户的正向额度记录及实际收款，消费后确认收入 |
| 订阅 / 其他经营收入 | 原售价、服务期间及依据，按自然日确认；其他收入支持应收未收 |
| 赠送 / 余额纠错 | 用户、实际额度变动；纠错另填待确认实收价值调整，支持负数，不调整主站余额 |
| 未消费余额退款 | 原收款、用户、正数退回额度及实际退款，冲预收价值 |
| 已消费服务退款 | 原收款及实际退款，在退款日冲确认收入 |
| 订阅终止退款 | 原订阅、停止服务日、退款及其中已履约退款 CNY；停止日起不再分摊未来服务 |
| 关联已有业务 / 排除 | 说明重复或测试依据，保留审计，不重复计现金和收入 |

退款必须关联已确认原收款，累计不超过原实收。主站 `refund_amount` 可能是额度金额，不直接当作实退现金，自动退款先待核验。主站若已有负向兑换调整，关联该负向记录且退回额度须等于其绝对值，避免重复减额度。订阅终止退款须对平原剩余未履约价值加已履约退款；特殊补偿、换套餐、暂停等需按真实合同修正期间及记录，不无依据自动推断。

新建 UUID 保证重试不重复记账。保存后展示对应现金台账，日期落在筛选外会自动切至该日。核对、排除和修改起点保存操作者、原因、时间与前后值；修正通过审计分类完成，不物理删除原凭据。

## 持久化、升级与性能

沿用资金时区每天 01:00 归档昨日、当日实时、历史直接读取的架构。`daily-profit.sqlite` 新增逐用户 / 计费类型来源快照，首次升级旧日报没有这些来源时后台补算，不阻塞页面等待整月。主站用只读一致性快照读取，明细完整性仍按 `SUB2API_TIMEZONE` 原生日桶核验，跨时区需覆盖相交的全部用量日。

新增 `accounting.sqlite` 保存原始来源、分类、期初、规则、每日经营结果及审计，按主站与资金时区隔离。旧 `cost-ledger.json` 原样保留，导入待分类，不能根据旧供应商标签擅自认定现金或费用。分类改变后从受影响日期起重新分配已归档来源，不重新查询上游；手动刷新只将所选范围历史上游日报排队重算。

后台每批最多三天，失败退避、租约 / 版本防止重复执行及旧任务覆盖。漏跑补排，零点至一点昨日等待归档，未来不查询。历史保留统计时的供应商范围及成本，配置修改后须明确重算。上游不可用时仍可归档主站来源，成本和利润待核验并重试。已清理且尚未保存的逐用户历史无法恢复；重算不能伪造来源。

需配套更新运营中心和供应商监控，保留原数据卷，无新环境变量或生产依赖。沿用 `PROVIDER_MONITOR_BASE_URL`、集成 Token、主站只读连接及资金时区；CMD 生成 Token、内部地址与域名配置见 [README](../README.md#供应商同步配置)。无人值守推荐持久集成 Token，浏览器短期 SSO 不保证凌晨有效。

余额读取 `GET /api/integrations/financial-balances` 或管理员 `/api/financial-balances`，只读最新账号快照，不读 Key 余额、不发起上游同步。仅纳入启用供应商，超过一小时、重复账号、无限余额、缺倍率 / 汇率时总额未知。当前余额按快照时倍率估值，不承诺是实际可退款现金。

日成本维持单日 `from=to`、`source=upstream_daily_summary`、`scope=account`、`providerFilter=scheduled_enabled` 契约。Sub2API 读取 `total_actual_cost`，New API 读取消费 `quota / quota_per_unit`，不使用标价或 RPM。账号包含全部 Key，建议专供主站。覆盖完整且 CNY 折算系数相同的历史段可合并，真正变倍率或缺历史仍未知。

汇率仍在供应商监控“设置与备份 → 运行设置 → 汇率（JSON）”填写，表示每单位原币等于多少显示币种。若上游 USD 标签实际按人民币 1:1 充值，可明确 `{ "USD": 1, "CNY": 1 }`，优惠倍率另算。详细连接 / 汇率 / 版本排查见 [README](../README.md#每日供应商消费不可用的排查)。

SQLite 使用 WAL，备份须使用 SQLite 一致性备份 API，或停服务后备份完整数据目录，不能只复制正在运行的主库文件。

## API 与验证

所有 `/api/cost-analysis/accounting/*` 接口要求管理员会话及 `no-store`，写操作还需 CSRF：`GET /report`；`GET /documents` 及 `/documents/:key`；`POST /documents`；`PUT /documents/:key`、`/opening`、`/policy`；`GET /credits/users` 及 `/credits/users/:userKey/records`。主站来源身份和原支付金额不能改写。

旧成本 / 收支 / 日差额 API 保留兼容，旧“利润减当前余额”不用于新版页面。执行 `npm test`、`npm run check`；`npm run preview:accounting` 启动仅本地、模拟用户和供应商的真实接口预览；`npm run check:accounting-ui` 验证桌面 / 390px / 320px，需要本地 Playwright，可用 `PLAYWRIGHT_MODULE_PATH` 和 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定安装位置。
