## 建议修复范围

1. 明细区分“已获取分组金额”和“完整可比状态”，有金额时明确展示已知金额 / 陈旧或待核验标记；来源不完整时完整合计和差额仍保留未知。
2. 将历史零用量 Key 的金额核验与发生时分组归属分开，避免无历史分组证据的闲置 Key 连带隐藏其他已核验分组；不使用当前目录倒推旧日关系。
3. 为缺少发生时 `group_id` 的兼容上游增加受限的真实分组统计读取，保留原期限、覆盖检查、统计截点和迟到保护，不直接用当前 `api_key.group_id` 分配全天消费。
4. 对已归档金额冲突返回明确状态与原因，保留旧值和后续证据，避免无说明的永久覆盖失败；历史数据修复另行核对，不自动覆盖已确认金额。
