# CSV 补记与用户扣费

入口：运营中心 → 计费核查 → CSV 补记。本功能导入上游的逐请求最终账单，将缺失请求归属到主站用户，先展示扣费预览，管理员确认后补记原生使用记录并结算。导入、匹配、预览均不扣费；不调用余额管理接口，不重发推理。

## 使用步骤

1. 选择上游 CSV 和编码，导入批次。支持 UTF-8（含 BOM）及 GB18030；可展开字段映射，对无法自动识别的表头手动指定。已导入的同一份内容会回到已有批次。
2. 将 CSV 的每个上游 Key 名映射到对应的 Sub2API 上游账号。Key 名不是下游用户，空 Key 名也必须单独映射，不能自动归到其他 Key。映射依据应是导出时实际使用该 Key 的账号。
3. 核对时区、时间含义、时钟修正和输入是否包含缓存，再点击“自动匹配用户”。默认 Asia/Shanghai、自动核对时间含义、5 秒容差。自动模式按每个 Key 的完整原生用量证据校准，至少 3 个有区分度的独立样本、90% 以上一致才判断开始 / 结束；没有足够证据须手动指定。显式设置与证据冲突时阻止时间补记。时间本身有偏移时先改时钟修正，不要只放大容差。
4. 查看本地用户 ID、邮箱、API Key、分组、上游账号、来源、开始时间及差值。“可补记 / 待确认”只列原生来源可预留的请求；“已定位用户 / 请求待核查”单列文件日志归属或同用户多次并发；“有记录 / 扣费待核查”单列已有用量但扣费未确认。多个候选必须明确选择并填写核对依据；只有文件日志或仍不能确定具体请求时不生成扣费预览。
5. 核实 CSV 是最终计费用量。使用请求当时冻结的核心售价报价；没有快照时填写模型的历史售卖单价（USD / 百万 Token）、售卖倍率、历史账号倍率和依据。缺失缓存明细必须明确核实为零；有缓存创建总数、没有时长拆分时必须核定 5 分钟 / 1 小时归属。不要直接复制上游倍率或支出。
6. 选中记录，生成扣费预览。逐笔显示用户、计费类型、Token、费用和“上游多扣余额差额”，下方按本页所选记录及用户分别汇总上游支出、本站拟补记和差额。差额为 CSV 上游实际支出减本站拟补扣金额：正数表示上游支出更高，负数显示“本站拟多收”，不表示已经收回资金或证明供应商错扣。订阅表示增加订阅历史用量，单列上游成本，不计入余额差额。缺失、负值、非 USD 或格式无法识别的上游费用保留未知；费用不完整时仅汇总已知支出，合计差额显示未知。金额按 8 位小数比较和汇总，不再乘上游或账号倍率。更改归属或价格后需重新生成预览；更改匹配配置后需重新匹配。
7. 勾选确认所选用户、用量和金额，再点击“确认补记并扣费”。处理结果保留核心案件 ID 和回执。若连接中断，重新打开同一批次，按原预览续办；不要另建一笔裸余额扣款。

每次预览 / 确认最多 20 笔。批次可筛选、分页，确认一页后继续下一页；每笔由原生事务单独提交，批次可能部分成功，失败记录与成功回执分别保留。已经开始确认的批次冻结匹配配置，失败记录保留原预览，避免途中改价或改用户；需要修订已保留的核心使用记录时，从“异常请求”按案件 ID 核查处理。

历史快照按请求独立报价，包含该次用户 / 分组倍率。手工价格表按模型应用到本次所选行，不会自动猜测不同用户、分组或时期的折扣。历史售价不同的行须分开选取、分别定价生成预览，再核对各自保存的倍率和金额后确认；不能以当前价格或同模型的另一位用户价格覆盖全部旧账。已保存的逐行预览可保留不同价格。

## 匹配依据

| 本地来源 | 处理 |
| --- | --- |
| fork 的持久化 dispatch 意图 | 优先使用；保留实际尝试的用户 / Key / 账号与历史价格快照 |
| 原版 `ops_error_logs` | 使用原生用户 / Key / 账号 / 分组归属；原生错误通常在结束时写入，用 `created_at - response_latency_ms` 还原开始时间 |
| 错误中的 `upstream_errors` | 区分不同上游尝试；多次尝试或缺耗时的记录保留不确定时间区间，单靠宽泛区间不能选定扣费请求 |
| 原生 `usage_logs` | 优先用同账号 / 模型、四类完整 Token 和时间排除已有用量；再检查原生扣费防重热表 / 归档或恢复案件 settled 状态。仅 ActualCost 非零也不冒充已核实扣费 |
| 主站结构化文件日志（可选只读挂载） | 通过服务端 request_id 关联用户 / Key / 分组、唯一账号选择及访问结束记录，找回被取消忽略策略排除的历史归属；可补全对应原生错误的开始时间 |

匹配先核对已有原生完整用量和请求 ID，再在尚未占用的本地来源中按账号、模型和开始时间查找。排除已有用量时同时检查开始 / 结束两种时间含义，避免表单设置错误把已付费请求匹配到另一个未付费意图。已验证对应 CSV 的本地记录不再污染其他行的候选；一笔本地记录被多条不同账单争用时保留冲突，不能把一笔扣费算成多笔。ID 与 Token 证据矛盾也转核查。

精确开始时间候选优先于无耗时的四小时区间；宽泛区间只显示时间证据不足。相同用户 / Key / 分组的多个 dispatch 可展示一致的用户归属，但不自动选定具体请求；跨用户、Key 或分组继续显示冲突。客户端可能重复的 ID 不当作自动扣费授权。即使只有一个时间候选，也要确认时间归属，不能按最近的一条静默选用户。

同一持久意图与其原生错误 / 使用记录会合并来源；多个真实 dispatch 仍保留独立候选。CSV 的完全重复行保守标记，不自行当作两笔独立消费。字段不全、非法计数、超过查询上限、源查询失败或候选超过 30 个时不生成可扣费预览。时间、模型或 Token 相似都不构成用户归属的保证。

### Lingsu 的例子

现有导出表头含 `Time`、`API Key Name`、`Model`、四类 Token、`Duration (ms)`、`Billed Cost` 等，可以直接识别。2026-10-23 这份导出的 `Time` 经原生用量验证为请求结束时间，不能设为开始时间。将 `ccmax-key` 映射到主站对应上游账号，选择自动核对或结束时间，再用 `Time - Duration` 与本地开始时间生成候选。

上游耗时 174 秒、本地错误耗时 125 秒可以是同一次调用；比较的是开始时间，不能要求两边结束时间相同。CSV 的最终 Token 可补足 CDN 超时后本站没收到的部分，但前提是能核对归属和最终账单。此流程无需 Lingsu 提供逐条日志 API，也不会主动读取供应商监控；CSV 替代了上游用量输入，供应商监控的原有后台查单继续独立运行。

旧版可能忽略客户端取消错误、异步日志队列丢弃、或按保留策略清理日志。若文件日志仍有完整关联元数据，可找回部分用户归属；只有文件日志的记录在现有核心导入契约中没有可预留的原生来源，仍不能点击确认扣费，不会往错误表写伪造记录。CSV 本身只包含上游 Key 名且所有归属证据都已丢失时无法恢复用户。无候选不代表“无人使用”，也不能按比例向其他用户分摊费用。

### 可选文件日志读取

部署时可在运营中心已有容器增加只读卷，并显式传入环境变量。例如现有服务器路径对应的增量为：

```yaml
services:
  operations-center:
    environment:
      OPERATIONS_CENTER_BILLING_LOG_DIR: /app/sub2api-logs
    volumes:
      - /root/sub2api-deploy/data/logs:/app/sub2api-logs:ro
```

合并到现有 Compose，不覆盖已有 environment / volumes；容器非 root 用户须有读取权限。未配置时仍能用原生数据库 / 恢复案件匹配，界面明确提示没有文件日志；显式配置但不可读则整次匹配失败。只读角色还需现有 `usage_billing_dedup` 和 `usage_billing_dedup_archive` 的 SELECT 权限，缺表时显示扣费未核实，权限错误不降级成已收费。

仅读取目录内 `sub2api*.log` / `.log.gz` 常规文件，不递归、不跟随文件符号链接。单次最多 128 个文件、解压后 1 GiB、600000 个窗口内事件、单行 64 KiB，超限或 gzip 损坏停止匹配。日志只提取允许的时间 / ID / 归属 / 模型 / 状态元数据，不保存正文或错误明文；日志轮转、缺行和未挂载均不能当作全量覆盖证明。这是本地代码提供的可选接入，尚未修改服务器挂载或权限。

CSV 可以没有请求 ID，但用于补记的原生错误日志至少须保留本地请求 / 客户端关联 ID 或原生上游尝试 ID，供核心排除已有账单和持久意图。所有本地关联 ID 均丢失的错误只展示候选，阻止 CSV 确认扣费；不能用 CSV 自带的一个 ID 冒充本地关联证据。

## 价格和资金语义

核心的冻结快照优先，报价只读；手工价格必须对应请求发生时的售卖规则。金额使用十进制计算并按原生 8 位小数量化，最终 ActualCost 由主站按 TotalCost × RateMultiplier 核定。账号倍率用于账号成本 / 限额，不额外乘进用户扣费。上游采购价、充值折扣、币种换算均不自动套用。

本次 CSV 批量流程覆盖标准 Token 计费。图片、视频、音频、工具收费、特殊 tier / effort 和非标准金额维度不凭这些列推算，应使用“异常请求”的原生维度核查流程。已有记录但少计的请求不通过 CSV 再收整笔费用：已有持久案件的，从最后已结算节点提交最终累计用量，核心生成差额；仅有原版使用记录而没有持久案件的，保留核查结果，不伪造原账或自动补差。

如果核心快照已明确不能进行标准 Token 报价，CSV 流程阻止预览并转上述原生核查，不用一组手工 Token 单价掩盖已知的不支持维度。

确认依次执行：核心预留导入来源 → 保存历史使用记录为 review → 审核为 prepared → 原生 Apply 事务写 `usage_logs`、dedup 和资金效果。仅预留导入来源不会产生使用记录或资金变化。原生服务与运营中心重试都依靠相同核心案件与原生幂等键，回包丢失后先重读结算状态，不新增第二笔消费。

## 防重、持久化和边界

- 同内容文件回到同一批次；每行保存稳定的上游身份摘要。调整时区、时钟或输入缓存解释不会改变其摘要。无请求 ID 的指纹无法识别供应商重新改写时间、模型、Key 名或 Token 后的账单，因此还要依赖本地请求预留和人工核查，不能声称任意 CSV 变体都能全局去重。
- PostgreSQL `sub2api_custom.billing_import_claims` 同时唯一约束上游账号 + 上游账单身份、本地请求来源，绑定预览摘要。重复导出、跨批次和多人同时确认不能为同一来源生成第二笔补记。
- 原生使用明细已清理时，核心仍检查现存 `usage_billing_dedup` 及其长期归档；已有原生扣费键的请求拒绝再建历史案件。只有日志查不到使用明细，不能推断它从未扣费。
- SQLite 与原核查队列共库，增加 `import_batches` / `import_rows` 保存原 CSV、选项、规范化行、候选、预览和回执；不新增资金账本。确认使用版本 CAS 和 5 分钟租约，中断后可恢复；普通未确认预览 1 小时有效，已开始确认的记录按原预览续办。
- 预览前、首次确认前重新读取本地来源，已有用量、归属候选或时间证据变化时停止补扣；确认后重试继续依靠原生预留和回执恢复。旧匹配算法和旧预览不能直接结算，未结算批次应重新自动匹配；旧版已开始确认的批次须先核实核心预留 / 回执，不能另导一份规避冻结。
- 原生日志查询只取归属、模型、时间、计数和关联 ID；不读取提示词、响应正文或日志明文错误详情。导入文件自身原样保留在管理员数据目录，备份须保护 CSV 中的用户 / IP 等信息。
- 每批最大 8 MiB、20,000 行、100 列、单行 64 KiB，时间跨度最多 31 天、最多 20 个上游 Key 映射。每类原生源及持久案件最多 20,000 条，超过即停止并要求缩小范围；时间容差 1–120 秒、时钟修正 ±300 秒。
- 历史请求必须超过独立处理期限加 60 秒。正常意图还须最近一分钟无更新；新建的历史错误案件只豁免其新 staging 时间，不豁免原请求的保护期限。已删除用户 / Key / 账号、历史订阅不唯一或归属不一致时核心拒绝补记。

需要配套更新主站 fork 和运营中心，主站启动执行新增 custom 迁移，原有使用记录与资金数据保留。仅做 CSV 导入无需新增机器、定时任务或供应商 API 凭据。数据与配置继续按[更新手册](billing-recovery-update.md)备份到同一专用目录；当前本地实现不代表生产已经部署。

## 本地验证

运行 `npm test`、`npm run check`。`node scripts/billing-import-replay.cjs <外部审计目录>` 可回放此前保存的 `import-rows.json`、`sources.json`、`billing-evidence.ndjson`、`access-events.json` 及两份匹配基线；核对旧误报、已有原生用量和文件日志归属，仅读本地文件、不连接生产、不预留或扣费。真实证据不纳入 Git。`npm run preview:billing-import` 启动只绑定 127.0.0.1 的隔离演示（默认 19876，端口占用则递增），输出可直接访问的 `/preview` 地址；只使用模拟用户与结算状态，不连接真实数据库或上游，`/sample.csv` 提供示例文件。

已有 Playwright 环境可运行 `npm run check:billing-import-ui`；支持 `PLAYWRIGHT_MODULE_PATH` 指定外部包、`PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定兼容浏览器、`BILLING_IMPORT_QA_DIR` 指定截图目录。脚本自动创建、关闭隔离演示，验证 1440px / 390px 的导入、匹配、预览、确认、刷新恢复、筛选和布局；没有将浏览器依赖加进生产镜像。
