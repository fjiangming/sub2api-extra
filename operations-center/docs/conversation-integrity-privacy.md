# 对话日志完整性与敏感信息评估

本轮遵循用户明确优先级：正常对话第一，归档第二。不能以等待归档、延迟流式返回、让推理报错或重发模型请求来换取日志完整。以下描述的是本地实现及验证边界，源码变更不会自动操作生产服务器。

2026-11-18 用户明确要求输出时避免因脱敏不可用丢弃整条记录：JSONL 下载及 Webhook / S3 默认优先有效脱敏，不可用时回退保留原文并标记实际来源与原因，可能含未替换敏感信息。以下引擎说明中“禁止含警告的脱敏副本推送”仍指该副本不能冒充检查完整的数据，不再表示整条记录都跳过；最新输出规则见文末与[JSONL 接入](conversation-jsonl-push.md)。排除规则、原文也缺失、传输范围和保留期边界不变。

## 完整性检查

| 环节 / 配置 | 原影响 | 当前处理及剩余边界 |
| --- | --- | --- |
| 单条 Request + Response 上限 | 默认累计 8 MiB，最多 16 MiB，保存前缀 | 新采集器取消该截断，UI 移除输入；旧策略字段只供旧采集器兼容，旧主站仍需升级 |
| WebSocket 帧数 / 持续时间 | 10,000 帧和 24 小时边界 | 取消固定帧数截断及持续时间钳制，帧正文及元数据纳入全局预算 |
| 接收正文 | 单个 base64 24M 字符、合计 32 MiB、JSON 48 MiB | 接收侧改为覆盖采集器预算及 WS 两侧别名的安全边界，HTTP envelope 272 MiB；越界明确拒收，绝不截断后标完整 |
| 全局观察内存 | 64 MiB，多并发共享 | 保留；任何单条或并发耗尽预算时整次放弃，释放正文并累计非身份丢弃。大于可用预算的单条本身也无法归档 |
| 队列 / 进程 | 队列 32，进程退出会丢失 | 保留有界队列，满则整次放弃；无原文磁盘 spool、跨重启恢复或退出强制排空，不承诺无损审计 |
| 独立归档处理 | 大正文脱敏阻塞运营中心主线程 | 接收与处理两个受限进程；原文事务提交后 ACK，再由持久待办后台处理，单进程各一项工作。接收忙 / 内存不足 / 落库前故障仍可整条跳过；已落库处理失败保留原文，不回退主线程或伪造完整 |
| 独立归档读取 | 大正文表汇总 / 正文解密阻塞主 API，策略过期会跳过采集 | 紧凑元数据、独立低优先级受限进程、有界队列 / 期限 / 内存，查询失败不回退主线程；历史索引逐条后台准备且明确显示不完整进度，原始密文不变。共享资源仍有成本 |
| 策略服务 | 请求路径同步 HTTP，最多等待 200ms | 后台每秒刷新，3 秒有效期；异常 / 过期 / 启动预热跳过采集，发送及入库复核当前用户 / 模型 |
| 发送 / 回执 | 单次发送，HTTP 200 不验证是否入库 | 最多三次同 ID 后台投递，失败退避 500ms / 2s；每次 2 秒，仅新持久接收协商为 5 秒；验证原事务提交后的 ID 和原文字节 / 帧元数据 SHA-256；网络失败仍可丢弃，绝不补发推理 |
| 磁盘 / 总容量 / 预留 | 可淘汰历史或只存缺正文的元数据 | 预检和写入结果均核对，空间不足整次拒收、保留历史；不再执行容量 evict。实际 IO 错误无成功回执 |
| 保留期 | 默认 7 天，定时清理历史及待推送引用 | 新增 0 为永久；升级保留旧设置，非 0 仍会清理。生产现有 30 GiB 等设置未被本地修改 |
| 断流 / 提前关闭 | 只取得部分实际字节 | 明确终态 / HTTP 错误关闭时最多两条后台补读，各 1s 总计 / 200ms 空闲，同池新请求立即抢占；普通在途观察最多后台收尾 250ms。失败响应也可完整保存；真实读取错误不被终态覆盖，保留收到部分并标不完整，不推送部分记录；无法恢复未到达字节 |
| 解压 / 脱敏资源 | 解压上限或处理异常导致正文缺失 | 原文保持原字节；解压输出上限 256 MiB 或处理失败时保留加密原文，单独标异常，无半成品脱敏副本 |
| 排除用户 / 模型 / 保存开关 | 有意不记录某些请求 | 保留双端门禁，未知模型不落盘；同一会话可能有意缺少这些轮次 |
| 会话标识 / 分页 / 页面预览 | 未提供 session-id 无法关联；预览看似截断 | 不猜测关联；列表分页 / 前 64K 文本只限制显示，复制、完整查看、下载均读取完整已保存字节 |
| 推送 / JSONL 下载 | 原先对不可用脱敏副本直接跳过 | 按用户最新要求优先有效脱敏，脱敏异常、缺失、未检查或过期时回退保留原文，实际来源和原因明确标注；用户 / 模型排除及显式传输范围仍复核，不将原文冒充脱敏 |

64 MiB 只是观察内存预算，不含后台组装、JSON/base64、加密和发送临时分配；实现仍有 CPU / GC 开销，并非零开销监听。采集 URL 经反向代理时，代理自己的请求体 / 超时限制也可能拒收，应检查归档丢弃统计和服务连接状态。完整性摘要证明收到的字节一致，不证明上游响应在语义上回答完整。

## 脱敏覆盖

原实现只有邮箱、电话、常见 key 和 IPv4，且只定位 JSON 字符串；证件及金融规则没有实现，数字字段及普通 id / name 也存在遗漏。这是本次补全的具体原因。

| 类别 | 当前识别方式 | 典型内容 |
| --- | --- | --- |
| 身份证件 | 明确字段 / 标签；自由文本中国 15 / 18 位身份证校验、SSN 模式 | 身份证、护照、社保、税号、驾照、居留证、病历 / 学号等字段 |
| 金融 | 字段 / 标签；自由文本卡号校验和 IBAN 校验 | 银行卡、银行账号、路由号、IBAN、BIC / SWIFT、收款 / 支付账号、钱包地址等字段 |
| 凭据 | 字段、文字赋值、已知 token 前缀、JWT、PEM 私钥、URI 鉴权及 URL 参数 | 密码、API / 云 key、OAuth / Session Token、Cookie、OTP / PIN / CVV、连接串、私钥、签名 URL 参数 |
| 联系方式 | 邮箱、电话模式及字段 | 邮箱、手机、电话、传真 |
| 网络 | IPv4 / IPv6 模式及字段 | 客户端 / 远端 IP、带 zone 的 IPv6 |
| 设备与社交 | 字段、部分标签及 MAC 模式 | IMEI、IMSI、ICCID、广告 / 设备 ID、序列号、VIN / 车牌、微信 / QQ / 社交标识等字段 |
| 个人资料 | 字段及有限文字标签，不是任意实体识别 | 姓名、用户名、地址 / 邮编、生日、经纬度 / GPS、健康 / 生物信息等字段 |
| 自定义保密值 | 最多 50 条精确字面量替换 | 企业项目代号、内部编号、提示词中的指定字串和特殊凭据 |

JSON 字符串、敏感数字、合法内嵌 JSON、工具参数 / 结果、常见 SSE / WS 拆分文本均处理；普通工具输出保持文字，结构和消息顺序保留。协议位置的角色、模型、工具名与关联 ID 保持一致，普通客户字段不享受全局豁免。敏感数字替换为字符串占位符，其余数值拼写、空白、未知字段和原文件字节保持。

相同类型和精确值使用稳定 HMAC 占位符，部分已识别结构值会同时替换负载中的引用。不同格式的手机号、姓名别名、自然语言代词及任意业务关系不自动判定为同一实体；过短或含糊的值不做无边界全文替换，避免破坏普通文字。自定义替换也可能改变内容含义，保护字段冲突时保留原文并报错。

## 不能承诺的范围

有限规则不能穷举任意人的姓名、地址、商业秘密或所有国家 / 机构证件，也无法可靠识别任意无标签自由文本、错别字、故意拆写、未知编码、加密数据或隐写。未成年人、医疗、生物信息和财务信息中的普通自然语言没有固定格式，不能仅因规则开启就宣称全部匿名化。字段名称、协议关联字段及必要索引仍会保留，不等同于全库匿名化。

未兼容协议的 base64 媒体、外部文件引用、二进制帧、加密正文和未识别签名不能完整检查时，整次保存加密原文并报告 `UNINSPECTABLE_CONTENT` 等固定分类，不生成或默认推送脱敏副本。不会为了处理附件下载外部资源，也不调用第三方模型处理生产正文。未知自定义编码无法保证识别出来；需要按实际业务增加识别 / 文本抽取能力并独立验证。

引擎 v4 对已知协议位置的 Claude thinking / signature_delta、Gemini thoughtSignature 保留原字节并记录 `OPAQUE_SIGNATURE`；对确切 Responses reasoning.encrypted_content 原样保留并记录 `OPAQUE_ENCRYPTED_REASONING`。其余可读文本继续处理，签名和加密推理内部均未检查，含警告的副本不具有默认脱敏推送资格。任意同名字段和嵌套工具中的协议伪装不放行。非媒体普通 URL 可按组件处理；真实工具参数 / 结果里的普通业务 file_id 按身份标识一致替换，实际上传 / 媒体 / 未知位置的引用继续拦截。错误编码或其他异常仍无半成品副本，原文回退不变。

引擎 v5 进一步兼容确切 Responses 消息 / 多模态工具返回、Chat 和 Claude 消息图片，含 WS create 包装。图片字节、URL 和来源元数据原样保留，标记 `OPAQUE_IMAGE`，其他可读文字继续处理；仍保留加密原文，禁止含警告副本的 webhook / S3 / JSONL 脱敏推送。图片文字、证件、人脸、定位和隐写等内部内容均未检查，图片 URL 内的凭据也可能原样存在；此兼容只解除整条文字处理失败，不宣称图片或引用已脱敏。不做 OCR / 外部下载，不放行未知字段、工具内嵌 JSON 伪装或未知媒体。升级不自动重写历史和清除传输异常。

引擎 v6 增加确切 Responses `compaction.encrypted_content` 协议项，覆盖原请求、compact JSON 结果、output_item / 响应事件和 WS create。保持压缩值和关联 ID 原字节，标记 `OPAQUE_ENCRYPTED_COMPACTION`，可读文字继续处理。模型加密压缩上下文内部仍无法检查，副本外推继续拒绝并保留加密原文；未知路径 / 内嵌工具伪装和自定义冲突不放行。此兼容不代表能恢复已压缩前的对话文本，也不修改原传输完整性。

这些检查范围警告不代表正文漏存，重复运行相同规则无法 OCR 图片或解密厂商上下文。当前引擎 / 规则已处理成功的记录不再允许无效重复处理，真实失败或规则更新可再次处理；原文、检查范围和外推门禁仍保留。可选传输诊断只接受固定枚举和字节计数，不存原始错误信息；错误返回时已经开始关闭只是顺序证据，不能据此认定日志完整或自动消除 read_error。旧日志缺少这些信息不做推测性修复。

Claude tool_result 内的图片只在原生 user 消息、有字符串 tool_use_id 和确切嵌套图片路径时兼容，仍标记图片内部未检查。完成检查 v2 兼容 JSON 协议标记下的真实 SSE，派生证据不改写原始传输状态；旧仅脱敏记录的重新核验只能说明现存副本，不能重建原文字节。原文摘要一致只证明收到的采集字节与保存一致，不能证明上游或用户端全部收齐。

运营中心的完成事件检查只提供应用层证据，不覆盖原始采集完整性、不补回丢失字节、不放宽推送门禁；从旧脱敏副本得到的证据明确标注来源。历史兼容检查须管理员显式启动，在独立低优先级进程限速执行，策略变更 / 取消会阻止未提交结果写入；内存、空间和忙锁保护均保留。缓存预算兼容不代表可以无限占用内存，资源不足仍保留原文或跳过新归档，正常对话继续优先。

原文含敏感信息，AES-GCM 加密并不等于脱敏，管理员仍可读取。仅脱敏模式在处理异常或仍有未检查内容时保留临时加密原文，这是异常回退及后续重处理的来源；只有成功且不含未检查内容时才移除临时原文。按用户最新要求，下载及 Webhook / S3 JSON / JSONL 默认“脱敏优先（不可用则原文）”，含协议签名、加密推理或图片警告的记录也可回退到保留原文，不能据“处理异常”消失或请求了 masked 就推断匿名化。实际原文行 `source=original`，回退还带 `requested_source=masked`、`fallback_reason`；页面及预览说明可能发送未替换敏感信息。显式选择原文也会把完整原始敏感信息交给接收方，两者均不能称为已脱敏。原文也不存在、排除或超出筛选的内容无法恢复，不能承诺整个会话必然完整。签名保留也不表示修改后的文本能通过厂商校验，原文仍是完整协议字节的来源。

PEM 私钥按成对标记线性定位，不以原有 32K 文本匹配上限漏过长私钥；发现起始标记而没有对应结尾时报告 `INCOMPLETE_PRIVATE_KEY` 并保留加密原文，不将不完整私钥当作已完成脱敏。

旧副本不自动获得新引擎资格。双副本有原文可重新处理；旧“仅脱敏”且无原文的记录无法重新识别已被原规则遗漏的所有值，旧缺失正文也不可恢复。需要按新策略重新采集后续对话，不能将这次修改描述为历史资料已经全部脱敏。
