# 成本分析页面改版方案

现行方案：用户于 2026-11-02 确认的[自动统计与简洁现金收支方案](cost-analysis-automatic-plan.md)已实现，仅消费毛利和现金收支两个视图，新增不受筛选影响的累计净结余。下文作为上一版设计归档，精细核算、分类和期初入口已移除；最新操作见[成本分析操作与统计口径](cost-accounting.md)，本轮未部署。

历史状态：本文件的四视图版本已由上述两视图方案替代。原来源、分类、期初和审计仍保存在数据卷中，旧 API 兼容保留；新版页面不再运行这些手工核算流程。

## 设计目标

把现金收付、额度变化和服务收入确认分别展示，让运营人员能够回答：本期赚了多少、钱收付了多少、还有多少预收余额未履约、哪些数据需要复核。默认当前月份至今天，趋势粒度按日，经营报表以 CNY 展示，时间边界统一使用资金时区。

保留现有运营中心模块、供应商监控集成、自动入账用户分页及兑换记录下钻。长篇口径说明默认折叠；首屏只突出当前视图的四个核心指标、趋势和明细，避免重复堆放汇总表。

## 页面布局

公共顶部：日期范围、快捷范围（本月、上月、本年、自定义）、统计粒度（日、周、月、年）、刷新、记一笔。日期筛选在四个视图间保留；粒度只控制趋势，日明细固定按日。

二级导航：自动统计（默认）、精细核算、现金收支、余额与核对。

### 自动统计

首屏四项指标为主站消费、供应商实际消费、消费毛利及毛利率，辅助行独立展示充值额度与当前余额。消费毛利 = 非 ID 1 用户主站实际消费 - 启用供应商实际日消费，不再从利润扣当前余额或重复扣手工供应商充值。充值额度支持用户列表搜索、分页和兑换记录下钻。

趋势与日表共用原有日汇总及历史归档，不受精细核算起点限制。打开即可读取，不要求操作期初或旧分类；这些要求只影响精细核算。充值与余额查询失败不遮挡主统计，真实用量 / 成本缺失仍留空并保留原因和重试。包含赠送、订阅产生的消费额度，名称明确为消费毛利，避免误称现金利润。

### 精细核算

1. 四项核心指标：本期确认收入、供应商实际成本、其他运营费用、本期经营利润。经营利润卡片同时展示经营利润率；点击指标进入同范围明细。
2. 简洁辅助行：用户消费额度、服务毛利、已核验天数。消费额度和确认收入分开命名。
3. 经营趋势：确认收入、供应商实际成本、经营利润；运营费用可通过图例打开。趋势和列表读取同一日报，支持日、周、月、年归并。
4. 每日经营明细：日期、用户消费额度、确认收入、供应商实际成本、其他费用、经营利润、利润率、数据状态、详情。底部合计利润率使用合计利润除以合计确认收入，分母不大于零时显示空值。
5. 每日详情使用侧面抽屉：收入构成（付费余额消费、订阅、其他已履约收入）、供应商拆分、费用分摊、数据来源和核验问题。供应商目录与大段解释不再独占默认页面。

收入构成和费用构成放在指标下钻中；保留必要的查看入口，避免在趋势和日表之间插入多块重复表格。

### 现金收支

1. 四项指标：确认实收、实际退款、现金支出、净现金流。实收与退款分开展示，净现金流等于实收减退款减现金支出。
2. 简洁辅助行：本期额度入账、待分类记录数。原“自动收入”改称“自动额度入账”，不能直接当现金实收。
3. 统一收支列表：日期、业务类型、对象、原币金额、CNY 折算金额、来源、关联凭证、分类状态、操作。支持收入 / 支出和业务分类筛选。
4. 自动额度入账保持“用户分页列表 → 每条兑换记录”两级下钻，搜索和时间筛选不丢失。已删除用户、关联缺失记录仍保留原始金额与来源。
5. 同笔在线支付与兑换、线下收款与管理员加余额、手工补录之间建立关联，现金只统计一次。没有关联依据时标记待复核，不靠金额和日期相似就自动删除记录。

复用既有“收款与入账”模块的收款、退款和订单证据，从成本分析进入时带上当前日期和来源条件；不再实现第二套支付对账。

### 余额与核对

1. 展示当前用户总余额（排除 ID 1）、当前上游预付余额及各自快照时间。当前余额不随日期筛选伪装为期末余额。
2. 有完整快照和变动来源时展示选定期间的期初、期末余额及变动核对；没有快照的历史期间显示不可回溯。
3. 待办列表按问题展示：管理员加余额未分类、可能重复的现金记录、上游日成本缺失、历史充值倍率 / 汇率缺口、费用未分类、收入分摊依据缺失。
4. 点击问题进入具体记录和证据，执行确认收款、标记赠送 / 纠错、关联既有记录、排除测试收入、补齐费用所属期间、重算受影响日期等操作。所有分类和排除仅写运营中心审计账，保留原因、操作者、时间和前后值。
5. 已删除账户的残留余额单列核对，不能仅因用户删除就自动确认为利润。历史收入和消费不随用户删除消失。

原“实际利润 = 本期收支差额 - 当前用户余额”卡片撤除，不改名后继续使用混合期间与存量的公式。累计净现金流与累计已确认经营利润如需展示，分别使用全历史现金账和经营日报，明确历史覆盖范围。

## 指标口径

| 指标 | 规则 |
| --- | --- |
| 用户消费额度 | 主站非 ID 1 用量的计费额度，保留已删除用户历史，区分余额、订阅等计费类型 |
| 付费余额消费收入 | 实际消耗的付费额度按其对应实收价值确认；充值优惠按已选定且一致的分摊政策处理 |
| 赠送消费 | 单列额度使用，不凭面值创造收入；上游实际成本仍计入 |
| 订阅收入 | 按套餐实收售价和有效服务期逐日分摊，暂停、退款、升级等按一致政策调整，不使用订阅消耗额度充当售价 |
| 其他确认收入 | 已交付的独立服务收入；用户充值不再次列入 |
| 确认收入 | 付费余额消费收入 + 订阅分摊收入 + 其他已履约收入 - 对应收入退款 / 折让 |
| 供应商实际成本 | 启用定时检查的供应商账号日消费，经当日已确认充值倍率和汇率折算；不叠加充值和原 Key 采购账本 |
| 服务毛利 | 确认收入 - 供应商实际成本，表示扣除上游成本后的业务差额 |
| 其他运营费用 | 归属于本期且未包含在服务成本中的服务器、域名、支付手续费、推广、人工等费用 |
| 经营利润 | 确认收入 - 供应商实际成本 - 其他运营费用 |
| 经营利润率 | 经营利润 / 确认收入；确认收入不大于零时不显示百分比 |

付费和赠送混合余额需保留入账来源与分配规则。示例：实付 100 获得 120 额度，采用比例分摊时消耗 60 额度确认 50 收入；纯赠送消费不确认收入。历史缺少来源时不能由当前余额倒推出付费比例，应标明待核验或在独立的“消费口径估算”中展示，不能冒充已确认经营利润。

管理员余额调整只证明额度变动，不能自动断言实收；负向调整也不能一律当作现金退款。线上订阅支付须从真实订单纳入，不能因兑换表没有记录而漏计。

所有应计成本必须计入且仅计一次。为保持四项指标可直接核对，除上游实际成本外的其他经营支出统一归入费用汇总，并可进一步标记直接服务成本 / 期间费用；例如部署外包费不能遗漏。主站管理员消费不形成客户收入，但管理员测试产生的上游费用仍是经营成本；若供应商总成本已包含，不能再次列运营费用。上游账号混用其他业务时需要独立账号或明确分摊依据。

供应商启用筛选沿用现有要求，并展示统计范围。仍发生生产费用的未纳入供应商会使利润偏高，页面应提供范围核对入口。历史保存当日统计范围，停用供应商不应默默改变旧归档；调整历史范围必须明确重算并留痕。

## 记账交互

使用侧面抽屉录入，保留列表位置。必填业务类型，系统根据类型确定是否影响现金、收入确认、资产余额或费用，避免由操作者任意勾选而产生矛盾。

| 业务类型 | 所需信息 | 统计影响 |
| --- | --- | --- |
| 供应商充值 | 供应商、付款日、实付金额、币种、到账额度、关联凭证 | 现金支出及预付余额；日消费时才确认成本 |
| 运营费用 | 分类、金额、币种、付款状态 / 日期、费用所属起止日期、分摊方式、凭证 | 实际付款计现金支出；按所属期间计运营费用 |
| 客户充值收款 | 用户、实收金额、币种、收款日、关联订单 / 兑换记录 | 现金实收；消费后确认收入，避免与自动记录重复 |
| 其他经营收入 | 名称、实收 / 应收金额、收款日、履约起止日期、凭证 | 收款计现金流，履约后确认收入 |
| 退款 / 折让 | 原业务记录、金额、日期、退款范围、凭证 | 未消费退款冲预收；已确认服务退款冲相应收入，现金退款单独计算 |

运营费用分类：服务器 / 带宽 / 存储、域名 / 证书、支付手续费、推广 / 佣金、人工 / 外包、其他。默认 CNY；即时费用默认所属期间等于发生日，月费 / 年费支持按自然日分摊并保证分摊合计等于原金额。付款时间和费用所属期间分别保存，支持预付和未付款费用。

长期资产按折旧政策另行处理；账户转账、分红、提款不列运营费用。赠送额度面值不重复列费用。收入和费用对原币、实际现金金额及额度金额分别命名，不复用一个金额字段表示不同含义。

## 核验与性能

- 金额状态与计算状态分开：实时 / 已归档说明计算时间；待分类 / 待统计 / 待核验说明数据能否确认。历史已归档也可能仍待核验。
- 确认收入或成本不完整时，对应利润显示空值并给出问题入口。可展示“已核验日期小计”，但明确标注覆盖天数，不冒充整期合计。
- 口径说明默认折叠；影响结果的错误仅显示一条简短摘要和待办数量，具体原因在下钻展开。
- 保留资金时区每日 01:00 归档昨日、当日实时、历史读取本地日报的架构。日期切换不发整月上游重复查询。
- 分类、凭证关联、分摊或核算规则改变后，只失效受影响日期；后台唯一覆盖重算并保留计算版本和变更原因，列表与趋势始终同源。
- 采用只读主站来源与运营中心分类 / 分摊 / 日报存储，不修改主站余额，不制造使用记录来凑利润，也不把核算逻辑移出既有模块。

## 迁移与交付顺序

1. 页面重组与名称纠正：默认自动统计，另有三个可选核算视图；原自动收入归为额度入账；原日差额更名消费口径毛利；撤除旧实际利润卡片，保留所有原始记录和下钻。
2. 费用分类与所属期间：旧供应商支出和自定义支出逐笔待确认，不根据旧 kind 自动认定充值或费用。先支持实际费用分摊与现金收支分离。
3. 收入确认与核对：关联收款、额度、赠送和订阅，补齐付费价值分配及退款规则。依据不足时保留待核验，只有消费额度时展示估算口径。
4. 统一经营日报：增加收入确认、费用分摊、利润及核验版本，保留原日表历史和可追溯来源，完成重算后切换趋势与合计。

验收重点：跨月余额继承、跨月 / 年付费用、上游充值和消耗不重复、线下收款与管理员加余额不重复、赠送及订阅口径、退款、已删除用户、零收入亏损、上游故障、历史范围变动、分类后定向重算，以及桌面 / 手机下钻和筛选状态保留。

本方案已按用户要求进入源码实现与验证；服务器部署仍需明确请求。
