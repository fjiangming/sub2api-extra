质量分
（延迟分 × 40% + 检测通过率 × 40% + 能力分 × 20%）÷ 可用权重之和

缺少某一维度时，只对已有维度重新归一化。延迟分由首字 P95 换算：1.5 秒及以内为 100 分，3/6/12/30 秒分别为 85/65/40/10 分，区间内线性插值，超过 30 秒为 0 分。

双源数据
基座 = Sub2API account_id；上游 = 映射供应商 api_key_id；实际窗口 = 所选窗口 ∩ 基座精确日志覆盖窗口 ∩ 上游日志覆盖窗口

一次列表查询固定同一个结束时间。基座管理用量接口使用 exact_total 精确分页并回补整个配置窗口；未完成精确回补时不判断 Key 总账盈亏，也不把未匹配的上游请求认定为额外流量。逐请求日志先按 request_id 一对一匹配，无法直接匹配时，再按模型、输入/输出/缓存 Token 和 5 秒时间容差配对。

费用对比
Key 总账毛差 = Σ基座 actual_cost ÷ 基座充值倍率 - Σ上游 actual_cost ÷ 上游充值倍率

列表优先展示统一窗口内整个映射 Key 的实际收入、实际支出和总账毛差；详情另行展示成功配对请求的可归因收支。Sub2API 的 actual_cost / total_actual_cost 表示实际扣除，对应界面绿色“总消费”；total_cost 表示标准价，account_stats_cost / total_account_cost 表示按账号倍率计算的账号口径成本，后二者不作为真实收支比较。只有基座精确分页完成、费用样本完整、Key 未被多个账号共享、币种一致且充值倍率明确时才判断总账盈亏。

首字 P95
首字 P95 = 排序样本 [ceil(n × 0.95)]；基座额外 P95 = percentile(base_ttft - upstream_ttft, 95%)

基座和上游只使用同一窗口内已配对、流式且首字时间大于 0 的请求，每侧最多采用最近 500 个样本。差值先逐请求相减再取分位数，不再用两个独立 P95 直接相减。

缓存读取率
Σ 缓存读取 Token ÷ Σ（输入 Token + 缓存写入 Token + 缓存读取 Token）× 100%

两侧均基于同一窗口内的同一批配对请求汇总。若同一配对请求的缓存读取或写入 Token 不一致，页面会标记异常；该指标不进入质量分。

检测通过率
成功完成的主动检测数 ÷ 主动检测总数 × 100%

每个账号采用观察窗口内最近最多 200 次主动检测；连通失败、超时或测试未正常结束均计为失败。

能力分
（算术 + 逻辑 + 数列 + 排序变换 + 校验码的正确项数）÷ 5 × 100

每次检测按账号和批次动态生成题目，降低固定答案记忆的影响。账号能力分是观察窗口内已覆盖检测的平均值，最多采用最近 200 次。当前仅 OpenAI 和 Gemini 支持自定义题集；指令遵循分单独展示且不进入质量分。若基座只返回固定问候语，记录为“能力题未执行 / 未覆盖”，不会误算为 0 分。

请求数
统一实际窗口内：基座 COUNT（Sub2API usage log ID）；上游 COUNT（供应商成功 log ID）

逐请求数据按来源日志 ID 去重，基座分页使用 exact_total=true。请求数展示同一时间窗口内各侧总量；只有基座与上游日志覆盖均完整时，未配对的上游请求才标记为“上游未归因”。只有累计用量的供应商使用相同快照起止时间的请求差值。
